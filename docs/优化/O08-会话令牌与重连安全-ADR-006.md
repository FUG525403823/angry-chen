# O08 会话令牌与重连安全（ADR-006）

> 里程碑：O8 ｜ 预估：1 会话 ｜ 上游移交物：HANDOFF-O07

## 0. 现状与不足（证据）

本步处理一处**身份认证缺口**：宽限期重连只按昵称匹配，任何人知道房间码 + 昵称就能接管别人的会话。
它需要一次协议版本升级，因此必须先落 ADR 再改代码——这也是本步唯一会触碰线上字节格式的文档。

### 0.1 结论一：宽限期重连按昵称匹配，等同"知道昵称即可接管"

| 事实 | 证据 |
|---|---|
| `findGracedSession(room, name)` 用 `session.name === name` 匹配已断线的宽限期会话 | `packages/server/src/rooms.ts:41-53` |
| 命中后把新连接绑到旧 `pid`（保留位置、血量、名额、武器） | `packages/server/src/room.ts:174-206` |
| 宽限期常量来自对局控制器 | `packages/server/src/rooms.ts:4,146`、`packages/server/src/match/controller.ts` 的 `GRACE_PERIOD_MS` |
| 昵称只做长度/字符校验，可重复 | `packages/shared/src/net/protocol.ts` 的 `LIMITS.minNameBytes/maxNameBytes` |

**攻击面**：知道房间码（4 位、31 字母表，`LIMITS.roomCodeAlphabet`）与目标昵称，在宽限期内带同名 join 即可：
①顶掉对方的重连；②继承对方的位置与已得资源。序号/位置合法性由 O01 的姿态校验兜底，但**身份**没有兜底。

### 0.2 结论二：握手帧里没有任何可验证的秘密

| 事实 | 证据 |
|---|---|
| `encodeWelcome` 固定 16 字节：`[0]` opcode、`[1..2]` pid、`[3..6]` 房间码、`[7]` 协议版本、`[8..11]` tick、`[12..15]` serverTimeMs | `packages/shared/src/net/codec.ts:366-375`、`decodeWelcome` 强制 `frame.length !== 16 → bad-length`（`codec.ts:378-388`） |
| `encodeJoin` 布局：`[0]` opcode、`[1]` 协议版本、`[2]` 名字长度、名字、末尾 4 字节房间码（总长 `3 + nameLen + 4`） | `packages/shared/src/net/codec.ts:246-256` |
| `Welcome`（定义在 `packages/shared/src/net/protocol.ts:143-149`）与 `JoinRequest`（定义在 `packages/shared/src/net/codec.ts:240-244`）都没有令牌字段 | `packages/shared/src/net/protocol.ts:143-149`、`packages/shared/src/net/codec.ts:240-244` |
| 协议版本号 | `packages/shared/src/index.ts:1`（`PROTOCOL_VERSION = 1`） |

### 0.3 结论三：客户端把"身份"存在 localStorage 的昵称里

| 事实 | 证据 |
|---|---|
| 昵称与上次房间码存 localStorage（跨标签页、跨会话共享） | `packages/client/src/net/connection.ts:38-39,83-84,97-98,107` |
| 重连靠"再次发送同一个 join" | `packages/client/src/net/connection.ts:198,306-308,342-344` |

因此即使服务器加令牌，客户端也必须把令牌放在**每标签页独立**的地方（`sessionStorage`），否则两个标签页会互相顶替。

### 0.4 结论四：文档里写死了旧协议版本号

| 事实 | 证据 |
|---|---|
| README 的健康检查示例断言 `protocolVersion` 为 1 | `README.md:23` |
| 运维手册两处 | `docs/运维手册.md:75,84` |

### 0.5 结论五：既有 ADR 目录的编号清单是手工维护的，且已经落后

| 事实 | 证据 |
|---|---|
| 磁盘上有 ADR-001…ADR-005 | `docs/00-共识/ADR/` 目录列表 |
| 但 `tools/check-docs.mjs` 的 `REQUIRED_DOCS` 只列到 ADR-004 | `tools/check-docs.mjs:24-30` |
| 校验规则只是"ADR 目录里至少 4 份" | `tools/check-docs.mjs:63-66` |

结论：新建 ADR-006 **不需要**改 `tools/check-docs.mjs`（本步明确不动该脚本，避免门禁风险）；
ADR-005 未列入 `REQUIRED_DOCS` 这一漂移在本步记为观察项（§9 未决项）。

## 1. 目标

本步骤结束后：

1. 每次成功 join 服务器生成 **8 字节随机会话令牌**，随 `welcome` 下发；客户端存于 `sessionStorage`；
2. 重连时 `join` 携带该令牌，服务器**只按令牌**匹配宽限期会话；无令牌或令牌不匹配一律按新玩家处理（对局中则拒绝）；
3. `PROTOCOL_VERSION` 升到 2，两端不匹配时按既有规则拒绝并给出可读原因；
4. 新增 `ADR-006` 记录该决策与后果；README 与运维手册的版本示例同步更新。

判据：`grep -rn "protocolVersion":1" README.md docs/` 无命中；新增协议单测覆盖
"令牌正确 → 复用 pid"、"令牌错误 → 拒绝"、"无令牌 → 新玩家（对局中拒绝）"三种情形。

## 5. 冻结契约

```ts
// packages/shared/src/net/protocol.ts
export const PROTOCOL_VERSION = 2;      // 实际常量定义在 packages/shared/src/index.ts
export const LIMITS = {
  // …
  tokenBytes: 8,                        // 会话令牌字节数（16 个十六进制字符）
} as const;

export interface Welcome {
  pid: number; roomCode: string; protocolVersion: number;
  tick: number; serverTimeMs: number;
  token: string;                        // 16 个十六进制字符
}
// packages/shared/src/net/codec.ts
export interface JoinRequest {
  name: string; roomCode: string; protocolVersion: number;
  token: string;                        // 空串 = 无令牌（新玩家）
}
```

| 冻结项 | 值 / 定义 |
|---|---|
| `welcome` 帧布局 | `[0]` opcode、`[1..2]` pid u16、`[3..6]` roomCode、`[7]` protocolVersion、`[8..11]` tick u32、`[12..15]` serverTimeMs u32、`[16..23]` token（ASCII 十六进制）→ **24 字节** |
| `join` 帧布局 | `[0]` opcode、`[1]` protocolVersion、`[2]` nameLen、`[3..3+nameLen-1]` name、再接 4 字节 roomCode、再接 8 字节 token |
| 令牌生成 | `node:crypto` 的 `randomBytes(8).toString('hex')`；每会话一次；重连复用不重生成 |
| 身份判定 | **只用令牌**；昵称不参与身份；令牌为空一律按新玩家 |
| 协议版本 | 2；两端不一致即拒绝（沿用既有拒绝路径） |
| 客户端存储 | `sessionStorage`（每标签页独立）；不可用时回退注入的 storage |
| ADR | ADR-006 为唯一权威描述；实现与该 ADR 冲突时以 ADR 为准并回改代码 |

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| v1 客户端被拒导致"刷新就好"的体验问题 | 用户报"连不上" | 拒绝时返回可读原因（版本不符）+ 文档写明"刷新页面"；版本升级本就是一次性成本 |
| 令牌经 `sessionStorage` 丢失（隐私模式/清站点数据） | 重连变新玩家、对局中被拒 | 回退路径明确（新玩家入房 / 提示会话失效）；不引入服务端持久身份 |
| 重连时重新生成令牌导致"第二次刷新掉线" | 连续两次快速刷新测试失败 | §5 明确"重连复用不重生成"；测试覆盖连续两次重连 |
| `decodeJoin` 放宽长度校验引入解析歧义 | 恶意帧被解析成奇怪令牌 | 只接受两种长度（无令牌 / 带令牌）；令牌字节强制 ASCII 十六进制，否则 `fail` |
| 改动触摸线上格式，回滚需两端同步 | 灰度期间版本混用 | 回滚 = `git revert` 本次提交并回滚客户端与服务器**同版本**部署；ADR-006 里写明"协议格式变更必须成对发布" |
| 回滚目标 | — | 回到 HANDOFF-O07 状态（`PROTOCOL_VERSION = 1`，昵称匹配）；不涉及持久化数据迁移 |
