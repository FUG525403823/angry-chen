# O01 权威姿态校验与硬纠正语义

> 里程碑：O1 ｜ 预估：1 会话 ｜ 上游移交物：HANDOFF-O00

## 0. 现状与不足（证据）

本步处理的是一处**正确性缺陷**（不是"代码风格"）：`applyPoseValidation` 把权威模拟自己产生的位移
当成客户端非法位移，于是既误伤合法玩家，又让 `ac_hard_correct_total` 这个指标失去语义。

### 0.1 结论一：位移预算被"模拟派生位移"挤爆，疾跑 + 狂暴时裕度为零

| 事实 | 数值 | 证据 |
|---|---|---|
| 位移上限公式 | `sprintSpeed × (dtMs/1000) × 1.15` = `6.3 × 0.05 × 1.15` = **0.36225 m/tick** | `packages/server/src/anticheat.ts:3,14-16` |
| 狂暴疾跑的权威速度 | `sprintSpeed × RAGE.moveSpeedMultiplier` = `6.3 × 1.15` = 7.245 m/s → **0.36225 m/tick** | `packages/shared/src/config/combat.ts:36`、`packages/shared/src/sim.ts:69-78`（`applyCommands` 传入 `RAGE.moveSpeedMultiplier`） |
| 冲撞羊击退速度 | 7 m/s → **0.35 m/tick** | `packages/shared/src/config/sheep.ts:48`、`packages/shared/src/ai/sheepAttack.ts:44-56`、`packages/shared/src/sim.ts:155-167` |
| 实体分离推挤 | 每对最多 `(minDistance − distance)/2`；玩家 0.4 + 咩咩兵 0.5 → `minDistance = 0.9` | `packages/shared/src/sim.ts:210-249`、`packages/shared/src/config/entity.ts:3-8` |

上限公式里的 `1.15` 与狂暴移速倍率**是同一个数字**，所以玩家在「疾跑 + 狂暴」状态下水平位移**恰好等于**判定位移上限：
`>` 比较不触发，但只要叠加任何一点派生位移（分离推挤、击退、碰撞外推），立刻判定违规。

后果链：违规 → `deps.metrics.speedViolations += 1` → 无条件 `hardCorrectTotal += 1` 并把位置**回退到 tick 前**、速度清零
（`packages/server/src/room.ts:676-698`）。因此：

1. **击退被吞掉**：被冲撞羊顶飞的同时被别的羊挤一下，击退位移即被回退；
2. **橡皮筋**：客户端收到"看起来没动"的权威位置，和解后本地位置被拉回；
3. **指标污染**：`docs/evidence/bots-4p-5min.json` 记录 `hardCorrectTotal = 10467`（523.34/分钟/人，阈值 ≤5），
   而 `docs/验收报告.md` §3.2 披露同一条命令三次复跑得到 `0 / 5222 / 10467`——分散极大正符合
   "取决于机器人是否恰好在羊群里疾跑"这一机制，而不是"客户端预测有缺陷"。

### 0.2 结论二：tick 前位置按"第 N 个 player"配对，不按 pid

| 事实 | 证据 |
|---|---|
| `capturePreTick` 按 `activeIds` 遍历顺序写入 `preTick[count*3 …]`，并以 `LIMITS.maxPlayersPerRoom` 截断 | `packages/server/src/room.ts:641-655` |
| `applyPoseValidation` 用同一个顺序取回 `preTick[index*3 …]` | `packages/server/src/room.ts:657-675` |
| 二者之间隔着 `stepWorld`（可能 despawn/spawn 实体、改变 `activeIds` 顺序） | `packages/server/src/room.ts:435-456`、`packages/shared/src/world.ts:172-178`（`insertActiveId` 按 id 升序插入） |

只要两侧的 `activeIds` 顺序或成员集合不同，配对即错位，`prevX/prevZ` 是**别人的**坐标 → 必然速度违规。

### 0.3 结论三：一个计数同时承担两种语义

`hardCorrectTotal` 既在"仅记录可疑"时自增，也在"真的回退位置"时自增（`packages/server/src/room.ts:692`），
而压测门槛直接读它（`tools/bots.mjs:924-935` 的 `S5.2-8 硬纠正 ≤ 5/分钟/人`）。
于是无法区分"反作弊真的拦住了作弊"与"反作弊误伤了好人"——这正是验收报告 §6.5 把该指标列为
"需后续单独排查、当前不能读作客户端预测缺陷结论"的原因。

### 0.4 结论四（顺带记录，明确不在本步修）：垂直维度校验是死代码

`state.vel.y` 在整条路径上恒为 0（`packages/shared/src/sim/localStep.ts:30,56`；
`packages/shared/src/sim.ts:140,149,164`），`PLAYER.gravity` / `PLAYER.jumpSpeed`
（`packages/shared/src/config/player.ts:6-7`）从未被模拟使用。因此：

- `BUTTON.jump`（空格）上传到服务器后没有任何效果（`packages/shared/src/config/input.ts:14` 有位、无人消费）；
- `check.vertical`（`packages/server/src/anticheat.ts:18-21`，读 `entity.vel.y`）永不触发。

本步**只记录、不修复**跳跃缺失（它属于玩法功能缺口，需先确认 FR 是否要求跳跃，见 §9 移交清单）。

## 1. 目标

本步骤结束后：**姿态校验只对"命令可解释的位移"计费**。权威模拟自身产生的位移（击退、实体分离推挤、静态碰撞外推）
不再导致玩家位置被回退；"可疑"与"强制回退"是两个独立计数与两条独立策略：

- **可疑**（`ac_pose_suspect_total`）：记录 + 采样日志，**不改位置**；
- **强制回退**（`ac_hard_correct_total`）：只在位移无法由命令或派生位移解释、或位置非法时执行。

判据：在 4 个无头机器人 5 分钟压测中，`ac_hard_correct_total` 差值 ≤ 5/分钟/人（`tools/bots.mjs --strict` 退出码 0），
且"羊群围住玩家"的回归测试在 200 tick 内产生 0 次回退。

## 5. 冻结契约

```ts
// packages/shared/src/world.ts
export interface Entity {
  // …既有字段…
  /** 本 tick 内由权威模拟自身（击退/实体分离/静态碰撞外推）产生的水平位移，单位 m。由 sim 累加，服务器校验后清零。 */
  derivedMoveX: number;
  derivedMoveZ: number;
}

// packages/server/src/anticheat.ts
export function validateAdvance(
  prevX: number,
  prevZ: number,
  x: number,
  z: number,
  velocityY: number,
  dtMs: number,
  out: AdvanceCheck,
  derivedBudgetM?: number, // 缺省 0 = 既有行为
): AdvanceCheck;

// packages/server/src/anticheat.ts
export function explainableByDerived(
  distanceM: number,
  limitM: number,
  derivedBudgetM: number,
): boolean;
```

| 冻结项 | 值 / 定义 |
|---|---|
| 指标名 | `ac_pose_suspect_total`（counter，记录不处置）、`ac_pose_rejected_total`（counter，位置非法被拒）、`ac_hard_correct_total`（counter，**仅**真正回退） |
| `LIMITS.poseHardCorrectFactor` | `1.5`（超出 `limit + derivedBudget` 的 1.5 倍才回退） |
| `derivedMoveX/Z` 生命周期 | 服务器 `applyPoseValidation` 读后清零；`spawnEntity` 重置为 0；客户端预测路径**不得**读取（客户端不参与姿态校验） |
| 判定优先级 | 位置非法 > 超出硬上限 > 派生位移可解释（suspect） > 通过 |
| `isLegalPosition` 谷仓边界 | 与 `collideStatic` 一致：`x <= barn.minX - radius` 或 `x >= barn.maxX + radius` 即视为仓外（任务 11，执行期新增） |
| 协议 | 不涉及（`derivedMove*` 不入快照、不上行） |

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 放宽校验给作弊留空间（客户端可谎报"我这 tick 被挤了"） | `ac_pose_suspect_total` 远高于 `ac_hard_correct_total` 且同一 pid 长期高发 | ①派生位移**只**由服务器权威模拟产生，客户端无法影响；②位置非法仍硬回退；③suspect 计数 + 每 5s 采样日志（复用 `ANTICHEAT_LOG_INTERVAL_MS`）便于事后定位 |
