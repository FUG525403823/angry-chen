# S12 复制调度、快照自适应与背压
> 里程碑：MS12 ｜ 预估：1.5 人日 ｜ 上游移交物：HANDOFF-S11

## 1. 目标

本步结束后，每个客户端拥有一条独立的复制流水线：以"已发送基线"做差分广播、出站队列顶到预算时丢旧快照而不丢事件、房间被最慢客户端拖累时自动降快照档位并在 3 秒干净期后升档；同时 tick 调度误差、单 tick 工作量与模拟漂移都有可断言的指标与预算，且"让出事件循环"不等于丢 tick。不可靠通道语义见 [ADR-009](../../00-共识/ADR/ADR-009-UDP传输与协议重构.md)；字节与背压口径继承 `send-queue.ts`、`O03 出站帧所有权与背压` 与 `O05 快照编码增量化与自适应快照率`。

## 5. 冻结契约

每客户端基线（`baseline.cpp`）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `baselineTick` | u32 | 0 = 强制全量；否则 = 上一帧已编码快照的 tick |
| `presentIds` | u16[256] | 已发布实体 id，**升序紧凑** |
| `presentCount` | u16 | 有效长度（≤ 256） |
| `record` | u8[256 × 15] | 每实体 15 B 记录镜像（量化后的线上字节） |

| 冻结项 | 值 / 定义 |
|---|---|
| 基线前进规则 | 快照通道**不可靠**：帧交付出所有权时基线前进到该 tick，**不等客户端 ack**；客户端丢失恢复靠 `baselineTick = 0` 语义 + 强制全量 |
| 强制全量节拍 | `kFullSnapshotIntervalTicks = 40`（2 s），与档位解耦（按 tick 计数判定） |
| 可靠通道确认 | `EventChannel` 用 `msgId` + `ackBase` + `ackBits` 确认；`CommandChannel` 只发最新，积压 > 2 丢中间 |
| 差分编码顺序 | 通用包头 → 删除列表（id 升序，≤ 255 条）→ 变更记录（id 升序，15 B/条，≤ 255 条）；未变实体不出现；强制全量时 `baselineTick = 0` |

出站队列与丢弃（`backpressure.cpp`）：

| 冻结项 | 值 / 定义 |
|---|---|
| 队列预算 | `kMaxBufferedBytes = 262144`（256 KiB，单连接） |
| 单帧上限 | `kMaxSnapshotBytes = 2048`；大于池槽的帧不入队 |
| 丢弃策略 | 队列已排队字节 + 本帧 > 256 KiB → **旧快照直接丢**（不入队，`ac_slow_client_drops_total` +1）；`EventChannel` 帧不丢（可靠重传） |
| 慢客户端判定 | 连续丢弃 **60 帧（3 s）** → `Disconnect(reason = 5 slowConsumer)`，随后进入 30 s 宽限期 |
| 队列字节口径 | 已拷贝未写完成的字节；健康连接稳态应接近 0 |

自适应快照率（`snapshot_rate.cpp`）：

| 冻结项 | 值 / 定义 |
|---|---|
| 编码 | `snapshotRateX10` 整数，单位 1/10 Hz；[ADR-009](../../00-共识/ADR/ADR-009-UDP传输与协议重构.md) 允许区间 **[100, 300]（10–30 Hz）** |
| 实装档位 | 继承 `protocol.ts` 的 `snapshotRateLevels`：**{200, 150, 100} = 20 / 15 / 10 Hz**；20 Hz tick 下单 tick 最多一帧，故实际上界 200；`300` 档保留给未来 tick 提速，本步不得启用 |
| 相位定义 | 200 = 每 tick；150 = 每 3 tick 发 2 次（相位唯一确定）；100 = 每 2 tick 发 1 次 |
| 降档触发（任一） | 最慢会话 `bufferedAmount > kMaxBufferedBytes/2`（128 KiB）、`tickSkips` 增长、`ac_room_budget_exceeded_total` 增长；触发即降一档 |
| 升档触发 | 连续 **3000 ms** 无触发条件 → 升一档，上限 200 |
| 评估周期 | ≥ 1000 ms；档位变更计 `ac_snapshot_rate_downshifts_total` |
| 事件帧 | 不受档位影响，仍每 tick 广播 |

字节预算与调度指标：

| 冻结项 | 值 / 定义 |
|---|---|
| 单快照上限 | **2048 B**（含包头） |
| 稳态快照 | **≤ 1228 B** |
| 每客户端带宽 | **≤ 40 KB/s**（只算快照通道载荷） |
| tick 抖动口径 | `tickScheduleError = 单调时钟 − (首 tick 时刻 + tickIndex × 50)`；P95 ≤ **8 ms** |
| 替代判据（本机定时器粒度 > 8 ms 时） | 前 1/3 与后 1/3 的 P95 差 ≤ **2 ms**，且 `|ac_sim_drift_ms| ≤ 50 ms` |
| 模拟漂移口径 | `simDrift = (world.timeMs − simStartMs) − (now − wallStartMs)` |
| 单房间工作量预算 | `kRoomTickBudgetMs = 8`；超出则让出事件循环，累积量**不扣除**（让出 ≠ 丢 tick） |

测试报告字段（`build/replication-report.json`，本步冻结）：

`{ suite, seed, ticks, snapshotBytesMax, snapshotBytesP95, steadyMeanBytes, droppedSnapshots, eventsDropped, rateLevelsVisited[], scheduleErrorP95Ms, simDriftMsMax }`

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 降档阈值过敏感，正常房间被压到 10 Hz | `ac_snapshot_rate_x10` 在无慢客户端跑次中掉到 100 | 触发条件加"连续 2 次评估都成立"再降档，并复核 `bufferedAmount` 是否把内核 UDP 缓冲也算进来 |
| 镜像与基线不同步，客户端解码出错误实体 | 差分套件的逐字节比较失败，或报告 `decodeFailures > 0` | 镜像只在"帧真正入队"后写；丢弃的帧不得改动基线（丢弃是队列层的事） |
| 强制全量节拍与档位耦合导致长时间不发送全量 | 丢帧后 40 tick 内未自愈的用例失败 | 全量节拍按 tick 计数判定，与 `snapshotRateX10` 解耦 |
| 工作量预算让出被实现为丢 tick | `ac_tick_skips_total` 增长而 `ac_room_budget_exceeded_total` 也增长 | 让出只改变本轮循环边界，累积 tick 数不扣除；测试断言两者独立 |
| 回滚目标 | — | `git revert` 本步提交，退回"每 tick 全量 + 无背压 + 无自适应档位"的 S11 行为（带宽与内存会退化，但功能可用） |
