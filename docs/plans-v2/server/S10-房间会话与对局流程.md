# S10 房间、会话与对局流程
> 里程碑：MS10 ｜ 预估：1.5 人日 ｜ 上游移交物：HANDOFF-S09

## 1. 目标

本步骤结束后，**一局对局能从房间码跑到结算**：用 4 位房间码建房与加入，房主在大厅集齐准备后开局，`lobby → loading → playing → intermission → ended` 五态按冻结的转移表流转，波间 20 秒可被全员准备跳过，掉线玩家在 30 秒宽限期内凭令牌回到原位（名额与位姿保留），对局结束产出可落盘的结算记录。

## 5. 冻结契约

### 5.1 `MatchPhase` 状态机（码 / 名字 / 合法转移）

| 码 | 名字 | 允许转移到 |
|---|---|---|
| 0 | `lobby` | `loading` |
| 1 | `loading` | `playing` |
| 2 | `playing` | `intermission`、`ended` |
| 3 | `intermission` | `playing`、`ended` |
| 4 | `ended` | `lobby` |

同态转移视为合法且不改动状态；其余组合（5×5 共 25 组中 13 组）属非法：记录 `matchTransitionDenied` 警告并返回 `false`，**不得**静默改状态。`ended → lobby` 的重置会清空战绩记录、波次与导演状态、回收全部羊与投射物、并把全部玩家补满。

### 5.2 阶段时长与推进规则

| 项 | 值 |
|---|---|
| `kLoadingMs` | 1500（= 30 tick，倒计时到 0 即进 `playing`、`wave = 1`、记 `startedAtMs`） |
| `kIntermissionMs` | 20000（= 400 tick） |
| `kIntermissionSkipMinMs` | 5000（= 100 tick；已过该时长且全员准备则立刻置 0） |
| 每晚 tick 的推进源 | `updateMatch(room, nowMs, elapsedMs)`，`elapsedMs` = 本次 tick 的真实毫秒增量 |
| 进 `playing` 的必经动作 | 全体补给（生命、护甲、三个弹匣、备弹 120、换弹与散布清零、怒气清零、倒地复位） |

### 5.3 房间码与建房

| 项 | 值 |
|---|---|
| 字母表 | `ABCDEFGHJKMNPQRSTUVWXYZ23456789`（31 字符，排除 I / L / O / 0 / 1） |
| 长度 / 空间 | 4 / 31^4 = 923521 |
| 保留码 | `0000` 表示「新建房间」，绝不作为真实房间码 |
| 生成 | 逐字符取 `floor(rng() * 31)` 并夹取到 [0, 30]；冲突或等于保留码则重试，最多 32 次；仍失败则建房返回空（调用方回 `room-full`）；随机数来自房间注册表自带的非模拟实例（种子 = 服务器启动毫秒），不得触碰 `world` 的三条模拟流 |
| 输入归一化 | 房间码一律转大写后匹配；长度不等于 4 或含字母表外字符即 `room-not-found` |
| 容量 | 每房最多 4 人（连接态），全服最多 64 房 |

### 5.4 会话与加入/离开

- `Session` 字段：`id`（连接短 ID）、`pid`（人员编号，0 = 未分配）、`name`（1–12 字节）、`token`（8 字节十六进制重连令牌）、`ready`、`weaponApplied`、`kills`、`roomCode`、`joinedAtMs`、`disconnectedAtMs`（`null` = 连接中）、`command`（最近一条已净化命令）。
- 加入结果三态：`ok` / `room-not-found` / `room-full` / `match-in-progress`（`playing` 阶段且无宽限期身份者不得中途加入）。`lobby` / `loading` / `intermission` / `ended` 阶段允许加入。
- 离开（主动）：立刻释放名额；若离场时刻处于 `playing` 或 `intermission`，结算里该玩家 `leftMidMatch = true`，否则为 `false`。

### 5.5 宽限期 30 秒与重连

| 项 | 规则 |
|---|---|
| 断线 | `disconnectedAtMs = nowMs`；其实体 `idle = true` 且速度与命令全部清零；名额、位姿、武器与统计数据**保留** |
| 宽限期 | `kGracePeriodMs = 30000`（= 600 tick）；到期仍未回来则移除会话、释放名额，并计入 `graceTimeouts` |
| 重连匹配 | **只按 `token` 匹配**宽限期会话，昵称不参与身份判定；成功后接管同一 `pid` 与实体，原会话置空并解除房间引用 |
| 重连补偿 | 解除 `idle`、水平速度清零、若倒地则解除倒地、生命取 `max(hp, maxHp * 0.5)` |
| 房间空闲 | 无会话或全部会话都已断线即判空闲；空闲起始时间记入 `emptySinceMs`，连续空闲 `60000` ms 未被认领则回收房间（清空会话与 `pid`、从注册表删除） |

### 5.6 结算数据结构与顺序

| 字段 | 类型 | 规则 |
|---|---|---|
| `matchId` | string | `roomCode + '-' + startedAtMs` |
| `startedAtMs` / `durationMs` | 毫秒 | `durationMs = max(0, endedAtMs - startedAtMs)` |
| `waveReached` | 整数 | 结束时的波次（0–10） |
| `winnerTeam` | 0 / 1 | 0 = 玩家方（第 10 波清空），1 = 羊群（全员倒地或无人在场） |
| `playerCount` / `players[]` | 整数 / 数组 | 每个 `pid` 一条：`name`、`kills`、`headshots`、`shotsFired`、`hits`、`revives`、`downs`、`aliveMs`、`leftMidMatch` |
| `matchEnded` 事件 | 事件 | `subjectId = winnerTeam`、`value = waveReached`、`flags = durationMs` |

统计映射（只读当 tick 的事件）：`playerHit` → 射手的 `hits`；`sheepKilled` → 射手的 `kills`，flags 含 `headshot` 时再 +1 `headshots`；`playerDowned` → 受害者的 `downs`；`reviveDone` → 救援者的 `revives`。`aliveMs` / `downedMs` 只在 `playing` 与 `intermission` 累积。`shotsFired` 用「开火前弹匣 − 开火后弹匣」差分补记，切枪跨帧时不补记。

### 5.7 每 tick 顺序与结束判定

1. 房间空闲/宽限到期检查（先处理超时，再处理加入与命令）。
2. 阶段推进（§5.2）→ 需要时执行全体补给。
3. 若处于 `playing`：装配命令 → `stepWorld(world, commands, 50)` → 统计累积 → 清波判定（调 `reviveDownedForWaveClear` 并进 `intermission` 或结束）。
4. 结束判定（仅 `playing`）：无任何已连接玩家，或全部已连接玩家都倒地 → `winnerTeam = 1`；
5. 广播快照与事件（事件通道按 `eventId` 幂等）。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 阶段机被"顺手放行"非法转移 | §6 第 3 条断言失败 | 转移只走 `canTransition` 一张表；非法记录警告并返回 `false` |
| 宽限期身份按昵称匹配 | 同名玩家抢到别人的名额 | 只按 `token` 匹配；用例覆盖"同名不同令牌"与"同令牌不同昵称" |
| 结算统计与实际事件不一致 | 击杀数少于 `sheepKilled` 事件数 | 统计只在同一 tick 内消费事件；跨 tick 不重放（事件池按 tick 有效） |
| 房间码空间被占用殆尽 | 连续 32 次冲突、建房返回空 | 保留码不与真实码冲突、回收空闲房；`room-full` 是合法返回值而非异常 |
| 波间跳过被滥用（0 秒进下一波） | 波次间隔短于 5000ms | 跳过必须同时满足"已过 5000ms"与"全员准备"；用例覆盖单一条件不成立的情况 |

回滚目标：回到 `HANDOFF-S09` 的状态（无房间与会话，只有纯模拟 + AI + 波次）。回滚方式为删除 `server/src/room/` 与测试目标、保留内存适配器；模拟与对拍不受影响。
