> 里程碑：MS15 ｜ 预估：1 人日 ｜ 上游移交物：HANDOFF-S14

## 1. 目标

本步结束后，服务器可以"装箱交付"：一条命令产出带版本号的 Release 可执行文件，一份 systemd 单元与两份反代片段把 HTTP 面与游戏端口放行（不再托管浏览器静态资源），运维只需读 `server/README.md` 就能定位可执行、配置、日志与战绩四类文件；同时给出旧 Node 服务器的退役判定清单与一份签署过的验收报告。部署形态继承 [ADR-004](../../00-共识/ADR/ADR-004-部署与持久化形态.md)，旧 Node 单元见 `D:\projects\tmp\angry-chen-bak\deploy\angry-chen.service`（只作对照，本步不新建也不修改），性能基线见 `soak-5min-o03.md`。

## 5. 冻结契约

版本与端口：

| 冻结项 | 值 |
|---|---|
| 版本号格式 | `MAJOR.MINOR.PATCH`（语义化，无前缀）；S15 的发布版为 **0.1.0** |
| 协议版本 | 常量 `protocolVersion = 1`，独立于语义化版本，不随发布变动 |
| `--version` 输出 | `ac_server 0.1.0 protocol=1 tick=50ms`（单行，退出码 0） |
| 环境变量 | `AC_UDP_PORT`（默认 **8788**）、`AC_HTTP_PORT`（默认 **8787**）、`AC_DATA_DIR`（默认 `/var/lib/angry-chen`）、`AC_LOG_LEVEL`（默认 `info`） |
| HTTP 端点 | `GET /health`（200）、`GET /metrics`（200，`text/plain; version=0.0.4`）、`GET /api/leaderboard?limit=`（200/429）、`GET /api/matches/recent?limit=`（200/429）、其它 404 |
| UDP 面 | 游戏流量直连 UDP `8788`，**不经反代**；机器人/客户端不依赖 HTTP |

部署目录布局（安装后）：

| 路径 | 内容 |
|---|---|
| `/opt/angry-chen/bin/angry-chen-server` | 唯一可执行文件 |
| `/etc/angry-chen/server.env` | `AC_*` 环境变量（不含任何密钥） |
| `/var/lib/angry-chen/matches.ndjson` | 战绩（追加式，永不截断） |
| `/var/lib/angry-chen/reports/` | 单局诊断报告，保留最近 200 份 |
| `/var/log/angry-chen/server.log` | 结构化 JSON 行日志 |

systemd 单元关键字段（`deploy/angry-chen-server.service`）：

| 字段 | 值 |
|---|---|
| `Type` / `User` / `WorkingDirectory` | `simple` / `angrychen` / `/opt/angry-chen` |
| `ExecStart` | `/opt/angry-chen/bin/angry-chen-server` |
| `Restart` / `RestartSec` | `on-failure` / `3` |
| `KillSignal` / `TimeoutStopSec` | `SIGTERM` / `10`（收到 SIGTERM 后先落盘报告与战绩再退出） |
| 加固 | `NoNewPrivileges=true`、`PrivateTmp=true`、`ProtectSystem=strict`、`ProtectHome=true`、`ReadWritePaths=/var/lib/angry-chen /var/log/angry-chen`、`LimitNOFILE=8192` |
| 日志落盘 | `StandardOutput=append:/var/log/angry-chen/server.log`，`StandardError=append:/var/log/angry-chen/server.err.log` |

日志落盘与轮转策略：

| 冻结项 | 值 |
|---|---|
| 落盘位置 | `/var/log/angry-chen/server.log`（stdout 追加）；systemd 环境下亦可改走 journald（单元里二选一，不同时启用） |
| 轮转条件 | 每日一次，或单文件 ≥ **64 MB** 立即轮转 |
| 保留 | **7** 份，压缩存储（logrotate：`daily`、`rotate 7`、`compress`、`copytruncate`） |
| 战绩与报告 | 不轮转、不截断；报告按份数保留 200 份，战绩靠常驻上限（10000 条）在内存侧约束 |
| 退役判定清单（6 条全满足才停止维护 `packages/server`） | ① v2 服务器 + v2 客户端完成一次 ≥30 分钟联合对局（含一次断线重连与一次波间跳过）② 性能门槛 8 条全绿 ③ 对拍向量仍逐位复现（`packages/shared` 冻结不删）④ 既有 `node tools/check-docs.mjs` 与 `node tools/check-assets.mjs` 全绿且 `packages/server` 测试仍全绿 ⑤ 生产部署连续 7 天无未捕获异常、无战绩写失败 ⑥ 回滚演练：旧 Node 服务器 + 旧客户端可在 5 分钟内恢复服务 |

## 6. 验证

| # | 命令 | 期望 | 失败意味着 |
|---|---|---|---|
| 1 | `cmake -S server -B server/build -DCMAKE_BUILD_TYPE=Release`；`cmake --build server/build -j`；`server/build/ac_server --version` | 输出 `ac_server 0.1.0 protocol=1 tick=50ms` | 版本未注入或格式与 §5 不一致（运维与代理无法自动比对） |
| 2 | `Start-Process server/build/ac_server -ArgumentList '--http-port','8787','--udp-port','8788','--data-dir','build/acvar'`；随后 `(Invoke-WebRequest -UseBasicParsing http://localhost:8787/health).StatusCode`；`(Invoke-WebRequest -UseBasicParsing http://localhost:8787/metrics).StatusCode` | 两次都 `200` | 端点未接线或端口参数未生效 |
| 3 | `try { (Invoke-WebRequest -UseBasicParsing http://localhost:8787/nope).StatusCode } catch { $_.Exception.Response.StatusCode.value__ }`（服务器运行中） | `404` | 兜底路由缺失（会把错误路径当成功返回） |
| 4 | `(Select-String -Path deploy/Caddyfile,deploy/nginx.conf -Pattern 'file_server\|try_files\|root ').Count` | 两份合计 **0** | 反代仍在托管浏览器静态资源（与"客户端已是原生进程"矛盾） |
| 5 | `Select-String -Path deploy/angry-chen-server.service,deploy/nginx.conf,server/README.md -Pattern 'AC_UDP_PORT\|8788'` | 三处都出现且端口一致 | 端口口径分叉（部署后连不上） |
| 6 | `node tools/check-docs.mjs` | 退出码 0 | 文档门被本步新链接或章节破坏 |

人工确认清单（验收报告需逐条勾选）：`docs/evidence/server-v2-acceptance.md` 含 ① S14 §5 门槛表的 8 条实测值 ② 四个端点响应摘要 ③ 退役清单 6 条状态 ④ 未验证项（本机非 Linux、systemd/反代未真机跑过）与该状态对应的后续动作。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 反代去掉静态托管后误删了 `/health` 段 | 部署后 `curl https://<域名>/health` 返回静态文件的 404 | 保留三个 `handle` 段并放在兜底之前；用 `curl` 三端点回归 |
| 日志文件写满磁盘 | 磁盘告警、`server.err.log` 快速增长 | logrotate 按日/64MB 轮转保留 7 份；报告 200 份上限；战绩只追加但常驻内存受 10000 条约束 |
| systemd 加固导致战绩不可写 | 启动后 `store.error` 日志 | `ReadWritePaths` 必须同时含数据目录与日志目录；排障命令写进 README |
| 版本号与协议版本被混为一谈 | 客户端因协议版本不匹配被拒 | 编译期注入版本、运行时独立常量 `protocolVersion = 1`；`--version` 同行列两个值 |
| 过早在真机上停止维护旧 Node 服务器 | 联合对局/回滚演练未完成就执行退役 | 退役清单 6 条为**合取**条件，任一未满足即保持 `packages/server` 可用 |
| 回滚目标 | — | `git revert` 本步提交：删除 v2 单元与验收报告，`deploy/` 恢复到旧 Node 形态（仍可用），`server/README.md` 运维段回退；无协议与数据格式影响 |
