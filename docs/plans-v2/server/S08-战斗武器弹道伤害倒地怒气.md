## 5. 冻结契约

### 5.1 武器表（抄 v1 `weapons.ts`，数值不得再调）

| slot | damage | pellets | rpm | auto | mag | reloadMs | spreadDeg | falloffStartM | falloffPerM | headshotMultiplier |
|---|---|---|---|---|---|---|---|---|---|---|
| 0 `pistol` | 25 | 1 | 300 | false | 12 | 1400 | 0.8 | 30 | 0 | 2.0 |
| 1 `rifle` | 20 | 1 | 600 | true | 30 | 2000 | 0.6 | 40 | 0 | 2.0 |
| 2 `shotgun` | 12 | 8 | 70 | false | 6 | 2600 | 4.0 | 12 | 0 | 2.0 |

初始备弹 `kReserveAmmoInitial = 120`；初始弹匣 = 各自的 `mag`；`switchTo` 与上表 slot 一一对应；射速间隔 `rpmToIntervalMs(rpm, mult) = 60000 / (rpm * mult)`，因此手枪 200ms、步枪 100ms、霰弹枪 `60000/(rpm·mult)` = `60000/70`（按公式现算，不写近似常数 857ms）。

### 5.2 散布、后坐与抖动

| 常量 | 值 | 语义 |
|---|---|---|
| `kSpreadGrowthPerShotDeg` | 0.1 | 每次成功开火累加 |
| `kSpreadMaxDeg` | 0.25 | 累积上限 |
| `kSpreadDecayDelayMs` | 350 | 距上一次开火静默超过它才开始衰减 |
| `kSpreadDecayPerSecondDeg` | 6.0 | 按 `dtMs / 1000` 线性衰减，下限 0 |
| `kRecoilPitchPerShotDeg` / `kRecoilYawJitterDeg` | 0.35 / 0.2 | 表现层后坐（模拟不改朝向） |

有效散布 = `weapon.spreadDeg + state.spreadDeg`。三轮试玩平衡结论（v1 冻结值，禁止回改）：累积由 +0.6°/发、上限 3.0° 收到 **+0.1°/发、上限 0.25°** —— 旧上限在 45m 处是 ±2.4m 的圆锥，玩家感知就是"射程不够"；同时步枪基础散布由 1.4° 收到 0.6°，三把武器 `falloffPerM` 整表置 0。抖动派生：`unitJitter(seq, salt)` 走 `imul` 整数哈希（`0x9e3779b1` / `0x85ebca77` / `0x2545f491`），`signedJitter = unitJitter * 2 - 1`；逐弹丸索引 `command.seq + pellet * 13`（yaw，salt `0x9e3`）与 `command.seq + pellet * 29`（pitch，salt `0x51f`）；俯仰夹取 ±`kPitchLimitRad = 1.5533`。

### 5.3 射线

- 最大距离 `kShotMaxDistanceM = 160`（场地对角线 ≈113m，等价于无射程上限但仍有限）。
- 起点 = 射手 `(pos.x, pos.y + kEyeHeightM, pos.z)`；方向 = `yawPitchToDirection(yaw, pitch)`，用 S02 的 `ac::yawPitchToDirection` / `forwardFromYaw` 加 §5.2 的抖动。
- 先对谷仓 AABB 求交取 `bestT`，再按实体 `EntityId` 升序逐个尝试（跳过射手自身），最近命中者胜出；水平投影间距超过包围半径的候选直接跳过（早退不改变命中集合）。

### 5.4 命中形状与部位

| 目标 | 形状 | 部位判定 |
|---|---|---|
| 玩家 | 竖直胶囊：半径 0.4，轴 y ∈ [pos.y + 0.4, pos.y + 1.3] | `ratio = (hitY - pos.y) / 1.7`；≥ 0.85 头、≥ 0.4 躯干、否则四肢 |
| 羊 | 局部坐标系（+Z 为正前方）的躯干盒 + 前伸头盒，见表 | 躯干盒内按高度阈值：≥ `headMinM` 头、≥ `torsoMinM` 躯干、否则四肢；头盒命中直接判头 |

| 羊形 | halfWidthM | halfDepthM | topM | headHalfWidthM | headMinYM | headMaxYM | headMinZM | headMaxZM | headMinM | torsoMinM |
|---|---|---|---|---|---|---|---|---|---|---|
| `grunt` | 0.86 | 0.66 | 1.15 | 0.22 | 0.68 | 1.12 | 0.41 | 0.91 | 0.78 | 0.34 |
| `ram` | 0.92 | 0.70 | 1.22 | 0.24 | 0.72 | 1.19 | 0.43 | 0.97 | 0.83 | 0.36 |
| `elite` | 0.97 | 0.74 | 1.29 | 0.25 | 0.76 | 1.26 | 0.45 | 1.02 | 0.87 | 0.38 |
| `king` | 1.38 | 1.06 | 2.05 | 0.36 | 1.08 | 2.04 | 0.65 | 1.46 | 1.25 | 0.54 |

命中盒是**渲染盒体口径**，与移动/分离用的 `radiusM` / `heightM` 分离；世界→局部用反向旋转，其中 `sin/cos` 一律来自 S02 的 `ac::sinUnits` / `ac::cosUnits`（角度先走 `quantizeAngle`）。该表由本份冻结，羊群 AI 计划只消费、不再定义。

### 5.5 伤害、护甲与衰减

```cpp
// server/src/combat/damage.cpp
const double fell = 1.0 - weapon.falloffPerM * std::max(0.0, distanceM - weapon.falloffStartM);
const double falloff = fell < kFalloffMinMultiplier ? kFalloffMinMultiplier : fell;  // 下限 0.5
const double base = weapon.damage * partMultiplier(part, weapon.headshotMultiplier)
                    * falloff * (isRage ? kRageDamageMultiplier : 1.0);
out.armorDamage = victimArmor > 0.0 ? base * kArmorAbsorbRatio : 0.0;   // 0.6
out.hpDamage = base - out.armorDamage;
out.isHeadshot = (part == kHitPartHead);
```

部位倍率：头 = 武器 `headshotMultiplier`（三把均为 2.0）、躯干 1.0、四肢 0.75。护甲上限 50、生命上限 100，**护甲先扣**，两者都不低于 0。三把武器 `falloffPerM = 0` ⇒ 衰减倍率恒为 1；下限 `kFalloffMinMultiplier = 0.5` 只在将来重新打开衰减时生效（改它必须走 ADR 并重建 fixture）。友伤 `kFriendlyFire = false`：同队命中直接丢弃。

### 5.6 每 tick 结算顺序（接在 S06 阶段 10）

1. 按玩家 `EntityId` 升序：`updateWeapon`（换弹完成补给、散布衰减）。
2. 按玩家 `EntityId` 升序处理命令（命令游标与阶段 1 一致）：写 `interactHeld`；已倒地则跳过后续；`switchWeapon` → `reload` → 怒气激活（成功则发 `rageActivated`，value 8000）→ 有开火位则开火。
3. 按玩家 `EntityId` 升序 `updateRage`（到期清零、闲置衰减），随后做倒地救援结算：受害者按升序，救援者取升序第一个满足条件者。

开火：节流与弹药校验通过后按 `pellets` 逐弹丸生成射向并求交，命中即结算；事件 `playerHit` 的载荷（与 S03 §5.4 事件表逐字一致）为 `subjectId` u16 = 射手、`targetId` u16 = 受害者、`value` u16 = 护甲伤害 + 生命伤害、`flags` u8（bit0 `headshot` / bit1 `downed` / bit2 `killed`）、`hitX`/`hitY`/`hitZ` i16（厘米，权威命中点取 §5.3 射线求交的最近命中点），载荷 14B、条目总长（`eventId` u32 + `type` u8 + 载荷）18B；羊死亡再发 `sheepKilled` 并累加射手怒气；玩家生命归零且未倒地则 `markDowned` + `playerDowned`。

### 5.7 倒地、救援与怒气

| 项 | 常量 | 值 |
|---|---|---|
| 救援 | `kReviveRangeM` / `kReviveDurationMs` / `kReviveResetDelayMs` | 2.0 / 3000（= 60 tick）/ 5000 |
| 救援 | `kReviverMaxSpeed` / `kRevivedHpRatio` / `kWaveReviveHpRatio` / `kProgressEventStepRatio` | 1.5 / 0.5 / 0.5 / 0.05 |
| 怒气 | `kRageMax` / `kRagePerKill` / `kRagePerEliteKill` / `kRageHeadshotKillMultiplier` | 100 / 8 / 20 / 2（爆头击杀 16 / 40） |
| 怒气 | `kRageIdleDecayDelayMs` / `kRageDecayPerSecond` | 10000 / 5 |
| 狂暴与精英 | `kRageDurationMs` / 伤害 / 射速 / 移速倍率 / `kSheepEliteState` | 8000 / 1.3 / 1.25 / 1.15 / 2 |

- 倒地：生命归零即 `downed`，实体保留、水平速度清零（阶段 1 里直接 `continue`）、不可开火、仍可被救援。
- 救援：救援者必须同队、未倒地、持续按住 `interact`、水平速度 ≤ 1.5 m/s、水平距离 ≤ 2.0m；每 tick 进度 +`dtMs`，满 3000ms 即 `reviveDone`（被救者生命 = 上限 × 0.5）；中断立即清空 `reviverId` 并在 `nowMs + 5000` 后把进度清零；进度事件 value = `round(ratio * 1000)`。
- 精英判定：`isElite = (entity.state == kSheepEliteState)` 且 `kSheepEliteState = 2` —— 与 v1 `SHEEP_ELITE_STATE` **逐字一致**（在 v1 里该常量等于羊状态码 2）。为保持对拍逐位一致，v2 原样保留；若要修正口径必须先写 ADR 并重建 fixture。
- 怒气：击杀累加（精英 20、普通 8、爆头 ×2），上限 100；满值后 `activateRage` 清零并开启 8 秒狂暴；狂暴期间伤害 ×1.3、射速间隔 ÷1.25、移速 ×1.15（移速由 S06 的命令应用读取）；未满且 10 秒无战斗开始每秒 -5，下限 0；到期立即失效。
- 波间复苏入口：`reviveDownedForWaveClear` 把全部倒地者按 `kWaveReviveHpRatio` 复苏并发 `reviveDone`（由对局流程计划在波次清空时调用）。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 抖动索引或 `imul` 常量抄错，弹着点漂移 | §6 第 5 条或连射类 fixture 变红 | 从 v1 `weapons.ts` 复制常量与索引表达式；先用 fixture 的连射场景定位再改 |
| 部位口径与命中盒混淆（拿 `radiusM` 判命中） | 描头经常判成躯干 | 命中只走 §5.4 的双口径；`radiusM` 只服务于移动、分离与羊的攻击距离 |
| 回滚姿态读错导致"打身后" | 高延迟下命中率异常 | 回滚只作用于玩家目标、上限 200ms、越界按当下姿态；用例覆盖 `rewindMs = 0 / 100 / 200` |
| 怒气衰减在战斗中提前触发 | 满值迟迟到不了 | 命中与击杀都必须刷新 `lastCombatAtMs`；用例断言 10 秒内不衰减 |

回滚目标：回到 `HANDOFF-S07` 的状态（阶段 10 为空实现、无伤害）。回滚方式为删除 `server/src/combat/` 与两个常量头，把阶段 10 还原为空函数；模拟内核与对拍不受影响。
