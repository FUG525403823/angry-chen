# S06 模拟内核：玩家移动与碰撞
> 里程碑：MS06 ｜ 预估：1.5 人日 ｜ 上游移交物：HANDOFF-S05

## 1. 目标

本步骤结束后，`ServerProcess` 能用恒定 50ms 的 tick 推进一个 `World`：已入局的陈sir 按上行命令（`moveX` / `moveY` / 朝向 / 冲刺位）移动，撞到谷仓与栅栏时停在边界上，与其他实体按半径互相分离；同一份移动语义同时以纯函数 `localStep` 暴露，使「同一初始状态 + 同一批命令」在权威侧与预测侧产生**逐位相同**的位姿。

## 5. 冻结契约

### 5.1 tick 阶段顺序（不可重排；`dtMs` 恒为 50）

顺序：0 `stepWorld` 头部（`tick += 1`、`timeMs += dtMs`、清空事件与 `eventCursor`）→ 1 `applyCommands`（按玩家 `EntityId` 升序）→ 2 `collectPlayerIds`（升序，跳过 `idle`）→ 3 `buildSpatialGrid` → 4 `updateAiIntents` → 5 `applyAiIntents` → 6 `applyKnockback` → 7 `integrateState(dtMs / 1000.0)` + `aliveMs += dtMs`（末尾对正在救援的玩家把水平速度 `clampHorizontalSpeed(1.5)`）→ 8 `collideStatic` → 9 `buildSpatialGrid` + `separateEntities`（每趟分离后重跑 `collideStatic`）→ 10 `resolveCombat` → 11 `resolveSheepAttacks` / `resolveEliteFire` / `advanceProjectiles` / 羊王更新 → 12 `stats.aliveSheep` 汇总。

本份实现 0/1/2/7/8/9/12；4/5/6/10/11 为空实现（空函数体、签名一次冻结）。阶段只允许在末尾追加；禁止变长 `dt`；`dtMs != 50` 时返回 `false` 且世界不变。

### 5.2 命令应用（逐位复刻 v1 `applyCommandToState`，禁止改写运算顺序）

```cpp
// server/src/sim/movement.cpp
void applyCommandToState(MoveState& s, const Command* c, double speedMultiplier) {
  if (c == nullptr) { s.vel = {0.0, 0.0, 0.0}; return; }   // 缺命令：速度归零、位置不动
  s.yaw = c->yaw; s.pitch = c->pitch;                      // 状态与命令一律 double 弧度
  const uint16_t yawTableUnits = ac::quantizeAngle(c->yaw);  // 需要方向向量时才量化成角度单位并查表
  const double speed = ((c->buttons & kButtonSprint) != 0 ? kSprintSpeedMps : kMoveSpeedMps)
                       * speedMultiplier;
  const double fx = ac::sinUnits(yawTableUnits), fz = ac::cosUnits(yawTableUnits);
  const double rx = ac::cosUnits(yawTableUnits), rz = -ac::sinUnits(yawTableUnits);
  double vx = fx * c->moveX + rx * c->moveY, vz = fz * c->moveX + rz * c->moveY;
  const double magSq = vx * vx + vz * vz;
  if (magSq > 1.0) { const double inv = 1.0 / std::sqrt(magSq); vx *= inv; vz *= inv; }
  s.vel.x = vx * speed; s.vel.y = 0.0; s.vel.z = vz * speed;
}
```

命令结构（字段顺序 = 线上载荷顺序，14 字节布局见 S03 §5.2）：`{moveX, moveY, yaw, pitch, buttons, switchTo, seq, clientTick}`。`moveX` / `moveY` 线上为 i8（±127），解码后除 127 得到内存侧 double ∈ [-1, 1]；`yaw` / `pitch` 线上为 u16 角度单位，解码后经 `radiansFromUnits` 得到 double 弧度（内存侧与对拍一律 double 弧度）；`seq` u16；`clientTick` u32（即 v1 `Command.tick`）。`buttons` 位域（u8，写盘 `& 0xff`）：`fire 1 / sprint 2 / jump 4 / reload 8 / interact 16 / rage 32 / switchWeapon 64 / ready 128`（v1 序 + `ready = 128`）；示例字节 `0x09 = fire|reload`（与 S03 §5.2 逐字一致）。

### 5.3 角度一律走共享查表（ADR-010 §3）

| 常量 / 规则 | 值 |
|---|---|
| `quantizeAngle(rad)` | `wrapAngle(rad) / kTwoPi * 65536.0` 后 `floor(x + 0.5)` 取低 16 位（S02 §5.3 冻结） |
| `radiansFromUnits(u)` | `u * (kTwoPi / 65536.0)`，`kTwoPi = 6.283185307179586`（位型 `0x401921FB54442D18`） |
| 查表 | `ac::sinUnits(u)` 取 `kSinQ30[u & 0xFFFF]` 并乘 `0x1p-30`；`ac::cosUnits(u) = ac::sinUnits((u + 16384) & 0xFFFF)` |
| 表来源 | `docs/evidence/fixtures/trig-table.json`（三键 CRC32C 锚点），由 `server/tools/gen-trig-table.mjs` 生成 `server/src/core/trig_table.hpp`（S02 交付） |
| 表示与用途 | 状态与对拍一律 double 弧度（S05 §5.2）；要方向向量用 `ac::quantizeAngle` + `ac::sinUnits` / `ac::cosUnits`（或 `ac::forwardFromYaw` / `rightFromYaw`），要角度单位用 `quantizeAngle` / `radiansFromUnits` |

本份不新建任何表：`kSinQ30[65536]` / `kAtanUnits[1025]` / `kAsinUnits[1025]` 由 S02 冻结并入库；模拟代码禁止出现 `std::sin` / `std::cos` / `std::atan2` / `std::hypot`。客户端预测必须使用同一张表与同一套量化入口，否则 §5.6 的一致性断言必然失败。

| 项 | 值 |
|---|---|

### 5.6 `localStep` 契约（客户端预测复用）

```cpp
struct LocalStepResult { bool ok; uint32_t tick; uint32_t timeMs; };
LocalStepResult localStep(World& world, const Command* commands, uint32_t commandCount,
                          uint32_t dtMs, EntityId localPlayerId);
```

- 语义：只推进 `localPlayerId` 一个 tick，等价于权威 tick 的子集「命令应用 → 积分 → 静态碰撞」；`commands` 为未确认命令缓冲（按 `seq` 升序，`commandCount >= 1`），本次只消费 `commands[0]`；`dtMs` 必须等于 50，否则返回 `{false, tick, timeMs}` 且世界不变。
- 副作用与输出：不读 `ai` / `spawn` 流、不写事件池、不触碰其他实体与统计量；位姿写回该玩家实体并返回推进后的 `world.tick` / `world.timeMs`。
- 一致性：同一初始世界与同一命令序列下，`localStep` 连跑 N 次与 `stepWorld` 每次传 1 条命令跑 N 次，`pos.x/y/z` 与朝向（double 弧度）必须 `bit_cast<uint64_t>` 全等。

构建冻结：`-std=c++20 -O2 -Wall -Wextra -fno-fast-math -ffp-contract=off`，禁止 `-march=native` / `-ffast-math` / `-Ofast`，基线 x86-64 SSE2；`stepWorld` 与 `localStep` 热路径不得调用分配器（测试构建用计数版全局 `operator new` 断言）。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 有人绕开 S02 的查表自建角度表 | `Get-ChildItem server/src -Recurse -Include *.cpp \| Select-String -Pattern "std::sin\|std::cos\|std::atan2"` 命中 | 只从 `server/src/core/trig_table.hpp` 取；缺口按 S02 的复查条件先改契约再动代码 |
| 运算顺序被无意改写 | 240 tick 位型对比用例不等 | §5.2 代码块整段复制进实现，禁止"顺手优化"；用 `bit_cast` 逐字段打印定位 |
| `-ffp-contract=off` 未生效导致 FMA 合入 | 同一二进制两次运行结果不同 | 编译标志进构建脚本并加断言；必要时用中间量阻断融合 |
| 分离在重叠边角抖动 | 分离用例间距在 0.8 附近振荡 | 退回「单趟 + 半邻域 + 各推一半」最小实现，并断言推离总量守恒 |

回滚目标：回到 `HANDOFF-S05` 的状态（不存在 `step.cpp` / `local_step.cpp` 的纯数据世界）。回滚方式为删除本份新增文件与构建目标登记，v1 冻结包与文档不受影响。
