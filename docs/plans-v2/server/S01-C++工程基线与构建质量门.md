## 5. 冻结契约
### 5.1 目录布局
```
server/
├─ CMakeLists.txt
├─ build.ps1
├─ src/
│  ├─ main.cpp
│  ├─ core/        log / math / rng / quantize / hash / trig_table
│  ├─ sim/         world / entity_table / pose_history / spatial_grid / arena
│  ├─ net/         wire / codec / udp_socket / reliability / fragment / handshake / memory_transport
│  ├─ ai/          羊群行为、波次导演
│  ├─ combat/      武器、射线、伤害、倒地、怒气
│  ├─ room/        房间、会话、对局流程
│  └─ persist/     战绩存储与诊断报告
├─ tests/
│  ├─ tiny_test.hpp
│  ├─ main_test.cpp
│  └─ fixtures/    字节级 fixture（十六进制文本）
└─ tools/          构建期脚本（表生成、fixture 导出）
```
新增子目录必须先在本表登记；头文件与实现同目录，命名 `snake_case`（工程约定 §11）。

### 5.2 语言与编译开关
| 项 | 冻结值 |
|---|---|
| 标准 | `-std=c++20`（MSVC 用 `/std:c++20`） |
| 优化 | `-O2`（Release）/ `-O0 -g`（Debug） |
| 浮点 | `-ffp-contract=off`、`-fno-fast-math`（禁止隐式 FMA 与快速数学） |
| 警告 | `-Wall -Wextra -Werror`；CMake 选项 `AC_WERROR` 默认 `ON`，CI 恒为 `ON` |
| 禁止 | `-ffast-math`、`-Ofast`、`-march=native`、`-mfma`、`/fp:fast` |
| 目标基线 | x86-64 SSE2（默认，不额外开指令集开关） |
| 依赖 | 仅 C++ 标准库 + 系统库（WinSock2 / POSIX socket）；新第三方库须先写 ADR |

### 5.3 target、产物与构建命令字面量
| target | 类型 | 组成 | 产物 |
|---|---|---|---|
| `ac_core` | 静态库 | `server/src/core/*.cpp` 及后续 `sim/net/ai/combat/room/persist` | `libac_core.a` |
| `ac_server` | 可执行 | `ac_core` + `server/src/main.cpp` | `server/build/ac_server.exe` |
| `ac_tests` | 可执行 | `ac_core` + `server/tests/main_test.cpp` | `server/build/ac_tests.exe` |
| ctest 用例 | CTest | `add_test(NAME unit COMMAND ac_tests)` | `1/1 Test #1: unit ... Passed` |

三条命令本份结束时必须全部可用（第一条是唯一入口）：
- `pwsh -File server/build.ps1 -Config Release` → 末行 `[build] ok ac_server.exe`
- `cmake -S server -B server/build -G Ninja -DCMAKE_BUILD_TYPE=Release; cmake --build server/build; ctest --test-dir server/build --output-on-failure`
- 直编兜底：`g++ -std=c++20 -O2 -ffp-contract=off -fno-fast-math -Wall -Wextra -Werror -Iserver/src server/src/main.cpp server/src/core/log.cpp -o server/build/ac_server.exe`

### 5.4 日志 JSON 字段（每行一个 JSON 对象，`\n` 结尾）
| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ts` | string | 是 | UTC ISO8601 毫秒，定长 `YYYY-MM-DDTHH:MM:SS.mmmZ` |
| `level` | string | 是 | `trace`/`debug`/`info`/`warn`/`error` |
| `evt` | string | 是 | 事件名，过去式（如 `serverStarted`、`clientDisconnected`） |
| `tick` | uint32 | 否 | 当前 tick；非模拟上下文省略 |
| `room` | string | 否 | 4 位大写房间码；无房间省略 |
| 附加键 | string/int64/uint64/double/bool | 否 | 调用点按插入顺序输出 |

字段顺序固定为 `ts,level,evt,tick,room,<附加键按插入序>`；字符串转义 `"`→`\"`、`\`→`\\`、控制字符→`\u00XX`；double 用 `%.17g`，非有限值输出 `null`；单行 ≤ 4096 字节，超长截断并在末尾加 `"truncated":true`。

### 5.5 自研断言框架 API（`server/tests/tiny_test.hpp`）
```cpp
namespace ac::test {
  void registerCase(const char* name, void (*fn)());  // AC_TEST 宏静态注册
  int  runAll(int argc, char** argv);                 // 支持 --filter=<子串>；返回失败用例数
}
#define AC_TEST(name)    // 定义 void name() 并静态注册，name 全局唯一
#define AC_CHECK(cond)   // 失败打印 FAIL <case>: <file>:<line>: <cond>
#define AC_CHECK_EQ(a, b)
#define AC_CHECK_NEAR(a, b, eps)
#define AC_FAIL(msg)
```
输出契约：每用例一行 `PASS <name>` 或 `FAIL <name>: <file>:<line>: <expr>`；末行 `TESTS <通过>/<总数>`；进程退出码 = 失败用例数。

## 6. 验证
| 命令 | 期望输出 | 失败意味着什么 |
|---|---|---|
| `g++ --version` | 含 `15.2.0` | 兜底编译器不在 PATH，`build.ps1` 的直编分支不可用 |
| `pwsh -File server/build.ps1 -Config Release` | 末行 `[build] ok ac_server.exe`，`server/build/ac_server.exe` 存在 | 源文件清单或编译开关有误，后续全部 C++ 计划无法开工 |

| `server/build/ac_tests.exe` | 末行 `TESTS 12/12`，退出码 0 | 断言框架或首套用例有缺陷，测试门不可信 |
| `ctest --test-dir server/build --output-on-failure` | `100% tests passed, 0 tests failed out of 1` | 未注册 ctest 用例，CI 失去测试门 |

## 8. 风险与回滚
| 风险 | 触发信号 | 对策 |
|---|---|---|
| cmake/ninja 安装失败或版本 < 3.28 | `cmake --version` 报错或低于 3.28 | 先用 `build.ps1` 的 mingw 直编分支推进；CI 用 ubuntu 自带 apt 版 cmake（≥3.28），本地安装不阻塞本份交付 |
| mingw 与 Linux g++ 的 `-Werror` 行为差异 | CI server job 因告警红灯 | 以 CI 编译器为准收紧代码；系统头用 `-isystem`，不整体 `-w` 静音 |
| 断言框架在首份就膨胀 | `tiny_test.hpp` 超过 200 行 | 只保留 5 个宏与 `--filter`，覆盖率与报告留给后续文档化流程 |
| 日志格式漂移 | `ConvertFrom-Json` 解析失败或键顺序变化 | 字段表本份冻结，后续只能追加键，不得改键名与顺序 |
| 本机无 cmake 导致 CI 与本地不一致 | 本地直编通过而 CI 失败（或反之） | 两条命令在 §6 都要求跑通，差异在 PR 里显式比对 |

回滚目标：`HANDOFF-S00`——删除 `server/` 下本份新增的全部文件（保留 `README.md` 与 `.gitignore`），从 `.github/workflows/ci.yml` 撤掉 `server` job；`packages/**` 与 `docs/00-共识/**` 不动，`node tools/check-docs.mjs` 仍全绿。
