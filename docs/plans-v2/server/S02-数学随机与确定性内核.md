## 5. 冻结契约
### 5.1 数学类型与函数
```cpp
namespace ac {
struct Vec3 { double x; double y; double z; };   // sizeof 24, alignof 8, 标准布局
struct Aabb { Vec3 min; Vec3 max; };             // sizeof 48
Vec3 addScaled(const Vec3& base, const Vec3& dir, double scale) noexcept;
double lengthSq(const Vec3& a) noexcept;   double length(const Vec3& a) noexcept;
Vec3 normalize(const Vec3& a) noexcept;    // 零向量返回 (0,0,0)，不产生 NaN
double clamp(double v, double lo, double hi) noexcept;   double clamp01(double v) noexcept;
double wrapAngle(double rad) noexcept;     // 归一到 (-PI, PI]；非有限输入返回 0
Vec3 forwardFromYaw(double yaw) noexcept;  // (sin yaw, 0, cos yaw)
Vec3 rightFromYaw(double yaw) noexcept;    // (cos yaw, 0, -sin yaw) —— 镜像基，禁止翻转
Vec3 yawPitchToDirection(double yaw, double pitch) noexcept;
bool aabbOverlaps(const Aabb& a, const Aabb& b) noexcept;      // 闭区间，三轴同时重叠

```
字段名、语义与 v1 `packages/shared/src/math.ts` 一一对应；翻转 `rightFromYaw` 的符号会同时改变射线、羊群转向与快照语义，属禁止变更。

### 5.2 mulberry32 与三流派生
```cpp
enum class RngStream : uint32_t { kAi = 1, kSpawn = 2, kFx = 3 };
struct Rng { uint32_t a; uint32_t nextU32() noexcept; double nextDouble() noexcept; };
Rng createRng(uint32_t seed, RngStream stream) noexcept;
double rngRange(Rng& r, double lo, double hi) noexcept;
int32_t rngInt(Rng& r, int32_t loInclusive, int32_t hiInclusive) noexcept;
```
- 派生：`a0 = (seed * 0x9E3779B1u + streamId) mod 2^32`（`streamId` = 1/2/3）。
- `nextU32()`：`a = a + 0x6D2B79F5`（mod 2^32）；`t = a`；`t = imul(t ^ (t >> 15), t | 1)`；`t ^= t + imul(t ^ (t >> 7), t | 61)`；返回 `t ^ (t >> 14)`。`imul` = 取低 32 位的无符号回绕乘法。
- `nextDouble() = nextU32() / 4294967296.0`（除 2³²，不是 2³²−1）。
- `rngInt = lo + (int32_t)floor(nextDouble() * (hi - lo + 1))`；`hi < lo` 时返回 `lo`；`rngRange = lo + (hi - lo) * nextDouble()`。
- 冻结位级锚点（`seed = 1234`，比较 double 的 IEEE754 原始位）：
| 流 | 派生 seed | 第 1 个 | 第 2 个 | 第 3 个 |
|---|---|---|---|---|
| `ai` | `0xA7689733` | `0x3FE136AC1DA00000` | `0x3FE621AEFEC00000` | `0x3FEA98B75AC00000` |
| `spawn` | `0xA7689734` | `0x3FE034F2D0E00000` | `0x3FE9A52769400000` | `0x3FC03B8F8F000000` |
| `fx` | `0xA7689735` | `0x3FE6611F0D400000` | `0x3FE348F073800000` | `0x3FC777A9BA000000` |

`ai` 流第 4–9 次 `rngInt(0, 99)` 为 `53, 69, 83, 62, 24, 82`。约束：模拟只允许读 `ai` 与 `spawn`；`fx` 流仅由表现层请求消费，读取 `fx` 不得改变模拟状态。

### 5.3 量化（ADR-009 冻结表，只做实现不做设计）
```cpp
int16_t  quantizePosition(double meters) noexcept;   // cm，夹取 [-32768, 32767]，-0 归一为 0
double   dequantizePosition(int16_t cm) noexcept;    // cm / 100.0
uint16_t quantizeAngle(double radians) noexcept;     // 0..65535，65536 单位 = 2*PI
double   dequantizeAngle(uint16_t units) noexcept;   // wrapAngle(units / 65536.0 * 2*PI)
int8_t   quantizeAxis(double axis) noexcept;         // 夹取 [-127, 127]
double   dequantizeAxis(int8_t v) noexcept;          // v / 127.0
uint8_t  quantizeRatio(double ratio) noexcept;       // 夹取 [0, 255]
double   dequantizeRatio(uint8_t v) noexcept;        // v / 255.0
```
- **舍入一律用 `floor(x + 0.5)`**，禁止 `std::round`/`lround`/`llround`（负数半值语义不同：`floor(-0.5 + 0.5) = 0`，`std::round(-0.5) = -1`）。
- `quantizePosition = clamp(floor(m * 100.0 + 0.5), -32768, 32767)`；`quantizeAxis = clamp(floor(a * 127.0 + 0.5), -127, 127)`；`quantizeRatio = clamp(floor(r * 255.0 + 0.5), 0, 255)`。
- `quantizeAngle`：`u = (int64_t)floor(wrapAngle(rad) / 2*PI * 65536.0 + 0.5); u %= 65536; if (u < 0) u += 65536;`（C++ 截断取模，等价于 v1 的 JS `%`）。
- 冻结锚点：`quantizePosition(1.2345)=123`、`quantizePosition(-0.005)=0`、`quantizePosition(500)=32767`、`quantizePosition(-500)=-32768`；`quantizeAxis(0.5)=64`、`quantizeAxis(-0.004)=-1`；`quantizeRatio(0.5)=128`、`quantizeRatio(0.004)=1`；`quantizeAngle(1.0)=10430`、`quantizeAngle(-3.5)=29030`、`quantizeAngle(PI)=32768`。

### 5.4 共享角度表（替代全部超越函数）
表文件与客户端链**共用同一份**：`docs/evidence/fixtures/trig-table.json`（纯文本入库），结构 `{"scale":1073741824,"units":65536,"sin":[...],"atanUnits":[...],"asinUnits":[...]}`。
| 键 | 长度 | 生成规则（第 k / i 项） | CRC32C（int32 小端字节流） |
|---|---|---|---|
| `sin` | 65536 | `round(sin(2*PI*k/65536) * 2^30)`，k = 0..65535 | `0x8BD9F737`（262144 字节） |
| `atanUnits` | 1025 | `round(atan(i/1024) / 2*PI * 65536)`，单位 = ADR-009 角度单位 | `0x197C3A8D`（4100 字节） |
| `asinUnits` | 1025 | `round(asin(i/1024) / 2*PI * 65536)` | `0xAD2BD35E`（4100 字节） |

```cpp
constexpr int32_t kSinQ30[65536];      // 构建期由 trig-table.json 的 sin 键生成
constexpr int32_t kAtanUnits[1025];    // 值域 0..8192，比例 i/1024 对应的角度单位
constexpr int32_t kAsinUnits[1025];    // 值域 0..16384
double  sinUnits(uint16_t units) noexcept;   // kSinQ30[units] * (1.0 / 1073741824.0)
double  cosUnits(uint16_t units) noexcept;   // kSinQ30[(units + 16384u) & 0xFFFFu] * (1.0 / 1073741824.0)
double  radiansFromUnits(uint16_t units) noexcept;  // units * (2*PI / 65536.0)
uint16_t angleUnitsFromVector(double dx, double dz) noexcept;  // atan2(dx, dz) 的整数实现
uint16_t angleUnitsFromRatio(double r) noexcept;               // asin(clamp(r, -1, 1)) 的整数实现
```
- `sin` 表**直接以 ADR-009 角度单位作下标**（65536 项 ↔ 65536 单位），查表无索引舍入；幅值精度 `2^-30 ≈ 9.3e-10`。
- `cosUnits` 用 `units + 16384` 位移，不另建表（与客户端 `Cos(units) = Sin(units + 16384)` 逐位同义）。
- `angleUnitsFromVector` 的八分圆算法（只用一次除法与一次乘法，跨语言逐位一致）：取 `ax=|dx|`、`az=|dz|`；`swap = ax > az`；`num = swap ? az : ax`，`den = swap ? ax : az`；`t = den == 0 ? 0 : (size_t)floor(num / den * 1024.0 + 0.5)`；`a = swap ? 16384 - kAtanUnits[t] : kAtanUnits[t]`；`dx < 0` 时 `a = 65536 - a`；`dz < 0` 时 `a = (32768 - a) & 0xFFFF`。返回 `a & 0xFFFF`。
- 锚点：`kSinQ30[0]=0`、`[8192]=759250125`、`[16384]=1073741824`、`[32768]=0`、`[49152]=-1073741824`；`kAtanUnits[0]=0`、`[512]=4836`、`[1024]=8192`；`kAsinUnits[0]=0`、`[512]=5461`、`[1024]=16384`。
- 精度上界：`sin`/`cos` 幅值误差 ≤ `2^-30`；`angleUnitsFromVector` 相对 `atan2` 误差 ≤ `5e-4 rad ≈ 0.029°`（比例表 1025 点；实测 `dx=0.3, dz=0.7` 差 1 单位、`dx=-0.9, dz=0.2` 差 4 单位）；`angleUnitsFromRatio` 同量级。
- 生成方式：`node tools/export-trig-table.mjs` 写出 `docs/evidence/fixtures/trig-table.json`（该脚本与客户端链共用，**三个键都必须输出**；只输出 `sin` 时服务端自检失败）；服务端 `node server/tools/gen-trig-table.mjs` 读同一 JSON 生成 `server/src/core/trig_table.hpp`（含三个 CRC 常量）。对拍向量的 v1 侧生成脚本必须改用同一批整数表替换 `Math.sin/cos/atan2/asin`，两侧表内容逐字相同是逐位一致的前提。
- 运行时禁令：`server/src/**` 不得出现 `sin/cos/tan/atan2/asin/exp/log/pow/hypot` 的标准库调用；需要角度一律走本表。

## 8. 风险与回滚
| 风险 | 触发信号 | 对策 |
|---|---|---|
| 表采样源不同（V8 与其它 JS 引擎的 `Math.sin` 末位差异） | 重生成后 `sin` CRC 不等于 `0x8BD9F737` | 共享表按本份 CRC 冻结入库；重生成在 Node 24 下执行并比对 CRC，不一致即停手排查采样口径 |
| 比例表精度不足导致转向抖动 | `angleUnitsFromVector` 与 `atan2` 偏差 > 5 单位，或羊群转向出现锯齿 | 比例表加密到 2049 点（i/2048）并同步客户端，需先改本份契约与共享 JSON |
| 量化取整在跨语言边界不一致 | `--filter=quantize` 在 C# 侧同样用例失败 | 统一 `floor(x + 0.5)`；C# 用 `Math.Floor`，禁 `Math.Round`（银行家舍入） |
| `fx` 流被模拟路径误读 | 同样的 `ai` 命令序列产出不同快照 | 代码评审 + `rng_test` 里“只读 fx 不改状态”的断言 |
| 表文件过大拖慢编译 | `trig-table.json` > 1 MB 或 `trig_table.hpp` > 1.5 MB | 与客户端链同步改为 16384 项 + 线性插值（两侧同一规则），需先改本份契约与共享 JSON |
