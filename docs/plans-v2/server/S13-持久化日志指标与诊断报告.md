## 5. 冻结契约

战绩记录 schema（`match_store.hpp`，NDJSON 一行一条，字段名即 JSON 键）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `matchId` | string | 对局唯一 id（文件名安全字符集 `[A-Za-z0-9._-]`） |
| `startedAtMs` | u64 | 对局开始的 Unix 毫秒 |
| `durationMs` | u32 | 对局时长（毫秒） |
| `waveReached` | u16 | 到达的最高波次 |
| `winnerTeam` | u8 | 0 或 1 |
| `playerCount` | u8 | 参战人数（1…4） |
| `players[]` | array | `{ name, kills, headshots, shotsFired, hits, revives, downs, aliveMs, leftMidMatch }` |

| 冻结项 | 值 / 定义 |
|---|---|
| 存储文件 | `<dataDir>/matches.ndjson`（战绩，只追加，永不截断）；`<dataDir>/reports/<matchId>.json`（单局诊断报告，保留最近 200 份）；`<dataDir>` 即 `AC_DATA_DIR` |
| 常驻上限 | `kMaxRecords = 10000`；超出时批量淘汰 `max(1, kMaxRecords/100)` 条最旧记录 |
| 坏行处理 | 解析失败或字段缺失 → 跳过并计 `ac_corrupt_lines_total`，不抛异常 |
| 排序一致性 | top = 击杀降序 → `startedAtMs` 降序 → `matchId` 升序决胜；recent = `startedAtMs` 降序 → `matchId` 升序 |
| sqlite 缝 | 同一接口的实现声明 `SqliteMatchStore` 保留；`AC_WITH_SQLITE` 默认 0，启用需先改 ADR |

> **已裁决（B7，`AC_DATA_DIR` 的平台分叉 + 测试/工具必须显式注入）**。原问题：本节只写 `<dataDir>` 即 `AC_DATA_DIR`，没写默认值从哪来、能不能依赖它。**裁决**：
> 1. **默认值按平台分叉**（保持现状）：POSIX `/var/lib/angry-chen`、Windows `data`（`server/README.md` §18.8-1：Windows 上按 POSIX 默认值写会在盘根造 `/var/lib` 树，故实现回落 `data`；部署单元显式注入 POSIX 路径）。
> 2. **测试与工具必须显式注入数据目录**（`RuntimeConfig::dataDir` 或 `AC_DATA_DIR`），**不得依赖默认绝对路径可写**：CI runner 上非 root 建不了 `/var/lib`，`runtime_test` 的 5 条与 `ac_gate` 都曾因此判红（`server/README.md` §19.2 的"root 假象"实测：同一套件在云服务器 root 下 468/468、在 CI runner 非 root 下 463/468）；`ac_gate` 未显式设置 `AC_DATA_DIR` 时用构建目录下的相对路径 `ac-gate-data`。
> 3. 结论入判据：**任何依赖"默认绝对路径可写"的用例都是环境依赖**，本步的 `store_test.cpp` 与后续工具都必须注入。
