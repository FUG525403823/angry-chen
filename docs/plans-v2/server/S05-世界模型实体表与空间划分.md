## 5. 冻结契约
### 5.1 World 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| `seed` | u32 | 对局种子；三流 RNG 都由它派生 |
| `tick` | u32 | 已步进 tick 数，从 0 起；`timeMs = tick * 50` |
| `entities` | `Entity[kMaxEntities]` | 定长数组，**下标 = `EntityId - 1`**，永不搬移 |
| `activeIds` | `u16[kMaxEntities]` + `activeCount` | 活动 `EntityId`，严格升序，是唯一遍历入口 |
| `freeIds` | `u16[kMaxEntities]` + `freeCount` | `EntityId` 空闲栈（LIFO） |
| `highWater` | u16 | 已分配过的最大 `EntityId`，初值 0 |
| `rng` | `{ ai, spawn, fx }` | 三条 `Rng` 流（seed 派生与常量见确定性内核契约） |
| `stats` | `{ aliveSheep, eventsDropped }` | 每 tick 写一次，供指标与波次导演只读 |
| `poseHistory` | `PoseHistory` | 20 槽姿态环（§5.3） |
| `grid` | `SpatialGrid` | 4m 均匀网格（§5.4） |
| `events` | `Event[256]` + `eventCount` | 本 tick 事件缓冲（256 = 数组容量），每 tick 开头清零；缓冲满则丢新事件并累加 `eventsDropped`。线上单帧事件数由 `u8 eventCount` 编码（硬上限 255），单帧预算另见 ADR-009 |

本份冻结的字段即上表：类型、顺序与容量不得改动；实体子结构（武器、倒地、怒气、羊群 AI 状态）与波次/阶段字段由其所属模块追加，追加不得改变上表字段的类型与顺序。

### 5.2 Entity 与 EntityId 分配
| `Entity` 字段 | 类型 | 说明 |
|---|---|---|
| `id` | u16 | 1..1024，`0` 表示“无实体”（哨兵） |
| `active` | bool | false 表示槽位空闲 |
| `kind` | u8 | 0 player / 1 sheep / 2 projectile / 3 pickup |
| `pos`, `vel` | `Vec3`（double） | 米与米/秒 |
| `yaw`, `pitch` | double | 弧度；`yaw` 约定与数学内核一致（前向 = `(sin yaw, 0, cos yaw)`） |
| `hp`, `maxHp`, `armor` | i32 | 整数血量，避免浮点累积差异 |
| `state` | u8 | 表现层状态码（快照 `state` 字段） |
| `team` | u8 | 0 玩家方 / 1 羊群方 |
| `ownerId` | u16 | 投射物/掉落物的拥有者，无则 0 |
| `aliveMs` | u32 | 存活毫秒，用于表现与统计 |
| `idle` | bool | 宽限期内的玩家标记（不删实体） |

- 分配：`freeCount > 0` 时 `id = freeIds[--freeCount]`（LIFO，最近释放的优先复用）；否则 `id = ++highWater`（≤ `kMaxEntities`）；`highWater == kMaxEntities` 且空闲栈为空 → 返回 `{ok=false, reason=kEntityPoolExhausted}`，**world 状态保持不变**。
- 复用时该槽位必须整体重置（`pos/vel/yaw/pitch/hp/state/team/ownerId/aliveMs/idle` 与全部子结构恢复初值），历史数据不得残留。
- 释放：`active = false`、`id` 压入空闲栈、从 `activeIds` 二分移除（保持升序）；同一 tick 内不得重复释放同一 id。
- 遍历：一切模拟遍历走 `activeIds` 升序；禁止按 `entities` 全数组扫描（会破坏 ADR-010 的顺序契约）。

### 5.3 姿态历史环（回滚命中用）
| 项 | 冻结值 |
|---|---|
| 槽数 `kPoseHistorySlots` | 20（1 秒 @ 50ms tick） |
| 每槽最大玩家数 | 8 |
| 每玩家记录 | 5 个 double（`x`, `y`, `z`, `yaw`, `pitch`）+ `id` u16；条目含对齐共 48 字节 |
| 内存占用 | 20 槽 × 8 玩家 × 48 字节 = 7680 字节（48 = 5×8 + 2 + 6 填充），创建时一次性分配 |
| 回滚限制 | 回退量 `ms = rttMs / 2`，上限 `kRewindLimitMs = 200`（即允许值 = `min(rttMs / 2, 200)`）；**越限（`ms > 200`）返回 `ok = false` 且不回滚**，调用方按**当下**姿态判定；`clamped` 仅作诊断，不代表已按 200 夹取 |

```cpp
void recordPoseHistory(PoseHistory& h, const World& w) noexcept;   // 每 tick 末尾调用一次，只记 kind == player
bool samplePoseAgo(const PoseHistory& h, uint32_t ms, uint16_t entityId, SampledPose& out) noexcept;
// ms = 请求回退量 = min(rttMs / 2, 200)（上限 kRewindLimitMs）；命中槽位 age = ms / 50（tick 粒度），在相邻两槽间线性插值：
//   alpha = (targetTick - olderTick) / (newerTick - olderTick)   // newestTick - ms / 50
//   插值只做 + - * / ；无该实体的记录时返回 false 且 out.found = false
// ms > kRewindLimitMs 即越限：返回 ok = false 且不回滚（out.clamped = true 仅作诊断），调用方按当下姿态判定
```
查询语义：`ms = 0` 返回最新槽位原值（`alpha = 1`，无插值误差）；历史不足 20 槽时按已写槽位插值；`ms > 200`（越限）按上表返回 `ok = false` 且不使用回滚姿态，只有 `ok = true` 时才使用插值结果。

### 5.4 空间网格
| 项 | 冻结值 |
|---|---|
| 单元边长 `kSpatialCellMeters` | 4.0 m |
| 列/行 | 20 × 20（`ceil(80 / 4)`），单元总数 400 |
| 索引 | `cell = cz * 20 + cx`；`cx = clamp(floor((x + 40) / 4.0), 0, 19)`，`cz` 同理（越界夹取到边界格） |
| 结构 | `cellStart[401]`（i32，前缀和）+ `cellItems[1024]`（u16，存 `EntityId`） |
| 参与实体 | 除 `kind == projectile` 外的全部活动实体 |
| 重建 | 两趟计数排序，按 `activeIds` 升序写入 → 每格内 `EntityId` 升序 |
| 遍历顺序 | `cz` 外层升序 → `cx` 内层升序 → 格内按写入下标升序（即 `EntityId` 升序） |

查询：`forEachNeighbor(grid, x, z, radiusM, visit)` 覆盖 `[x ± r, z ± r]` 的全部整数格，夹取到 `[0, 19]`（夹取只会多访问、不会漏配对）；顺序断言只到「**每格内 `EntityId` 升序 + 格索引（`cz`/`cx`）升序**」这一级，**不作全局 `EntityId` 单调断言**。

### 5.5 场地与实体尺寸（继承 v1 冻结数值）
- 场地：80m × 80m，`halfSize = 40`；围栏高 3 m、厚 0.5 m；谷仓 AABB `min(-4, 0, -4)` / `max(4, 5, 4)`。
- `playerSpawn`（4 个）：`(-4.5, 7)`、`(-1.5, 7)`、`(1.5, 7)`、`(4.5, 7)`。
- `spawnPoint`（12 个，半径 38 m 环）：`(0, 38)`、`(19, 32.909)`、`(32.909, 19)`、`(38, 0)`、`(32.909, -19)`、`(19, -32.909)`、`(0, -38)`、`(-19, -32.909)`、`(-32.909, -19)`、`(-38, 0)`、`(-32.909, 19)`、`(-19, 32.909)`。
- 碰撞半径/高度：player `0.4 / 1.7`、sheep `0.5 / 0.9`、projectile `0.08 / 0.16`、pickup `0.35 / 0.7`（米）。
- 实体容量 `kMaxEntities = 1024`，与 `EntityId` 上限、网格 `cellItems` 容量三者必须恒等。

### 5.6 热路径零分配约束
`spawnEntity`、`despawnEntity`、`recordPoseHistory`、`buildSpatialGrid`、`forEachNeighbor` 在稳态下不得调用 `new`/`delete`/`malloc`/`realloc`，不得使用会分配的容器（`std::vector`/`std::string`/`std::map`）；容器一律在 `createWorld` 时定长预分配。

## 8. 风险与回滚
| 风险 | 触发信号 | 对策 |
|---|---|---|
| 实体表被搬移导致 `EntityId` 失效 | 用例中出现 id 与下标不一致 | §5.1 冻结“下标 = `EntityId - 1`、永不搬移”，容器只用定长数组 |
| 空闲栈 LIFO 复用旧子结构残留 | 复用的羊带着上一只的 AI 状态 | 释放时不清、分配时整体重置（§5.2），并有“复用后字段全为初值”的断言 |
| 网格单元尺寸选得过大/过小 | 邻居查询访问量 > 64 实体/次，或漏配对被测试抓到 | 先按 4m 冻结；若遥测显示单次访问 > 64，改 2m（20→40 列）并同步契约 |
| 姿态环只记玩家导致 AI 回滚需求落空 | 后续命中判定需要羊的过去姿态 | 本份已把槽位数据结构做成泛化记录（5 double + u16 id，含对齐 48B），扩到羊只需加一维上限并改契约 |
| 零分配被日志或断言打断 | `alloc_test` 出现非零计数 | 计数只在 `AC_CHECK` 内部清零的专门缝里读取；模拟路径禁用格式化输出 |

回滚目标：`HANDOFF-S04`——删除 `server/src/sim/**` 与两个测试文件；传输层与协议层不受影响，`node tools/check-docs.mjs` 仍全绿。
