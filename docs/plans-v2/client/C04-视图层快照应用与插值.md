# C04 视图层：快照应用与插值
> 里程碑：MC04 ｜ 预估：1 人日 ｜ 上游移交物：HANDOFF-C03

## 1. 目标

客户端把解码后的快照变成只读的 `SnapshotView`：100ms 插值缓冲与 ±50ms 抖动吸收、按 tick 单调丢弃旧帧与重复帧、远端实体位置与角度插值（角度走最短弧）、和解误差的视觉平滑与硬纠正吸附语义。本份只做快照应用与渲染侧插值，不含预测步进与和解重放。

## 5. 冻结契约

### 5.1 常量表
| 常量 | 值 |
|---|---|
| `InterpolationDelayMs` | `100`（插值缓冲，渲染时间落在最新快照之后 100ms） |
| `InterpolationDelayMaxMs` | `250`（动态上限） |
| 插值延迟动态化 | `clamp(2 * 到达间隔中位数, 100, 250)`，中位数取最近 `60` 个到达间隔采样 |
| `SnapshotHistory` | `6` 帧关键帧环 |
| `JitterAbsorbMs` | `50`（单帧时间估计的修正量上下限） |
| `StatsWindowMs` | `1000` |

### 5.2 旧快照丢弃规则（tick 单调）
```text
// 快照载荷段序（逐字对齐 S03 §5.3）：通用包头 → tick u32 → serverTimeMs u32 → lastAckedSeq u16
//   → baselineTick u32 → 实体块（count u8 + 15B×n） → 移除列表（removedCount u8 + u16×m）
//   → 事件块（eventCount u8 + Σ条目；v2 新增，置于载荷末尾）
// SnapshotView 的字段与上述段序一一对应：tick / serverTimeMs / lastAckedSeq / baselineTick / 实体镜像 / 移除列表 / 事件块。
```
| 条件 | 行为 |
|---|---|
| 帧内字段与段序 | 与 S03 §5.3 逐字一致：`tick`、`serverTimeMs`、`lastAckedSeq`、`baselineTick`、实体块、移除列表、事件块 |
| 帧内含事件块 | `eventCount` u8 + 条目（`eventId` u32 + `type` u8 + 载荷）；本份随帧保留供 HUD 消费，不参与插值 |
| `tick <= appliedTick` | 整帧丢弃，返回 `false`，不更新任何状态 |
| `baselineTick == 0` | 先清空镜像再应用，属全量帧 |
| `baselineTick > tick`，或 `baselineTick > appliedTick` | 丢弃该帧并计 `baselineMismatch`，不改动画状态 |
| 解码失败 | 丢弃并计 `invalidSnapshots`，已应用状态原样保留 |

### 5.3 渲染时间与插值
```csharp
// 时间估计：estimatedServerTimeMs 每帧向 (最新快照 serverTimeMs + 本地经过时间) 修正
// 单帧修正量 clamp(delta, -50, +50)；偏差绝对值超过 500ms（重连、长时间丢包）直接重置估计值
renderTimeMs  = estimatedServerTimeMs - interpolationDelayMs;
bracket       = FindBracket(帧的 serverTimeMs 升序表, renderTimeMs);
alpha         = clamp((renderTimeMs - older.serverTimeMs) / (newer.serverTimeMs - older.serverTimeMs), 0, 1);
pos           = Lerp(older.pos, newer.pos, alpha);
yaw/pitch     = LerpAngle(older, newer, alpha);   // 最短弧，delta 折到 [-π, π]
hpRatio/state/flags = 最新帧的值，不做插值；关键帧少于 2 时直接显示最新帧
```

### 5.4 远端实体平滑与生命周期
| 情形 | 行为 |
|---|---|
| id 同时出现在 older 与 newer | 位置与角度按 §5.3 插值 |
| id 只出现在最新帧（新进场） | 直接吸附到最新帧姿态，不做插值 |
| id 出现在移除列表 | 视图对象立刻回收进池，不做淡出 |
| 本地玩家已有预测值 | 用预测值渲染，不参与插值 |
| 本地玩家无预测值 | 用最新帧姿态 |

### 5.5 硬纠正的表现语义（阈值与过渡时长）
| 和解误差 `e` | 表现 |
|---|---|
| `e <= 0.001m` | 忽略（`SmoothingEpsilonM = 0.001`）；偏移量归零 |
| `0.001m < e <= 1.0m` | 交给 `ErrorSmoother`：偏移按时间常数 `0.12s` 的一阶指数衰减，衰减到小于 `0.001m` 即归零；本份只冻结归零阈值 `SmoothingEpsilonM = 0.001`（归零阈值上界），不冻结「归零耗时」这类导出值 |
| `e > 1.0m` | 立刻吸附到权威姿态（过渡时长 `0ms`），并 `ErrorSmoother.Reset()` |

`ErrorSmoother` 只写渲染变换，不写回 `SnapshotView` 或任何模拟状态；因此它允许使用 `Mathf.Exp`（ADR-010 的运算子集约束只覆盖权威模拟与客户端预测）。

## 6. 验证

1. 分组自检：`& $env:AC_UNITY -batchmode -quit -nographics -projectPath client -executeMethod Ac.Tests.SuiteRegistry.RunAll -logFile -`（`AC_UNITY` 见 [C01](C01-Unity工程基线与构建.md) §5） → 期望含 `PASS view.tick_monotonic`、`PASS view.interp_100ms`、`PASS view.jitter_50ms`、`PASS view.hard_correct_1m` 与末行 `SELFTEST OK`；失败意味着快照应用或插值偏离 §5，画面会出现顿挫或抖动。
2. 单调性用例细节：喂入 tick 序列 `20, 19, 21, 21, 23` → 期望只应用 `20`、`21`、`23` 三帧，`invalidSnapshots` 与 `baselineMismatch` 均为 `0`；失败意味着旧帧会覆盖新帧，运动出现回退。
3. 插值用例细节：两帧间隔 50ms、`serverTimeMs` 相差 50ms，渲染时间取两者中点 → 期望位置为两端点的算术中点，误差不超过 `1e-9`；失败意味着 alpha 或关键帧环索引有误。
4. 视图只读：`Select-String -Path client/Assets/Scripts/View/*.cs -Pattern "SnapshotView\."` → 只出现 `ForEachVisible`、`GetLocalAuthority`、`GetServerTimeMs`、`AppliedTick`、`LocalPlayerId` 这些只读成员；失败意味着视图层在写回模拟状态，和解会与渲染互相污染。
5. 仓库质量门：`node tools/check-docs.mjs` 与 `node tools/check-assets.mjs` 全绿。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 快照到达抖动大导致画面顿挫 | 渲染位置一帧跳超过 1m | 检查插值延迟是否升到上限 250ms，必要时提升快照率而不是放宽抖动吸收 |
| 关键帧环索引错位 | 插值出现"回到过去"的姿态 | 用 §6 第 2 条的序列用例做回归，并核对环索引 `(newestIndex + 1 + i) % 6` |
| 视图层写回模拟状态 | 和解误差持续增大 | 按 §6 第 4 条扫描只读成员；任何写接口都从 `SnapshotView` 移除 |
| 实体进出导致视图抖动 | 实体在帧间闪烁 | 进场上限吸附、离场立刻回收；必要时对同 id 复用视图对象并重置姿态 |

回滚目标：回到 HANDOFF-C03（有传输与 codec、无视图层），删除本份新增的 `Sim/SnapshotView.cs`、`View/` 下三个文件与 `client/Assets/Tests/interpolation_test.cs`。
