## 1. 目标
一条命令产出可发给玩家的 Windows x64 IL2CPP 发布包（含 sha256 清单与可核对的版本行，协议版本字节见 [ADR-009](../../00-共识/ADR/ADR-009-UDP传输与协议重构.md)），客户端日志按天落盘并按大小轮转，验收时能用同一份 checklist 与服务端逐条走完"连接→大厅→对局→波次→结算→重连"并留下原始输出；`../../../docs/运维手册.md` 的客户端章节随之可用。

## 5. 冻结契约
构建产物命名与目录：

    OutputDir      = client/Builds/Windows/          // 不入库（client/.gitignore 已忽略）
    ExecutableName = AngryChen.exe                  // IL2CPP，x64
    DataDir        = AngryChen_Data/                // 随归档同目录
    ArchiveName    = ac-client-<semver>+<sha7>-win64.zip
    LatestPointer  = client/Builds/Windows/latest.txt   // 单行：归档名 + 空格 + sha256
    HashAlgorithm  = SHA256
    Backend        = IL2CPP；ScriptingBackend 只允许 IL2CPP 作为发布通道

版本号格式（客户端与服务器同构，仅前缀不同）：

| 项 | 值 |
|---|---|
| `SemanticVersion` | `2.0.0`（`MAJOR.MINOR.PATCH`，发布递增 PATCH，协议或玩法不兼容时递增 MINOR） |
| `ProtocolVersion` | `1`（等于 ADR-009 的 `version` 字节） |
| `BuildCommit` | `git rev-parse --short=7 HEAD` 的 7 位小写十六进制 |
| `BuildTimeUtc` | ISO8601 `yyyy-MM-ddTHH:mm:ssZ` |
| `VersionLine` | `ac-client 2.0.0+<sha7> proto=1` |
| 服务器对应行 | `ac-server <semver>+<sha7> proto=1`（由 S15 冻结） |

联调核对规则：`proto` 必须完全相等（不等即拒绝连接，见 ADR-009 的 `Disconnect(reason=version)`）；`MAJOR.MINOR` 必须相等；`PATCH` 与 `sha7` 允许不同，但必须把两侧版本行同时写进验收报告。

日志路径与轮转：

| 项 | 值 |
|---|---|
| 目录 | `Application.persistentDataPath/logs/`（Windows：`%USERPROFILE%\AppData\LocalLow\<company>\<product>\logs`） |
| 当前文件 | `client-<yyyyMMdd>.log`，UTF-8 无 BOM，每行一条 JSON：`{"ts","level","evt",...}` |
| 首行 | 固定为 `{"evt":"boot","version":"ac-client 2.0.0+<sha7> proto=1"}` |
| 轮转 | 单文件达 `8 * 1024 * 1024` 字节即改用 `client-<yyyyMMdd-HHmmss>.log`，同目录最多保留 5 份，超出删最旧 |
| 崩溃 | 未捕获异常写 `crash-<yyyyMMdd-HHmmss>.log`：版本行 + 异常栈 + 最近 200 行日志 |
| 级别 | `info` 常态；`debug` 仅在启动参数 `-debug` 时开启（等价 v1 的 `?debug=1`） |

验收判定标准（6 步 checklist，每步必须给出原始输出证据）：

| # | 步骤 | 操作 | 判定信号 |
|---|---|---|---|
| 1 | 连接 | 用 S15 的联调入口拉起 `ServerProcess`，客户端指向该地址 | ≤ 5s 进入大厅；日志首行版本行与服务器一致；无 `Disconnect(reason=version)` |
| 2 | 大厅 | 输入昵称（1–12 字节）与房间码加入 | 房间码 4 位合法；玩家行出现且 `ready=false`；4 人名额上限生效（第 5 人被拒） |
| 3 | 对局 | 全员准备开始 | 进入 `playing`；快照率 20Hz（或自适应降档 ≥ 10Hz）；`ping <= 120ms`；`lossPercent <= 5%` |
| 4 | 波次 | 打到第 3 波 | 波次计数递增；波间 20s 倒计时可见，全员准备后立即开波；羊形四类都出现过 |
| 5 | 结算 | 打完一局 | `Results` 榜与服务端 `matches.ndjson` 同一条记录一致（`waveReached`、`winnerTeam`、最高击杀、`durationMs` 四字段相等） |
| 6 | 重连 | 断开网络 10s 后恢复（另跑一次断网 40s） | 10s 断网：30s 宽限期内恢复同一 `pid` 与位置；40s 断网：名额释放，客户端回大厅并提示 |

## 6. 验证
    pwsh client/build.ps1 -Configuration Release -Target Win64 -Out client/Builds/Windows
    Get-FileHash client/Builds/Windows/*.zip -Algorithm SHA256
    Get-ChildItem (Join-Path $env:USERPROFILE "AppData\LocalLow\AngryChen\AngryChen\logs")

| 检查 | 命令 | 期望输出 | 失败意味着什么 |
|---|---|---|---|
| 构建 | 第一条命令 | 末行 `BUILD OK ac-client-2.0.0+<sha7>-win64.zip`，退出码 0 | IL2CPP 工具链缺失或 URP 包不全：先补 VS Build Tools 的"桌面 C++"工作负载，仍失败则记录为阻塞项 |
| 归档完整性 | 第二条命令 + `Get-Content client/Builds/Windows/latest.txt` | 哈希与 `latest.txt` 中的值逐字符相等 | 归档与清单不同源，分发会造成版本不可核对 |
| 日志落盘 | 第三条命令 | 存在 `client-<yyyyMMdd>.log`，且 `Get-Content <该文件> -TotalCount 1` 输出中的 `version` 与 `VersionInfo.VersionLine` 相等 | 日志没落盘或版本行没注入，第 5 步的验收不可复核 |
| 轮转 | 手动把当日日志补到 9 MiB 后重启客户端 | `logs/` 下最多 5 个 `client-*.log`，最旧的被删除 | 轮转未生效，长期运行会写满磁盘 |
| 联调 | 按 §5 checklist 走 6 步 | 6/6 通过，原始输出进 `docs/evidence/client-v2-acceptance.md` | 任一步失败即发布判定 FAIL，按步骤定位（连接→协议版本，对局→网络，结算→战绩接口） |
| 文档链 | `node tools/check-docs.mjs` | `OK：…` | 本文件或运维手册章节的链接/格式不合规 |

人工确认：把归档解压到另一台干净 Windows 机器，双击 `AngryChen.exe` 能进大厅；杀软未拦截 `UnityPlayer.dll`。

## 8. 风险与回滚
| 风险 | 触发信号 | 对策 |
|---|---|---|
| IL2CPP 工具链缺失导致构建失败 | `build.ps1` 报找不到 C++ 链接器 | 安装 VS Build Tools 的"使用 C++ 的桌面开发"工作负载；仍失败则用 Mono 后端出包并在验收报告标注 `backend=Mono`，本里程碑判定 FAIL |
| 客户端与服务器版本行不一致 | 第 1 步被 `Disconnect(reason=version)` 拒绝 | 两侧都从同一 commit 出包；发布前用 `latest.txt` 与服务器 `/metrics` 的版本行做一次机器比对 |
| 日志写满磁盘 | `logs/` 目录超过 5 个文件或单文件超 8 MiB | 轮转参数写死在 §5 并由人工步骤回归；磁盘剩余 < 1GB 时只写 `warn` 以上 |
| 验收环境与玩家环境不同（杀软/显卡驱动） | 干净机器上无法启动 | 验收报告记录测试机型号、驱动版本与杀软；启动失败时附带 `crash-*.log` |
| 重连语义与服务器宽限期不一致 | 第 6 步 10s 断网后未恢复同一 `pid` | 以服务器 30s 宽限期为准，客户端只负责重试节奏（1s、2s、4s，上限 8s）；差异写进报告并回查 S10/S15 契约 |

回滚目标：HANDOFF-C14。回滚动作 = 撤销 `client/build.ps1` 的发布开关（回到编辑器内运行），删除 `VersionInfo.cs` 与 `LogSink.cs` 的接线，保留 `docs/evidence/client-v2-acceptance.md` 的 FAIL 记录；玩家侧不受影响（无发布包）。
