## 5. 冻结契约

### 5.1 v2 包结构与读取顺序（承继服务端协议契约）
| 段 | 长度 | 读取顺序与判定 |
|---|---|---|
| 通用包头 | 8B | `version`(u8，必须为 `1`) → `type`(u8) → `flags`(u16) → `session`(u16) → `seq`(u16)，小端 |
| 可靠扩展头 | 12B，仅 `flags` 位 0 为 1 时 | `msgId`(u32) → `ackBase`(u32) → `ackBits`(u32) |
| 分片头 | 4B，仅 `flags` 位 1 为 1 时 | `fragId`(u16) → `fragIndex`(u8) → `fragCount`(u8) |
| 载荷 | 剩余字节 | 载荷首字节不再是 opcode，类型由通用包头的 `type` 承载 |

`type` 码表：`1` Hello、`2` HelloAck、`3` Resume、`4` Command、`5` Snapshot、`6` Event、`7` KeepAlive、`8` Disconnect、`9` Fragment。

### 5.2 载荷字段表（偏移相对载荷首字节，小端）
```csharp
// Command（type=4，14B）
// 0: seq u16 | 2: tick u32 | 6: moveX i8 | 7: moveY i8 | 8: yaw u16 | 10: pitch u16 | 12: buttons u8 (& 0x7f) | 13: switchTo u8 (0/1/2，非法回落 0)
// 轴 = round(axis * 127) 后钳制到 -127..127；buttons 位域 fire=1 sprint=2 jump=4 reload=8 interact=16 rage=32 switchWeapon=64
// Snapshot（type=5，固定 15B）：0: tick u32 | 4: serverTimeMs u32 | 8: lastAckedSeq u16 | 10: baselineTick u32 (0 = 全量) | 14: recordCount u8
// 15: 15 * recordCount 字节记录块；15 + 15n: removedCount u8；16 + 15n: 2 * removedCount 字节 EntityId u16，升序
// 记录（15B）：0: id u16 (1..1024) | 2: kindFlags u8 | 3: xCm i16 | 5: yCm i16 | 7: zCm i16 | 9: yawUnits u16 | 11: pitchUnits u16 | 13: hpRatioUnits u8 | 14: state u8
// kindFlags：kind 取位 0-1（player=0 sheep=1 projectile=2 pickup=3）；flags 取位 2-7（downed=1 rageMode=2 reloading=4 charging=8 fading=16 idle=32）
// Event（type=6）：tick u32 | count u8 | 事件块；每条首字节为 type，其后长度固定：playerHit 8B | sheepKilled 6B
// waveStart 4B | waveClear 6B | playerDowned 3B | reviveProgress 7B | reviveDone 5B | rageActivated 5B | matchEnded 7B
// 未知事件类型返回 UnknownEvent 并终止本帧解析；任何越界返回 Truncated
```

### 5.3 量化表（承继 ADR-009，不得改步长）
| 量 | 编码 | 常量与范围 |
|---|---|---|
| 位置 | int16 厘米 | `CentimeterPerMeter = 100`；范围 `-32768..32767` |
| 角度 | uint16 映射 `0..2π` | `AngleUnits = 65536` |
| 血量 | uint8 相对值 | `HpUnits = 255` |
| 输入轴 | int8 | `MoveAxisScale = 127`；输入轴上限 `1.0` |
| 俯仰限制 | 弧度 | `PitchLimitRad = 1.5707963267948966`（π/2） |
| 实体标识 | uint16 | `EntityId` 上限 `1024` |

### 5.4 取整与边界（跨语言逐位一致的前提）
| 规则 | 冻结实现 |
|---|---|
| 四舍五入 | 与 JS `Math.round` 等价：`(int)Math.Floor(x + 0.5)`；禁止 `Math.Round` 的银行家舍入 |
| 角度封装与量化 | `wrap(a) = a - Math.Floor(a / Tau) * Tau`，落在 `[0, 2π)`；`units = (int)RoundHalfUp(wrap(a) / Tau * 65536) % 65536`，`Tau = 6.283185307179586` |
| 轴与位置量化 | 轴先乘 127、位置先乘 100，再四舍五入，最后钳制到 `-127..127` 与 `-32768..32767` |
| 血量量化 | 先把 `hp/maxHp` 钳制到 `0..1`，再乘 255 后四舍五入 |
| 越界读取 | 任何越界立即返回 `Truncated`，不得补 0 后继续解析 |

### 5.5 随机数（承继 ADR-010）
| 项 | 冻结值 |
|---|---|
| 算法 | mulberry32：`a = (a + 0x6D2B79F5) >>> 0`；`t = a`；`t = (t ^ (t >>> 15)) * (t or 1)`；`t = t ^ (t + ((t ^ (t >>> 7)) * (t or 61)))`；返回 `((t ^ (t >>> 14)) >>> 0) / 4294967296`，乘法按 32 位截断 |
| 流 ID 与派生种子 | `ai = 1`、`spawn = 2`、`fx = 3`；`derived = (seed * 2654435761 + streamId) >>> 0`（32 位截断乘） |
| C# 实现 | 全程 `uint` 与 `unchecked` 运算；禁止 `System.Random` 与 `UnityEngine.Random` |

### 5.6 共享角度表
| 项 | 冻结值 |
|---|---|
| 文件与格式 | `docs/evidence/fixtures/trig-table.json`，形如 `{"scale":1073741824,"units":65536,"sin":[65536 项 int32],"atanUnits":[1025 项 int32],"asinUnits":[1025 项 int32]}`（三键由同一脚本输出，服务端 S02 §5.4 读同一份文件） |
| 生成与读取 | `node tools/export-trig-table.mjs`：`sin[k] = round(Math.sin(2πk/65536) * 1073741824)`（65536 项）、`atanUnits[i] = round(Math.atan(i/1024) / (2π) * 65536)`（1025 项）、`asinUnits[i] = round(Math.asin(i/1024) / (2π) * 65536)`（1025 项）；读取 `Sin(units) = sin[units mod 65536] * (1.0 / 1073741824.0)`，`Cos(units) = Sin(units + 16384)` |
| 失败行为 | 表缺失或长度不为 65536 时自检失败；运行期加载失败即抛错并拒绝进入对局，禁止回落到 `Math.Sin` |

### 5.7 拒绝原因与输出格式
```csharp
public enum DecodeFailure { None = 0, Truncated = 1, BadLength = 2, BadValue = 3, UnknownEvent = 4, VersionMismatch = 5 }
```
自检输出格式（逐字冻结）：`SELFTEST START cases=<n>`、`PASS <caseId>`、`FAIL <caseId> expected=<e> actual=<a>`、`SELFTEST OK cases=<n>`、`SELFTEST FAIL failures=<n> cases=<n>`。fixture 断言格式：通过打印 `[fixture] <name> OK`；不一致打印 `[fixture] <name> tick=<t> field=<path> expected=<v> actual=<v>`；目录缺失或为空打印 `[fixture] none` 且不算失败。

## 6. 验证

1. 角度表：`node tools/export-trig-table.mjs --check` → 期望 `trig-table.json OK (65536 entries)`；失败意味着表与 v1 `Math.sin` 不一致或文件被替换，跨语言角度函数会分叉。
2. 核心自检：`& "$env:ProgramFiles\Unity\Hub\Editor\6000.0.32f1\Editor\Unity.exe" -batchmode -quit -nographics -projectPath client -executeMethod Ac.Core.SelfTest.Run -logFile -` → 期望末行 `SELFTEST OK cases=<n>`；失败意味着量化、解码或随机数与 §5 有偏差，跨语言对拍不可能收敛。
3. 禁超越函数扫描：`Select-String -Path client/Assets/Scripts/Sim/*.cs, client/Assets/Scripts/Net/*.cs -Pattern "Math\.(Sin|Cos|Tan|Exp|Log|Pow|Atan|Hypot)"` → 期望无输出；失败意味着权威运算子集被破坏，预测会持续被硬纠正。
4. 分组自检：把第 2 条的 `-executeMethod` 换成 `Ac.Tests.SuiteRegistry.RunAll` → 期望含 `PASS codec.roundtrip`、`PASS quantize.edge`、`PASS rng.streams` 与末行 `SELFTEST OK`；失败意味着字段偏移、边界钳制或随机数位运算有误。
5. 仓库质量门：`node tools/check-docs.mjs` 与 `node tools/check-assets.mjs` 全绿。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 角度表体积拖累仓库 | `trig-table.json` 超过 1 MB | 改为 16384 项并线性插值，同步更新本文件 §5.6、生成脚本与两侧读取实现 |
| 取整语义不一致 | 位置往返误差出现 1cm 级偏移 | 统一改用 `RoundHalfUp`，并在自检里加 `-0.5`、`0.5`、`32767.5` 三个边界用例 |
| C# 位运算写成有符号 | 随机数输出为负或首值不符 | 全量改用 `uint` 与 `unchecked`，用 v1 实测值做门禁用例 |
| fixture 目录尚不存在 | 加载器抛异常 | 加载器对缺失目录打印 `[fixture] none` 并继续；§6 第 4 条不依赖外部文件 |

回滚目标：回到 HANDOFF-C01（工程可构建、无 `Sim` 与 `Net` 逻辑代码），删除本份新增的 `.cs` 文件、`tools/export-trig-table.mjs` 与 `docs/evidence/fixtures/trig-table.json`。
