## 5. 冻结契约

### 5.1 输入采样与命令上行
| 项 | 冻结值 |
|---|---|
| 上行速率 | `30` Hz（间隔 `33.333ms`，上一帧未到间隔不发） |
| 采样源 | 引擎内置 `Input`：移动轴用 `Input.GetAxisRaw("Horizontal"/"Vertical")`，按钮用 `Input.GetKey(KeyCode.*)`，鼠标增量用 `Input.GetAxisRaw("Mouse X"/"Mouse Y")`；**不引 Input System 包**（`Input.mousePosition` 不用于视角） |
| 积压合并 | 未确认命令超过 `2` 条时丢弃除最新外的未确认命令，只发最新一条，并计 `commandsMerged` |
| 按钮位域 | fire=1 sprint=2 jump=4 reload=8 interact=16 rage=32 switchWeapon=64 ready=128（8 位，写端 `& 0xff`；位序承继 v1，与协议字段同名同值；示例 `0x09` = fire\|reload） |
| 移动轴 | `moveX` 前后（W 为 `+1`、S 为 `-1`）；`moveY` 横移（A 为 `+1`、D 为 `-1`）；范围 `±1` |
| 视角 | 灵敏度倍率 = `0.001 rad/px * 设置值`，设置值范围 `0.2..3.0`；`yaw -= dx * scale`；`pitch -= dy * scale` 后钳制到 `±1.5707963267948966` |

命令载荷（type 4，固定 14 字节，紧随 8 字节通用包头；字段顺序逐字对齐 S03 §5.2 与 ADR-009）：

```text
moveX i8 @0、moveY i8 @1、yaw u16 @2、pitch u16 @4、buttons u8 @6、switchTo u8 @7、
seq u16 @8、clientTick u32 @10                 // 合计 14 字节
```

- 采样侧的输出类型是 `Ac.Core.InputIntent`（字段与本表逐条同名同域）：`Ac.Core` 按 `ContractSuite` 白名单引用不到 `Ac.Net`，载荷映射由 `CommandCodec.IntentToPayload` 承担。
- v2 由通用包头携带 `version`/`type`/`session`，载荷里**没有 opcode**（v1 的 15 字节含 opcode 且 `seq`/`clientTick` 在前）。
- `seq` u16 与包头 `seq` 同值；`clientTick` u32 = 客户端已知的最新权威 tick（v1 的 `Command.tick`）。

### 5.2 键位表
| 按键 | 作用 |
|---|---|
| `W`、`S`、`A`、`D` | 前后与横移轴 |
| `LeftShift`、`RightShift` | sprint 位 |
| `Space` | jump 位（只上报意图，不做垂直积分） |
| `Mouse0` | fire 位 |
| `R` | reload 位 |
| `E` | interact 位 |
| `F` | rage 位 |
| `Q` | switchWeapon 位 |
| `Escape` | 解锁指针（进入 UI 交互） |

### 5.3 局部步进语义（与服务端模拟内核逐条一致）
```csharp
// 步进入口消费 Ac.Sim.StepCommand（CommandCodec.ToStepCommand 由载荷映射，Ac.Sim 同样引用不到 Ac.Net）
// dtMs 恒为 50；speed = ((buttons & 2) != 0) ? 6.3 : 4.5
// units = QuantizeAngle(state.yaw); fwdX = TrigTable.Sin(units); fwdZ = TrigTable.Cos(units)
// rightX = fwdZ; rightZ = -fwdX;  vx = fwdX * moveX + rightX * moveY;  vz = fwdZ * moveX + rightZ * moveY
// m = vx * vx + vz * vz; if (m > 1) { k = 1.0 / Math.Sqrt(m); vx *= k; vz *= k; }
// vel = { x: vx * speed, y: 0, z: vz * speed }   // 不做垂直积分
// pos += vel * (dtMs / 1000.0)
// 碰撞一：谷仓 AABB 推出。若 pos.y < 5 且位于扩展盒内，比较 pushLeft/pushRight 与 pushBack/pushForward，取小者所在轴推到盒面并把该轴速度置 0
// 碰撞二：场地边界钳制 limit = 40 - 0.5 / 2 - 0.4；越界即夹到 limit 并把该轴速度置 0
```
移动参数冻结值：`moveSpeed = 4.5`、`sprintSpeed = 6.3`、`jumpSpeed = 4.8`、`gravity = 14`、玩家 `radius = 0.4`、`height = 1.7`、`eyeHeight = 1.6`、场地 `halfSize = 40`、围栏 `thickness = 0.5`、谷仓盒 `x ±4 / z ±4 / y 0..5`。

### 5.4 预测步进常量
| 常量 | 值 |
|---|---|
| `SubstepMs` | `50`（与服务端 tick 相同，禁用变长 dt） |
| `MaxSubstepsPerFrame` | `5`（一帧最多补 5 步，超出部分丢弃累加器余量） |
| 累加器上限 | `50ms`，即余量只保留一个子步，避免追帧雪崩 |
| 渲染外推 | `renderPos = state.pos + state.vel * (accumulatorMs / 1000.0)` |

### 5.5 相机与视图模型参数
| 项 | 冻结值 |
|---|---|
| 相机 FOV | 默认 `75`，可调范围 `60..100`（度） |
| 近裁与远裁 | `0.1` 与 `300`（米） |
| 相机位置 | 陈sir 位置加 `eyeHeight = 1.6`（沿世界 Y 轴） |
| 相机旋转 | `yaw` 与 `pitch` 直接取自本机命令姿态（弧度），俯仰限制 `±1.5707963267948966` |
| 视图模型 FOV | `62` 度；近裁 `0.01`、远裁 `12` |
| 视图模型挂点 | 相机局部坐标基座偏移 `(0.17, -0.19, -0.02)` |

### 5.6 指针锁定与失焦处理
- 点击画面：`Cursor.lockState = CursorLockMode.Locked` 且 `Cursor.visible = false`；锁定期间鼠标增量才计入视角。
- `Escape`：`Cursor.lockState = CursorLockMode.None` 且 `Cursor.visible = true`。
- `Application.focusChanged(false)`：清空全部按键位与移动轴，立即 `flush` 一条零意图命令，并保持不采样直到重新获得焦点；这条命令是防止"失焦后一直自动前进"的唯一手段。

## 6. 验证

1. 分组自检：`& $env:AC_UNITY -batchmode -quit -nographics -projectPath client -executeMethod Ac.Tests.SuiteRegistry.RunAll -logFile -`（`AC_UNITY` 见 [C01](C01-Unity工程基线与构建.md) §5） → 期望含 `PASS input.rate_30hz`、`PASS input.backlog_merge`、`PASS input.lock_flush`、`PASS camera.pitch_clamp` 与末行 `SELFTEST OK`；失败意味着输入上行或相机参数偏离 §5，本地手感与权威姿态会持续分歧。
2. 上行速率：以 1ms 步进模拟 1000ms 的 `InputSampler.Update(dtMs)` → 期望恰好发出 `30` 条命令（容差 ±1）；失败意味着节流间隔写错，命令带宽超预算。
3. 积压合并：待发队列上限 `MaxBacklog = 2`，连续 5 次采样都不取走 → 期望队列长度 `2`、`commandsMerged` 增加 `3`（每丢一条旧意图记一次），且队尾一定是最新采样（取尽后最后取出的 `seq` 等于采样器 `Seq`）；失败意味着积压会无限增长，`CommandChannel` 变成延迟队列。
   本行原写“5 条未确认后再采样一次 → 队列 1、+4”，与 §5.1 的“超过 2 条即丢弃”自相矛盾：上限既然是 2，队列永远到不了 5，那次采样也不可能一次丢 4 条。这里按 §5.1 的口径改写成可直接观测的期望值。
4. 确定性扫描：`Select-String -Path client/Assets/Scripts/Sim/LocalStep.cs, client/Assets/Scripts/Sim/Predictor.cs -Pattern "Math\.(Sin|Cos|Tan|Exp|Log|Pow|Atan)"` → 无输出；失败意味着预测使用了被禁的超越函数，会被权威快照周期性硬纠正。
5. 仓库质量门：`node tools/check-docs.mjs` 与 `node tools/check-assets.mjs` 全绿。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 与服务端步进语义漂移 | 预测位置与权威位置差持续增长 | 以本文件 §5.3 为单一来源逐条比对服务端实现，差异即改一侧；不引入容差比较 |
| 键位与鼠标增量读法不一致 | 视角灵敏度对不上设置值 | 只使用 `Input.GetAxisRaw` 的鼠标增量与 `GetKey` 的按键状态，禁用 `GetAxis` 的框架平滑 |
| 失焦后仍持续移动 | 切出窗口后角色自行前进 | 按 §5.6 清空位域并 flush 零意图命令；把该用例纳入门禁 |
| 追帧雪崩 | 一帧内子步数暴涨 | 累加器上限 50ms、每帧最多 5 步，超出即丢弃余量并计 `droppedSubsteps` |

回滚目标：回到 HANDOFF-C04（有快照应用与插值、无输入与预测），删除本份新增的 `Core/InputSampler.cs`、`Sim/LocalStep.cs`、`Sim/Predictor.cs`、`View/FpsCamera.cs`、`View/ViewModelAnchor.cs` 与 `client/Assets/Tests/InputCameraSuite.cs`。
