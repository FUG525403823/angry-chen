## 5. 冻结契约

    RoomCodeLength        = 4
    RoomCodeAlphabet      = "ABCDEFGHJKMNPQRSTUVWXYZ23456789"   // 31 字符，排除 I L O 0 1

    NameMinBytes          = 1
    NameMaxBytes          = 12

    ChatMaxLines          = 5
    ChatMinIntervalMs     = 500
    ChatWindowMs          = 5000

    IntermissionMinMs     = 5000
    LeaderboardLimit      = 10

    ResultsRetryMs        = 400
    ResultsRetryMax       = 3

房间码输入规则（按顺序应用，每步都有用例）：

| 步骤 | 规则 | 例 |
|---|---|---|
| 1 | 转大写 | `ab3k` → `AB3K` |
| 2 | 逐字符丢弃不在 `RoomCodeAlphabet` 内的字符（含空格、`I`/`L`/`O`/`0`/`1`、全角字符） | `a b0o` → `AB` |
| 3 | 截断到 4 位 | `ABCDEF` → `ABCD` |
| 4 | 加入判定：长度 == 4 且每位在表内；`"0000"` 只走"新建房间"按钮 | `"ABCD"` 合法，`"0000"` 非法加入码 |

阶段、界面与可见条件（唯一真相是服务器下发的 `MatchPhase`）：

| phase | 显示 | 可见条件 | 进入时动作 |
| `lobby`(0) | `Lobby` | 任意时刻处于大厅 | 聚焦房间码输入框；保留上次昵称与房间码 |
| `loading`(1) | 加载条 | 收到 `loading` 后 | 隐藏大厅与聊天；预热音频与场地 |
| `playing`(2) | HUD + `Chat` | 本地玩家已 `spawn` | 聊天可见、输入焦点归相机 |
| `intermission`(3) | `Intermission` | 收到 `intermission` 且 `wave >= 1` | 显示倒计时与波间武器选择 |
| `ended`(4) | `Results` | 收到 `matchEnded` | 播放 `victory`/`defeat`；拉取榜单 |

队伍与准备字段（服务器状态 → 客户端显示）：

| 字段 | 类型 | 显示条件 |
|---|---|---|
| `pid` | `int` | `pid <= 0` 的行整行不渲染 |
| `name` | `string` | 直接渲染，已按 12 字节截断 |
| `ready` | `bool` | 准备与否的文本与配色 |
| `weapon` | `int` | `0/1/2` → `手枪/步枪/霰弹枪` |
| `kills` | `int` | 大厅与波间显示"击杀 N"；结算显示明细列 |
| `downed` | `bool` | 波间显示"倒地"，优先于准备状态 |
| `hostId` | `int` | 等于 `min(pid)`；只有该 pid 看到"开始对局"按钮 |

波间规则：倒计时初值 `20000ms`，每帧按服务器 `intermissionMs` 覆盖本地显示（不做本地外推）；`intermissionMs > 15000` 时禁用跳过按钮；`ReadyCount == PlayerCount && PlayerCount > 0` 立即请求开波。
聊天规则：发送前截断到 64 字节（UTF-8，不切断多字节字符）；空文本提示"请输入内容"；`< 500ms` 内第二次发送丢弃并提示"发送过快"；5 秒窗口内第 6 条起丢弃并提示"过于频繁"；缓冲最多 5 行，超出丢最旧；服务器侧的聊天限流属 **v2 契约待 S03/S10 补**：v1 的 `maxMessagesPerSecond = 60` / `rateWindowMs = 1000` / `rateStrikesBeforeDisconnect = 3` 是 v1 常量，v2 尚未冻结聊天限流常量，不得把它当成既存契约。
结算榜排序与服务端战绩存储冻结的 top 排序（[S13](../server/S13-持久化日志指标与诊断报告.md) §5「排序一致性」）逐字一致：击杀降序 → `startedAtMs` 降序 → `matchId` 升序决胜；取前 `LeaderboardLimit`（10）条。记录与明细字段照抄 S13 §5 的冻结 schema（不得自创字段）：榜单行 `matchId / startedAtMs / durationMs / waveReached / winnerTeam / playerCount`，单局明细列 `name / kills / headshots / shotsFired / hits / revives / downs / aliveMs / leftMidMatch`。

## 8. 风险与回滚
| 风险 | 触发信号 | 对策 |
|---|---|---|
| 客户端显隐与服务器阶段错位 | 人工确认时界面卡在大厅/加载条 | 只在 `MatchPhase` 变化事件里切换界面；禁止用计时器猜阶段；补一条"重复同相位不重入"的用例 |
| 结算接口不可达或超时 | `Results` 三次重试后仍为空 | 用本局 `matchEnded` 载荷渲染摘要并标注"榜单暂不可用"；不阻塞返回大厅 |
| 输入法全角/组合字符导致房间码残缺 | 玩家反馈"码输入不进" | 归一步骤 2 已丢弃表外字符；再加一条全角用例；提示文案写明允许的字符集 |
| 本地限流与服务器限流双重触发 | 玩家被服务器断连（strike） | 客户端阈值必须严于服务器聊天限流（500ms/5 条按最严假设；服务器侧常量 **v2 契约待 S03/S10 补**）；发现相反情况立即改客户端 |

回滚目标：HANDOFF-C11。回滚动作 = 删除七个 UI 文件与 `client/Tests/lobby_flow_test.cs`，把启动流程指回 C10 的 HUD 直连会话；服务器侧不受影响。
