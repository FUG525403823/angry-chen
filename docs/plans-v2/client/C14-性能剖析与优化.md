## 1. 目标

## 5. 冻结契约
目标与预算（1920×1080、URP、`Application.targetFrameRate = 0`、VSync off、引擎版本见 C01）：

    FrameP95BudgetMs        = 20.0     // 240 帧窗口
    FrameP99BudgetMs        = 33.0
    ManagedAllocBudgetBytes = 0        // 稳态每帧；GC.GetTotalMemory(false) 差分判定
    Gc0DeltaBudget          = 0        // 采样区间内 GC.CollectionCount(0) 增量
    WarmupFrames            = 120
    SampleFrames            = 600
    Runs                    = 3        // 取中位
    DrawCallBudget          = 120
    TriangleBudget          = 180000
    ParticleBudget          = 256
    MaterialBudget          = 24
    StageBudgetMs           = input 0.5 / sync 1.5 / predict 1.0 / fx 4.0 / audio 1.0 / draw 10.0 / overlay 1.0 / hud 1.0

实例化与合批阈值（`Batching.cs`）：

| 判定 | 阈值 | 动作 |
|---|---|---|
| 同类羊可见数 | `>= 25` | 走 `Graphics.DrawMeshInstanced`，每批 ≤ 1023 实例 |
| 同类羊可见数 | `< 25` | 走 `Graphics.RenderMesh` 单绘 |
| 静态几何段（场地/围栏/看台） | 同材质 `>= 8` 个 mesh | 合并为一个合并网格（只读，运行时一次） |
| 剔除距离 | 羊 `60m`、场地 `80m` | 视锥剔除 + 距离剔除 |
| 画质档 | `0 低 / 1 中 / 2 高` | 阴影距离 `20/35/50m`、实例化上限 `256/512/1024`、粒子上限 `96/160/256` |

基准场景定义（`client/tools/frame-bench.ps1` 的场景名 `bench-4p60sheep`）：

| 项 | 值 |
|---|---|
| 玩家 | 4 个（1 个本机视角 + 3 个机器人按 30Hz 发命令） |
| 羊 | 60 只（`grunt/ram/elite/king` 按 `9:3:2:1` 混合，含 `questionBolt` 投射物） |
| 特效 | 满特效：枪口火焰、曳光、粒子上限 256、字幕 3 行、音频 24 音源 |
| 服务器 | 本地 `ServerProcess`，tick 20Hz、快照率自适应初始 20Hz |
| 时长 | 预热 120 帧 + 采样 600 帧（约 10 秒 @60fps），重复 3 次 |
| 采样点 | 每帧 `End()` 后取 8 段耗时 + 帧间隔 + 分配增量 |

测量方法（必须照做，否则数值不可比）：

1. 图形设备：`Unity.exe -batchmode -projectPath client -executeMethod Ac.Bench.FrameBench.Run` —— **不得**加 `-nographics`（软件光栅化的帧时间不具代表性）。
2. 分配：预热后与采样后各取一次 `GC.GetTotalMemory(false)`，差值除以采样帧数记为 `managedAllocBytesPerFrame`；同区间读 `GC.CollectionCount(0)`。
3. 统计：每段与帧间隔各自排序后取下标 `ceil(0.95 * n) - 1`（与 `../../../tools/bench-sim.mjs` 的分位口径一致）。
4. 结论：三次运行取中位，全部满足阈值才判 `PASS`。

报告字段（`docs/evidence/client-v2-frame.md` 必备，缺一即判 FAIL）：`machine`、`cpu`、`gpu`、`driver`、`unityVersion`、`resolution`、`qualityTier`、`scene`、`warmupFrames`、`sampleFrames`、`runs`、`frameP95Ms`、`frameP99Ms`、`managedAllocBytesPerFrame`、`gc0Delta`、`drawCalls`、`triangles`、`particles`、`materials`、`stageP95`（8 段）、`commit`、`verdict`。

## 8. 风险与回滚
| 风险 | 触发信号 | 对策 |
|---|---|---|
| 无图形设备的批处理读数失真 | 脚本报 `no graphics device`，或 P95 异常低（< 5ms） | 只用 `-batchmode` 且带真实图形设备；报告写入 GPU 与驱动版本，禁止用 `-nographics` 数值判 PASS |
| 基准机与被测机不同导致结论不可移植 | 同一 commit 两机 P95 相差 > 30% | 报告必须记 `cpu/gpu/driver`；跨机只比趋势，达标判定同机同场景 |
| 优化引入不确定性（超越函数、fast-math 思路） | 预测出现周期性硬纠正 | 遵守 ADR-010 运算子集；需要角度函数改用共享查表 |
| 剖析器自身成为开销 | 开关面板时 `hud`/`overlay` 段 P95 变化 > 1ms | 采样只在帧末一次；面板不可见时不拼字符串 |
| 合批阈值牵动视觉质量 | 羊群漏绘或位置抖动 | 阈值只作性能开关，不改实体位置；视觉回归走 C08 的用例 |

回滚目标：HANDOFF-C13。回滚动作 = `client/tools/frame-bench.ps1` 判定退化为仅记录（退出码恒 0），`Batching.cs` 固定走单绘路径，`FrameProfiler` 保留；性能结论降级为"未达标并记录"，不影响可玩性。
