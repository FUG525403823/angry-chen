# ADR-017：角度表随包分发（Resources 资产 + 镜像门禁）

- 状态：已裁决（实现随本 ADR 一起落地）
- 日期：2026-09-29
- 影响面：`client/Assets/Resources/trig-table.json`（新增，TextAsset 镜像）、
  `client/Assets/Scripts/Sim/TrigTable.cs`（`Install`/`IsInstalled`/`Reset`/`ResourceName`）、
  `client/Assets/Scripts/Boot/GameBootstrap.cs`（`InstallTrigTable`）、
  `client/Assets/Tests/QuantizeSuite.cs`（用例 `quantize.trig_table_packaged`）、
  `tools/export-trig-table.mjs`（写镜像 + `--check` 双侧校验）、`docs/运维手册.md`
- 相关：C02 §5.6（共享角度表）、C15（打包发布）、ADR-010（跨语言确定性）、
  `docs/evidence/client-v2-remaining-work.md`（A15）、S02 §5.4（服务端侧的同一份表）

## 背景与证据

C02 §5.6 冻结了"两侧共用 `docs/evidence/fixtures/trig-table.json`"这条单一来源，并把
**构建产物的打包**明确留给 C15（`TrigTable.cs` 原注释："构建产物的打包由 C15 决定"）。C15 交付了出包链路，
但这条留白没有被补上：`RepoPaths` 是**从工程根往上找仓库目录**的定位器，而**出包 player 里没有仓库根**。

实跑证据（2026-09-29，Windows x64 Mono 包，`client/Build/Windows64/ac-client-0.1.0+0d2bc6f-win64.zip`）：

```
Ac.Boot: 连接 43.143.120.65:8788（来源 server.txt）
TrigTableException: 角度表缺失：C:\Users\ADMINI~1\AppData\Local\Temp\docs\evidence\fixtures\trig-table.json
  at Ac.Sim.TrigTable.LoadFromFile (System.String path)
  at Ac.Sim.TrigTable.get_Shared ()
  at Ac.Sim.LocalStep.StepLocalPlayer (...)
  at Ac.Sim.Predictor.StepWith (...)
  at Ac.Boot.GameLoop.Frame (...)   ← 每帧一条，Player.log 15 秒涨到 81 KB
```

即：**出包版整条本地预测链路每帧抛异常**。编辑器里看不见（工程根上一级就是仓库根，`RepoPaths` 命中），
批处理自检也看不见（同样在仓库里跑），六步联调同样看不见（联调跑的是编辑器）。这与 A11/A12 是同一类
"只有真机出包才暴露"的缺陷。

## 裁决

1. **随包形态**：`docs/evidence/fixtures/trig-table.json` 作为 Unity `TextAsset` 复制到
   `client/Assets/Resources/trig-table.json`（**资产名 `trig-table`**，`TrigTable.ResourceName` 是唯一字面量）。
   `Resources` 是引擎自带机制：不需要 `StreamingAssets` 路径处理、不依赖工作目录、IL2CPP 下同样有效。
2. **加载责任分层**：`Ac.Sim` 不引 UnityEngine（引擎无关的确定性内核），所以由 **Boot 层**在装配时读取资产
   并把文本喂进 `TrigTable.Install(string)`：
   - `GameBootstrap.Start()` 第一件事是 `InstallTrigTable()`（早于任何 `Frame()`）；
   - 拿不到资产时记一条 `error` 并保持未装载（此时 `Shared` 退回仓库路径 —— 只有编辑器/自检走得到）。
3. **单一来源不许分叉**：仓库那份仍是唯一来源；镜像由生成器写、由门禁比：
   - `node tools/export-trig-table.mjs` 同时写 `docs/evidence/fixtures/trig-table.json` 与
     `client/Assets/Resources/trig-table.json`（同一次 `JSON.stringify`，逐字节相同）；
   - `node tools/export-trig-table.mjs --check` 除原有三张表 CRC 外，**再比镜像逐字节相等**，不一致即 `exit 1`；
   - 客户端用例 `quantize.trig_table_packaged` 在运行期再比一次（`TextAsset.text` == 仓库文件文本），
     并断言 `InstallTrigTable()` 能把"未装载"状态装成表（值级锚点 `SinRaw/AtanUnitsRaw/AsinUnitsRaw`）。
   三道里任意一道都能独立抓到"只改了一侧"。
4. **不动线上语义**：协议、量化、表内容一个字没改；改的只是"表从哪儿读进来"。

## 回归判据

- `node tools/export-trig-table.mjs --check` → 退出码 0，且打印 `镜像 OK`；
  把镜像改坏一个字节 → 退出码 1（实测）。
- `SELFTEST`：新增 `quantize.trig_table_packaged`（193 → 194 例），全绿。
- 真机复核：重新出包后同一个 `server.txt` 场景下 `Player.log` **0 条 `TrigTableException`**、
  整份日志 1.1 KB（修前 81 KB / 每帧一条）。
