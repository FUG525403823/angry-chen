# ADR-001 技术栈与仓库形态

- 状态：已接受（M0 前）
- 决策者：项目负责人
- 生效范围：全仓库

## 背景与约束

1. 单人开发、单机 Windows（`D:\projects\tmp\angry-chen`），环境已核实：Node 24.14.1、pnpm 11.22.0、npm 11.11.0、16 核；**无 docker、无 go、无 rustc**。
2. 目标形态是"联机 PVE 射击"，需要：权威服务器、客户端预测、多人同局、快速迭代。
3. **零外部素材**：不允许下载模型/贴图/音频；所有视听内容程序化生成。
4. 需要可自动化回归（本机没有 Chrome、没有 Playwright 浏览器，只有 Edge）。

## 选项

| 选项 | 说明 |
|---|---|
| A | TypeScript 全栈单仓：`shared` 纯逻辑 + Node 权威服务器（`ws`）+ 浏览器 three.js 客户端 |
| B | Unity / Godot + 内置 Netcode |
| C | Phaser 2D + Colyseus 框架 |
| D | 自研 C++ / Rust 权威服务器 + 客户端 |

## 决策

**采用方案 A。** 具体锁定：

| 项 | 选择 | 版本（实测可得） |
|---|---|---|
| 运行时 | Node.js | 24.14.1 |
| 包管理 | pnpm workspace | 11.22.0 |
| 语言 | TypeScript（strict + `erasableSyntaxOnly` + `verbatimModuleSyntax`） | **5.9.3** |
| 服务端执行 | `tsx`（dev: `tsx watch`） | 4.23.13 |
| 客户端构建 | Vite | 8.3.0 |
| 渲染 | three.js（仅 client） | 0.186.0 |
| 网络 | `ws` | 8.21.3 |
| 测试 | vitest + @vitest/coverage-v8 | 5.0.1 |
| 静态检查 | eslint + typescript-eslint + prettier | 10.11.0 / 8.70.0 / 3.9.8 |

仓库形态：pnpm workspace，三包 `@ac/shared`、`@ac/server`、`@ac/client` + `tools/`，详见 [工程约定](../工程约定.md#1-仓库形态)。

## 关键实测依据（不是推断）

1. **为什么 TypeScript 锁 5.9.3 而不用最新的 7.0.2**：`typescript-eslint@8.70.0` 的 peerDependencies 是 `typescript: ">=4.8.4 <6.1.0"`（`npm view typescript-eslint peerDependencies` 实测）。用 7.x 会失去类型感知 lint，违背质量门设计。
2. **为什么服务端用 tsx 而不是 Node 原生类型剥离**：实测 `node packages/client/... .ts` 解析 workspace 软链时抛 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`——Node 明确不支持剥离 `node_modules` 下的类型（软链 `--preserve-symlinks` 亦然）；同一场景下 `tsx` 正常运行并输出正确结果。因此服务端零构建产物的前提是引入 `tsx`。
3. **为什么必须开 `erasableSyntaxOnly`**：实测 strip-only 模式对 `enum` 与构造器参数属性抛 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。开启该编译项可让"代码永远可被剥离"成为编译期约束，保留将来去掉 `tsx` 的自由。
4. **为什么客户端直接消费 shared 源码**（`exports: { ".": "./src/index.ts" }`）：Vite / vitest 均能解析 `.ts` 入口，改 `shared` 即触发客户端 HMR，且避免"服务端用 dist、客户端用 src"的双份语义。

## 被否决方案的理由

- **B（Unity/Godot）**：本机无引擎工具链，编辑器内逻辑无法在本仓库以纯文本方式增量施工；无头自动化与文档化施工成本高；与"线性十份文档即可完成"的目标冲突。
- **C（Phaser + Colyseus）**：2D 俯视削弱"枪战"的空间感与问界额标的可读性；Colyseus 强加房间/状态同步框架，反而遮蔽本项目要显式冻结的协议与预测逻辑。
- **D（C++/Rust 服务端）**：本机无 rustc/go 工具链，需先解决交叉编译；而 4 人 + 60 羊 @20Hz 的负载远未到需要原生语言的量级。
- **React / Vue / 状态管理库**：无 SSR 与复杂表单需求，HUD 与大厅用原生 DOM + CSS 足够，省一个框架依赖与其升级负担。
- **WebRTC / WebTransport**：需要额外信令或 Node 端不可用的服务端实现；以 `Transport` 缝预留，见 [ADR-002](ADR-002-网络模型与协议.md)。

## 后果

- 正面：服务端无构建产物，改一行即重启；同一份 `stepWorld` 被服务器、客户端预测、无头机器人共用，可测性极强。
- 负面：`tsx` 成为运行时依赖（而非纯开发依赖）；`.ts` 扩展名导入会出现在 shared/server 的相对导入里，需要团队纪律（已写入工程约定）。

## 复查触发条件

- `typescript-eslint` 放开对 TypeScript 7 的支持，且 TS 7 在本仓库 `pnpm check` 全绿。
- Node 放开了对 `node_modules` 下 `.ts` 的类型剥离。
- 需要超过 8 人同局或需要 UDP 语义时，重新评估网络与运行时选型。
