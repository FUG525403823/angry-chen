# ADR-008 服务端语言与客户端引擎变更

- 状态：已接受（v2 起点）
- 取代：[ADR-001](ADR-001-技术栈与仓库形态.md)（技术栈与仓库形态）
- 生效范围：全仓库——`server/`、`client/`、`docs/plans-v2/`、质量门

## 背景与约束

1. 现役实现（TypeScript 全栈，ADR-001）在**性能上限**与**游玩体验上限**两方面都触顶：服务端单核承担模拟 + 编码 + 房间调度，客户端受浏览器 WebGL 与 GC 抖动约束；这正落在 ADR-001 自己写下的复查触发条件里（"需要超过 8 人同局或需要 UDP 语义时，重新评估网络与运行时选型"）。
2. 目标形态不变：联机 PVE 射击，服务器权威 + 客户端预测 + 多人同局；玩法与术语不变（见 [CONTEXT](../CONTEXT.md)）。
3. v2 起点本机实测：**PATH 上没有 `cmake`/`ninja`/`cl`**（但 VS 2026 自带 CMake 4.2.3 + Ninja 1.12.1 与 MSVC 14.50，可由 `vswhere` 定位，无需额外安装）、**没有 Unity 国际版编辑器/Hub**；有 **团结引擎 Tuanjie Cowork 2.1.0**（Hub，`D:\tools\unity\Tuanjie Cowork\hub\tuanjie.exe`）、mingw `g++ 15.2.0`、Windows SDK 10.0.26100、`dotnet`、`python`、`node`、**Windows PowerShell 5.1（无 `pwsh` 7）**；`win32 x64`，C: 剩余 53.4GB、D: 剩余 1307.5GB。
4. 硬约束延续：**零外部素材**（[ADR-003](ADR-003-美术素材与问界标识策略.md)）；文档线性链驱动施工（[工程约定](../工程约定.md)）。

## 选项

| 选项 | 说明 |
|---|---|
| A（现役） | TypeScript 全栈：shared 纯逻辑 + Node 服务器 + 浏览器 three.js 客户端 |
| B | **C++ 权威服务器 + Unity 客户端** |
| C | C++ 服务器 + 自研/其它引擎客户端（Godot、自绘） |
| D | 只把服务器换成 C++，客户端维持浏览器 three.js |

## 决策

**采用 B。** 锁定如下（未写死补丁号的项，由对应链的第一份计划固化并回写本表）：

| 项 | 选择 | 说明 |
|---|---|---|
| 服务端语言 | **C++20** | 只用标准库；新增第三方依赖必须先写 ADR |
| 服务端构建 | CMake ≥3.28 + Ninja，或 MSVC 19.4x；**mingw g++ 15.2 为当前可用兜底** | 由 [S01](../../plans-v2/server/S01-C++工程基线与构建质量门.md) 固化实际链路 |
| 客户端引擎 | **团结引擎（Tuanjie，Unity 2022.3 线）+ 编辑器随附 URP** | 国内网络条件下 Unity 国际版不可得，故选国产同源分支。当前目标版本 `2022.3.62t16`（安装器已就位）；具体补丁号与安装路径由 [C01](../../plans-v2/client/C01-Unity工程基线与构建.md) 写进 `ProjectSettings/ProjectVersion.txt` 与 `$env:AC_UNITY`，**若实测与本表不同则回写本表**。已知代价：日后若迁回 Unity 6，需要迁移 URP 14→17 的材质与 Renderer 资产 |
| 客户端语言 | C#（引擎提供版本，2022.3 线 → C# 9 / .NET Standard 2.1） | 不开 `unsafe`，不引第三方包 |
| 输入 | 引擎内置 Input + `Cursor.lockState` | 不引入 Input System 包 |
| UI 文本 | 系统字体（`Font.CreateDynamicFontFromOSFont`） | 不导入 TMP Essentials 等素材包（守住零外部素材） |
| 网络 | **自研 UDP 可靠性层**，规范见 [ADR-009](ADR-009-UDP传输与协议重构.md) | 双端各自实现同一份冻结规范，不引 Unity Transport |
| 确定性 | 跨语言确定性规则见 [ADR-010](ADR-010-跨语言确定性与对拍.md) | 由对拍向量机器验证 |
| 仓库形态 | `server/`（C++） + `client/`（团结引擎工程） + `tools/`（Node 门禁脚本） + `docs/`（共识、需求、双链计划）；v1 的 `packages/**`、Node 工具链与 v1 文档已移出仓库，冻结副本在 `D:\projects\tmp\angry-chen-bak` | 见 [工程约定](../工程约定.md) §1 |
| 计划链 | 两端**各自线性**：S01→S15 与 C01→C15，共 30 份，见 [plans-v2 索引](../../plans-v2/README.md) | 原 P01–P10 与 O01–O10 已移出仓库 |

## 被否决方案的理由

- **A（维持 TS 全栈）**：性能与表现力上限是本次重构的动因本身；浏览器无法发裸 UDP，快照/命中补偿只能靠 TCP 手法缓解（ADR-002 §"TCP 队头阻塞"）。
- **C（C++ + 非 Unity 系客户端）**：自绘客户端要重写渲染、输入、音频、UI 四层，工期与风险远高于用现成引擎；Godot 需要另一套工具链与素材策略，本机同样未安装。
- **D（C++ 服务器 + 浏览器客户端）**：改造量最小，但游玩体验的上限仍被浏览器/WebGL 与 GC 锁死，等于只解决了一半动因。

## 实测依据与代价（诚实列账）

1. 工具链来源：CMake/Ninja/MSVC 全部随 VS 2026 已装（`vswhere` 定位，不额外安装），mingw `g++` 为兜底；引擎用**已在本机的团结引擎**（Tuanjie Cowork + 2022.3.62t16），需要的是**重新激活许可**（旧许可文件随旧安装被删除）。因此 S01/C01 的入口条件写成"定位/验证"而不是"下载安装"，并保留了失败回退路径。
2. CI：本仓库当前**没有任何 CI 平台接入**（`.github/` 目录在 v2 起点不存在，`.github/workflows/ci.yml` 由 [S01](../../plans-v2/server/S01-C++工程基线与构建质量门.md)【新建】，含 quality/server/server-perf 三个 job）。引擎构建需要许可激活，**不接入 CI**；客户端侧以本地可复现的构建脚本 + 验收报告为准（C15）。C++ 侧可接入 Linux CI（S01/S14）。
3. 新增风险：**跨语言浮点确定性**（C++ 与 C# 两套实现必须逐位一致）。对策是 ADR-010 的受限运算子集 + 从旧 TS 模拟导出的对拍向量（S07/C02/C06）。
4. 失去的东西：同一份 `stepWorld` 被服务器/客户端预测/机器人三处共用的"同源模拟"红利。v2 以**对拍向量**替代"同源"，代价是每次契约变更要同步两侧并重跑对拍。

## 后果

- 正面：模拟与编码可做到零 GC、可控内存布局、可上 UDP、可用原生剖析器定位帧时间；客户端可上真实 GPU 特性与实例化。
- 负面：双语言双工程，跨语言一致性靠对拍维持；旧 TS 实现转为**冻结对照**，但已移出本仓库（副本 `D:\projects\tmp\angry-chen-bak` 含 `node_modules`，仍可跑旧栈做基准对照）。

## 复查触发条件

- 跨语言对拍在 [S07](../../plans-v2/server/S07-旧TS模拟对拍.md) 无法收敛（两次会话内仍非逐位一致）→ 决策回退：权威模拟仍只在 C++，客户端改为**纯插值不预测**，并以此修订 ADR-009 的通道预算。
- 引擎大版本升级（含从团结引擎 2022.3 线迁到 Unity 6）、C++ 标准升级、或需要引入第三方库 → 先写新 ADR。
