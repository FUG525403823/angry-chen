# ADR-016：产品侧连接参数入口与默认端口（出包版怎么指向服务器）

- 状态：已裁决（实现随本 ADR 一起落地）
- 日期：2026-09-29
- 影响面：`client/Assets/Scripts/Boot/GameBootstrap.cs`、`client/Assets/Tests/BootSuite.cs`
  （用例 `boot.server_config`）、`client/server.txt.example`（分发模板）、`client/.gitignore`、
  `docs/运维手册.md`（客户端段）、`docs/evidence/client-v2-remaining-work.md`（A13-3 收口）
- 相关：ADR-014 §后果-2（`-server` 在出包版不可用）、ADR-009（握手时序）、
  `server/README.md` §18.2/§18.7（`AC_UDP_PORT=8788`、`AC_HTTP_PORT=8787`）、
  C03 §5.5（握手）、C15（打包与联合验收）、`docs/evidence/server-v2-acceptance.md` §14（生产部署）

## 背景与证据

1. **出包版没有可用的命令行入口**（ADR-014 §后果-2，当时如实登记为"仍未做"）：Unity 播放器自己解析
   `-server`（headless server 开关），参数不合法时还会中止进程，于是 `GameBootstrap` 的 `-server` 分支在
   player 里**形同不存在**；产品侧当时只剩环境变量 `AC_SERVER` 一条通路 —— 而"让玩家设环境变量"不是产品形态。
2. **默认端口指向了错误的那一面**：`GameBootstrap.DefaultServerPort` 是 **8787**，而按
   `server/README.md` §18.2，8787 是**HTTP 诊断面（TCP）**、游戏面是 **UDP 8788**（`AC_UDP_PORT`）。
   客户端拿 8787 去发 UDP `Hello`，服务端那个 UDP 端口根本不存在 ⇒ **永远收不到 `HelloAck`**，
   表现就是"出包版连不上服务器"。这条从未被暴露，因为：
   - 编辑器与批处理一律 `ShouldConnect=false`（C03/C15 的测试纪律，用例 `boot.server_config` 钉着）；
   - 六步联合验收每次显式传 `AC_JOINT_UDP=127.0.0.1:8788`（`client/tools/joint-acceptance.ps1:89`）；
   - 机器人 `ac_bot` 有自己的 `--port` 默认值（8788），与客户端默认值无关。
3. 生产部署（2026-09-29，`43.143.120.65`）之后，"客户端怎么填地址"成了产品侧唯一挡在前面的问题：
   公开可达的是 `UDP:8788`（待安全组放行，见 `server-v2-acceptance.md` §14.6）与 `TCP:80`（反代）。

## 裁决

1. **解析顺序（第一个非空的赢）**：

   | 顺序 | 来源 | 形态 | 谁在用 |
   |---|---|---|---|
   | 1 | `-acserver host:port` | 命令行 | 产品侧（可写命令行的高级用户/启动器） |
   | 2 | `AC_SERVER` | 环境变量 | 服务器运维、批处理、CI |
   | 3 | `server.txt` | **与可执行文件同级**的第一行有效 `host:port` | 产品侧默认形态（解压即用） |
   | 4 | `-server host:port` | 命令行 | 编辑器/历史写法（修复不改它） |
   | 5 | `127.0.0.1:8788` | 默认值 | 本机起服务器的开发形态 |

2. **默认端口 8787 → 8788**（游戏面 UDP）。8787 只承载 HTTP 诊断面（`/health`、`/metrics`、`/api/*`），
   客户端**不连**它（那是给运维与看板用的）。
3. **`server.txt` 的读法**：与 exe 同级（出包版取 `Application.dataPath` 的父目录，即解压目录）；
   空行与 `#` 注释跳过；开头的 UTF-8 BOM 剥掉（Windows 记事本"UTF-8"会写 BOM）；读不到/读坏了当作"没配"，
   进程照常起来（不许因为一个坏配置文件起不来）。
4. **fail-closed 不回退**：第一个**非空**候选解析失败 ⇒ 本进程离线（`ServerHost=null`），
   **不许**退到后面的候选或默认值 —— 沿用 C03 既有的"不许悄悄连默认端口"语义。
5. **可观测**：`GameBootstrap.ServerSource` 记录生效来源（`-acserver`/`AC_SERVER`/`server.txt`/`-server`/`default`），
   真连之前打一条 `Debug.Log`（每次装配一条，不在帧路径上）。
6. **线上语义一律不动**：不碰 wire 格式、量化、握手时序与任何 `server/**` 代码；本 ADR 只改客户端"连哪儿"。

## 回归判据

用例 `boot.server_config`（`client/Assets/Tests/BootSuite.cs`）新增断言，逐条钉住上面的裁决：

- 默认端口 `== 8788` 且 `!= 8787`（后者带"HTTP 面"理由的说明，值一改就红）；
- `-acserver` / `AC_SERVER` / `server.txt` / `-server` 的优先级四条各一断言；
- 四条都空 ⇒ `127.0.0.1:8788` 且 `Source == "default"`；
- 第一个非空候选解析失败 ⇒ `IsValid=false` 且 `Host=null`（不许回退）；
- `server.txt` 的 BOM / CRLF / 注释 / 两侧空白四种写法；
- `ProductServerArgument != ServerArgument`（与 Unity 自用的 `-server` 不许撞名）。

> 判别力证据（本轮）：把 `DefaultServerPort == 8788` 那条临时改成 `== 8787` 后 `SELFTEST` 变红（`FAIL boot.server_config`），
> 回滚后 `SELFTEST OK cases=193` —— 证明新增断言确实在执行，且整体零回归（基线同为 193）。

## 分发与运维

`client/server.txt.example` 是随仓库给出的模板（不是可执行配置）：发版时把它复制成 `server.txt` 放在
**`angry-chen.exe` 同级**，把 `host:port` 改成目标服务器（例：`43.143.120.65:8788`）。
玩家侧只需改这一行 —— 不需要环境变量、不需要命令行参数。
