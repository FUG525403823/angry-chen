# ADR-015：鼠标视角两轴的符号（本仓 `pitch` 以抬头为正）

- 状态：已裁决（实现随本 ADR 一起落地）
- 日期：2026-09-29
- 影响面：`client/Assets/Scripts/Core/InputSampler.cs`（`Sample()`）、
  `client/Assets/Tests/InputCameraSuite.cs`（`camera.pitch_clamp`）、
  `docs/plans-v2/client/C05-输入相机与本地移动预测.md` §5.5 的"视角"行、
  `docs/evidence/client-v2-remaining-work.md`
- 相关：C05 §5.5/§5.6、S02 §5.4（`yawPitchToDirection`）、S03 §5.2、S06 §5.2、ADR-009（量化）

## 背景与证据

C05 §5.5 冻结的视角式子是：

```
yaw -= dx * scale;    pitch -= dy * scale;      // 灵敏度倍率 = 0.001 rad/px * 设置值
```

它是从经典 Unity 第一人称片段（`rotationX -= mouseY`）抄来的，而那句话成立的语境是
**"pitch 以低头为正"**（那里相机写的是 `Quaternion.Euler(pitch, yaw, 0)`）。本仓的 pitch 语义相反，
三处独立证据一致：

| 位置 | 事实 |
|---|---|
| `FpsCamera` / `PresentationLayer.SyncCamera()` | 相机写 `Quaternion.Euler(-pitch, yaw, 0)` ⇒ `forward.y = sin(pitch)` ⇒ **pitch > 0 = 抬头** |
| `server/src/core/math.hpp` `yawPitchToDirection` | 返回 `(cosPitch·sin yaw, sin(pitch), cosPitch·cos yaw)` ⇒ **pitch > 0 = 抬头**，与客户端同义 |
| `client/ProjectSettings/InputManager.asset` | `Mouse X`/`Mouse Y` 均 `type: 1, invert: 0` ⇒ 引擎侧**右移为正、上移为正** |

于是 `-=` 在本仓语义下变成**双重取反**：鼠标右移 ⇒ `yaw` 减小 ⇒ 视角左转；鼠标上移 ⇒ `pitch` 减小 ⇒ 视角下压。
两条都反，实跑表现就是"视角很奇怪、反过来、像没法操作"（用户实跑反馈）。

## 裁决

1. `InputSampler.Sample()` 改为 `yaw += dx * scale;` `pitch += dy * scale;`；C05 §5.5 的式子同步更正。
2. **线上语义一律不动**：`yaw` 前向仍是 `(sin yaw, 0, cos yaw)`（S02/S05/S06），`pitch` 仍是"抬头为正"
   （`yawPitchToDirection`），命令载荷 `intent.Pitch = QuantizeRadians(PitchRad)` 原样 ⇒ **无协议影响**，
   两侧对拍、门禁场景与联调脚本不受影响。
3. 判据 = "鼠标方向即视角方向"：右移右转、上移上抬、下移撞 `-π/2`、上移撞 `+π/2`（钳制仍按 C05 §5.5）。

## 回归判据

`camera.pitch_clamp` 用例按本 ADR 反向修正注入方向，并补水平轴断言：右移 ⇒ `YawRad > 0`、左移 ⇒ `YawRad < 0`。

> 本轮按要求不打开 Unity：用例改动**未经执行**（`SELFTEST` 未重跑），如实记在证据文件里。
