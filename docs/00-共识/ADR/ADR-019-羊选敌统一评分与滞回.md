# ADR-019：羊选敌统一评分与滞回

- 状态：已批准（2026-10-26）；人类明确选择“版本化更新受影响向量（推荐）”。批准行为变更不等同于全量验收通过。
- 影响面：服务端 `selectTarget`、AI 回归测试；不改变线协议或客户端。

## 背景与决策

旧目标只按 `aggro * targetSwitchRatio` 续期，而候选目标按 `aggro + 1/(1+distance)` 打分。两个静止、零仇恨玩家便会在连续 tick 交替成为目标；真实 `selectTarget` 的 20 tick 回归已在旧实现失败。

以下新规则仅用于 `playerCount > 1`。零／单玩家保持旧数值路径：有效旧目标不因超视距或移出列表而丢失；目标失效时 ID 归零但缓存距离保留；仅在视距内访问当前目标时刷新距离。此行为由直接 API 与真实 `stepWorld` 回归锁定，并用旧目标对象验证。

多人当前目标和候选目标统一使用 `score = aggro + 1/(1+水平距离)`。先找到最高分候选，再仅当其分数**严格大于**当前完整分数乘 `targetSwitchRatio`（1.5）时转移。平分（包括恰好等于切换门槛）保留当前目标；无当前目标时按玩家列表顺序打破同分。不能把滞回反复施加到遍历中的候选，否则选中者会依赖遍历顺序而非最高分。

当前目标必须仍在本次玩家列表中，实体存在、活动、为玩家、HP 大于零且处于 sightM 内；不满足时立即按候选规则重新选择，不受旧目标滞回限制。无合法目标时 ID 与距离均归零。保留既有的遮挡续追约定：新目标必须可见，合法当前目标不因谷仓短暂遮挡而丢失。命中增加仇恨及逐 tick 衰减规则不变，合法高仇恨候选仍可超过切换门槛。

## 取舍与验证

拒绝仅提高零仇恨下的固定门槛或加入锁定计时器：前者仍使评分口径不一致，后者会延迟失效重选与合法仇恨转移。统一评分复用既有 1.5 比率，无新增状态、协议字段、时间窗口或分配。

冻结 v1 对拍向量仍是必须报告的兼容性契约，不可因本提案改变行为便豁免。实际逐 tick 对照发现：10 条失败向量并非单玩家场景，初始化生成四个活动玩家，脚本也显式驱动 id 1..4；旧零仇恨交替选敌从 tick 2 起影响目标 ID，随后影响位置、状态或事件。要求这些逐 tick hash 完全保持与要求相同输入稳定选敌存在直接冲突，`selectTarget` 没有可区分的运行模式。不得识别 fixture 名称/种子或跳过比较来规避。

批准前基线：`ai_` 36/36，新规则对旧向量 `fixture_` 11/21；同环境旧目标对象 21/21。零／单玩家兼容修复不能使这些四人向量兼容。

## 人类决定与版本迁移

人类明确选择“版本化更新受影响向量（推荐）”，拒绝撤回多人修正，也不通过种子/场景特判维持旧hash。保留旧向量与旧实现对照证据，记录行为变化，由真实新服务端生成新向量并审查，双端同步验证。

- 旧10条逐字节归档在 `docs/evidence/fixtures/legacy/targeting-v1/`，附旧 `targeting.cpp.txt`；不纳入顶层自动枚举。
- 活动14条中只更新受影响10条为行为版本 **targeting-v2**；schema仍为2、configHash仍为`19a978ea`（常量未变），版本/来源采用旁路文档记录，不伪称来自冻结TS。
- 独立离线C++导出工具复用fixture初态/投影helper，实际调用新`stepWorld`、导演及快照编解码；JS复用原serializer。测试本身未增加重录模式，也未跳过/放宽比较。冻结TS导出不再允许覆盖活动向量，审查旧规则必须显式输出到独立目录。
- 生成后严格`fixture_`为21/21 exit0，幂等重算10/10。C#仅有玩家运动学预测，不模拟羊选敌；elite向量的玩家位置/朝向不变，tick300 HP变化不在既有预测比较范围；其余9条仍按既有理由校验形状。必须单独报告实际客户端验证，不将此边界说成全量模拟双端等价。
- 完整CTest实际执行但失败：unit进程在runtime.start失败后vector断言中止（0xc0000409，CTest exit8）；不得把fixture全绿等同完整验收。命令、SHA256、审查与最终双端结果见服务端证据。
