# ADR-002 网络模型与协议

- 状态：**传输与协议条款已被 [ADR-009](ADR-009-UDP传输与协议重构.md) 取代**；服务器权威 / 客户端预测 / 量化表 / 差分基线 / 回滚补偿等语义继续有效
- 生效范围：`@ac/shared` 的 `net/*`、`@ac/server`、`@ac/client` 的网络层

## 背景

联机 PVE 射击需要：多名玩家看到一致的敌人、命中判定公平、100ms RTT 下手感可接受。浏览器**不能**发送裸 UDP（无 `RTCDatagram` 之外的通道，而 WebRTC 需要信令与 STUN），因此传输层只能在 WebSocket / WebRTC DataChannel / WebTransport 中选择。

## 决策

1. **服务器权威**：世界状态只在服务器演进。客户端上报的是**命令**（意图），服务器下发的是**快照**（投影）与**事件**（既成事实）。客户端永不产生伤害判定。
2. **传输层用 WebSocket（TCP）**，走 `ws`，二进制帧。
3. **二进制协议**：小端 `ArrayBuffer` + `DataView` 手写编解码，量化传输。不用 JSON 传快照（体积与解析开销）。
4. **频率**：服务器 tick 20Hz（50ms），每 tick 广播一次快照；客户端命令上行 30Hz；事件通道与快照复用同一连接。
5. **差分快照**：服务器为每个客户端记录"已确认基线 tick"，只下发与基线的差异（改变实体 + 移除实体列表）。（**基线口径已被 [ADR-009](ADR-009-UDP传输与协议重构.md) 改为「已编码基线 tick」**：快照通道不可靠、不等 ack；本条其余语义继续有效。）
6. **`Transport` 缝**：网络行为抽象为 `send` / `onMessage` / `close` 三件事，提供两个真实适配器——WebSocket（生产）与内存队列（测试）。因此房间逻辑可在无 socket 的情况下被完整集成测试。
7. **命中判定用回滚补偿**：服务器保存 1 秒（20 tick × 50ms）的姿态历史环，命中时按 `min(RTT/2, 200ms)` 回退目标姿态再求交。

## 量化与字段（冻结）

| 量 | 编码 | 精度 |
|---|---|---|
| 位置 x/y/z | `int16`，单位厘米，范围 ±327.67m | 1cm |
| 偏航 / 俯仰 | `uint16`，`0..65535` 映射 `0..2π` | ≈0.0055° |
| 血量 | `uint8`，`round(hp / maxHp * 255)` | 1/255 相对值 |
| 状态 | `uint8` 位域（kind / anim / flags） | — |
| 实体标识 | `uint16` | — |
| tick | `uint32` | — |
| 服务器时间 | `uint32` 毫秒（相对对局开始） | 1ms |

量化误差判定：客户端渲染位置与权威位置差值不得超过量化步长（1cm），由协议 round-trip 属性测试保证。

## TCP 队头阻塞的取舍与缓解

选 TCP 的代价是丢包时会阻塞后续快照（队头阻塞），在公网抖动下可能造成画面"一顿一顿"。

缓解措施（全部是冻结要求）：

1. 单快照 ≤ 2KB、稳态 ≤ 1.2KB，缩短队头阻塞的持续时间。
2. **不重传应用层数据**：快照是"最新即最优"，服务器每 tick 覆盖，客户端**丢弃**晚到的旧快照（按 tick 单调性），不排队。
3. 命令上行 30Hz 且**只发最新**：客户端若发现上行积压超过 2 条未确认命令，则跳过中间帧、只发最新的状态。
4. 客户端对远端实体插值缓冲 100ms，抖动吸收上限 ±50ms。
5. 事件通道（命中/击杀/波次）虽然是可靠语义，但它是**幂等**的：重复应用同一事件不会产生额外效果。

## 后果与后续路径

- 正面：零信令、零 NAT 穿透问题、一条连接即可跑通全部功能，服务端可在单进程内水平扩容（房间维度）。
- 负面：极端丢包下体验劣于 UDP。若将来要上公网大流量，切换路径为：`WebTransport`（Node 端暂无成熟服务端实现）→ 或 `WebRTC DataChannel` 不可靠通道 + 独立信令；由于协议编解码与 `Transport` 已分离，切换只影响适配器与连接管理，不影响 `sim` 与协议字段。
- 重新评估触发条件：实测公网环境丢包 > 3% 且玩家可感知卡顿；或同局人数 > 8。
