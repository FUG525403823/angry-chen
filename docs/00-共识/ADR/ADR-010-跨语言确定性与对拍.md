# ADR-010 跨语言确定性与对拍

- 状态：已接受（v2 起点）
- 生效范围：`server/` 的模拟内核与 AI、`client/` 的预测/和解/数学模块、`docs/plans-v2/` 的 S02/S06/S07/S08/S09 与 C02/C04/C05/C06/C08
- 关联：[ADR-008](ADR-008-服务端语言与客户端引擎变更.md)（双语言）、[ADR-009](ADR-009-UDP传输与协议重构.md)（量化与快照）

## 背景

v1 的手感来自"同一份 `stepWorld` 被服务器、客户端预测、机器人三处共用"（ADR-002 §3.1）。v2 拆成 C++ 与 C# 两套实现后，这条红利消失：若两侧浮点结果不一致，预测会持续被硬纠正，手感反而比 v1 更差。

## 决策

1. **数值表示**：世界状态的位置/速度一律 IEEE754 `double`（C++ `double`，C# `double`）；量化传输按 ADR-009。**禁止 `float`/`Math.fround` 参与权威模拟**（避免两侧精度差异）。
2. **允许的运算子集**（权威模拟与客户端预测必须只用这些）：
   - `+ - * /`（IEEE754 正确舍入，跨平台一致）
   - `sqrt`（IEEE754 要求正确舍入）
   - 整数加减乘与位运算（`uint32` 回绕语义显式）
   - 比较、`min`/`max`、`abs`（用位运算实现，不用库函数）
3. **禁止**：`sin/cos/tan/exp/log/pow/atan2` 等超越函数、`hypot`、隐式 FMA、`-ffast-math`、`-march=native`、x87 80 位中间精度（编译目标 `SSE2` 基线）。角度统一用**共享查表**：
   - 表的生成：离线脚本用宿主 `Math.sin` 按 v1 的公式采样成整数表（步长与幅值规格由 S02 冻结），生成结果作为对拍向量的一部分入库到 `docs/evidence/fixtures/`。生成脚本在**可写派生副本** `D:\projects\tmp\angry-chen-fixture`（从备份仓库复制）上运行，备份仓库 `D:\projects\tmp\angry-chen-bak` 全程只读。
   - 唯一允许的角度入口是 S02 冻结的四个函数：`quantizeAngle`（弧度 → u16）、`sinUnits`/`cosUnits`（查表）、`angleUnitsFromVector`、`angleUnitsFromRatio`（用查表 + 整数比较替代 `atan2`/`asin`）。AI 与战斗代码不得直接调用任何超越函数。
   - v1 要参与对拍的部分，在派生副本里以**同一张表**替换其 `Math.sin/cos/atan2/asin` 之后再导出向量；`angry-chen-bak` 不做任何写入。
4. **遍历顺序**：只遍历数组与插入序容器；禁止依赖哈希容器迭代序。实体处理顺序 = `EntityId` 升序。
5. **随机数**：只用 v1 `rng.ts` 的 `mulberry32`（`uint32` 位运算，跨语言逐位可复现），并保持三条流 `ai`/`spawn`/`fx`；`fx` 流不得影响模拟流。
6. **对拍机制**（这是本 ADR 的核心）：
   - **测试向量（Fixture）= 纯文本 JSON**：`{ seed, configHash, ticks: [{ dtMs: 50, commands: [...] }], expected: { entities: [{id, kind, pos, yaw, pitch, hp, flags}], events: [...], rngState } }`。
   - 由 [S07](../../plans-v2/server/S07-旧TS模拟对拍.md) 从**冻结的 v1 `packages/shared`**（备份仓库，只读）导出，落在 `docs/evidence/fixtures/`，**入库**（纯文本，符合零素材约束）。
   - C++（S07）与 C#（C02/C06）各自加载同一批 fixture，逐位比较；任何一项不一致即门禁失败并打印首个差异字段。
   - fixture 覆盖：静止、直线移动、碰撞、连射命中、倒地救援、四种羊形 AI、羊王阶段切换、波次导演预算、快照编码 round-trip。
7. **契约变更流程**：改动被 fixture 覆盖的规则（数值表、AI 参数、量化步长）→ 先改 v1 对照实现或显式重建 fixture，两侧同时改，再跑对拍；不得只改一侧。

## 被否决方案的理由

- **定点数（fixed-point）全覆盖**：跨语言最稳，但要把 v1 的全部浮点规则（射线、散布、羊群转向）重写为定点，工作量大且数值手感会变，fixture 无法直接对照。
- **只在服务器跑模拟、客户端纯插值**：最省事，但放弃预测就放弃了本地手感（移动延迟 = RTT/2），与本次重构动因冲突；作为 ADR-008 的**回退选项**保留。
- **依赖 `float` + 容差比较**：容差会随 tick 累积放大，最终仍表现为周期性硬纠正；"逐位一致"是可机器判定的强约束，值得为它限制运算子集。

## 后果

- 正面：确定性可被门禁机器验证；两侧同一份 fixture 也让"数值平衡改动"变成可回归的。
- 负面：模拟代码不能随手用三角函数与浮点库；需要维护 fixture（体积小、纯文本）。

## 复查触发条件

- 出现无法用查表表达的数学需求（如真实弹道积分）→ 先评估定点化并写新 ADR。
- fixture 集合 > 2MB 或单次对拍 > 30s → 改为抽样对拍并记录覆盖率。
