# ADR-020 完整渲染历史与单调播放时钟

- 状态：已接受
- 范围：客户端 SnapshotView、EntityViews、Interpolation
- 关联：ADR-009、ADR-010、ADR-011

## 背景

线协议快照为稀疏差分。旧实现将线记录直接作为插值历史，未变化实体缺席时不能保持正确的历史姿态；到包直接校正时间还会使播放时间倒退。离线真实源回归 `tools/remote-pose-check.ps1` 在实施前分别报告 sparse-stop、clock-monotonic、missing-baseline 失败。

## 决策

1. 保留 TryGetFrame / TryGetEntityInFrame 的原始线记录语义，增加独立的完整渲染历史查询。历史内存预分配，帧内不分配。
2. 差分只基于其声明且实际持有的基线重建；缺基线不修改镜像、播放历史或已应用 tick，计入 BaselineMismatch，等待已有全量恢复。不新增请求类型或羊预测。
3. 同一实体的连续历史用于插值；删除、重新出现或 kind 改变构成新的表现生命周期，不跨生命周期插值。新实体仍从最新权威姿态出现，移除仍立即生效。
4. 到包更新时钟目标，播放时钟只在 Advance 中受控前进。动态延迟的变化也由播放速率吸收，不直接跳减播放时间。偏差超过既有重置阈值时允许显式重新锚定；新会话显式 Reset。
5. 无未来样本时保持最后有效姿态，不外推羊或变更固定模拟步长。

## 后果与验证

增加固定容量的渲染历史内存和线性拷贝，换取常数时间实体历史查询及稀疏状态正确性。网络字段、量化规则、本机预测与原始线记录接口不变。验证包括稀疏停止、非最新基线重建、缺基线拒绝、生命周期隔离、到包抖动下单调播放及原有移动回归。离线结果不等价于真实联机/GPU验证。
