# ADR-011 表现层数值单一来源

- 状态：已接受（v2 收尾）
- 生效范围：`client/Assets/Scripts/View/**`（剔除距离、阴影距离、实例化/粒子上限）、`client/Assets/Tests/PerfSuite.cs`、`client/Assets/Tests/SheepSuite.cs`
- 关联：[ADR-008](ADR-008-服务端语言与客户端引擎变更.md)（引擎与 URP）、[ADR-010](ADR-010-跨语言确定性与对拍.md)（对拍口径：本 ADR 只动**表现层**数值，不碰权威模拟）
- 依据：C07 §5(d)、C08 §5(e)、C14 §5（三份计划正文不动，取代关系记在本 ADR）

## 背景

同一个"多远还算可见"的问题，在计划里有三个互斥的答案：

| 出处 | 冻结值 |
|---|---|
| C07 §5(d) | 阴影距离**单值 60m** |
| C08 §5(e) | 剔除距离**90m** |
| C14 §5 | 剔除距离**羊 60m / 场地 80m**；阴影距离**20/35/50m（按画质档）** |

实现侧**不得自签规格**（审查已两次判定），于是 `LightingRig.ShadowDistanceM = 60f` 与
`Culling.CullDistanceM = 90.0` 各自按自己的计划留了下来，而 `Batching` 里另有一份 C14 的档位表。
结果：同一个问题有三处答案，其中两处在代码里而不是在表里；Culling 的两条剔除路径
（`Filter` / `IsVisible`）还把 90 硬编码进了循环条件。

## 决策

1. **`Batching` 的档位表是表现层距离与上限的唯一来源**：剔除距离（羊 60m / 场地 80m）、
   阴影距离（20/35/50，按画质档）、实例化上限、粒子上限。其他模块**只读不抄**。
2. **C14 §5 取代 C07 §5(d) 的单值 60m 与 C08 §5(e) 的 90m**。作废的是这两个**数**；
   C08 §5(e) 的算法结构（6 平面视锥 + 距离 + 屏幕占比三级剔除、零分配索引缓冲）继续有效，
   只是距离不再由 `Culling` 自带。
3. `Culling` 不再自带距离常量，改为从档位表读羊档：`Batching.CullDistanceMeters(Batching.CullKindSheep)`。
   场地档（80m）保留给场景几何，羊实例一律用羊档。
4. `LightingRig` 不再自带阴影距离，改为 `Batching.ShadowDistanceFor(Batching.QualityTier)`。
5. 画质档是**运行期选择器**（`Batching.SetQualityTier`），阴影距离必须能随档变化；C07 的单值 60m
   表达不了这件事，这是本条裁决的理由之一。

## 后果

- 表现层距离只剩一处可改：改 `Batching` 的档位表即改全部读数（`Culling` 与 `LightingRig` 都不再持有副本）。
- 剔除距离从 90m 收紧到 60m。用例里的距离断言随之收敛：`SheepSuite.ChecksCulling` 的
  "80m 仍可见"改成 55m，否则那条断言会在距离检查处提前返回，"占比不足"这一路就再也没被真正走过。
- C08 §5(e) 的 90m 与 C07 §5(d) 的 60m 在客户端代码里不再有对应常量；两份上游计划正文不修改，
  取代关系只记在本 ADR（ADR 先于代码的纪律）。
- **待人类复核**：C08 当初给 90m 的理由未见记录，若美术/性能实测认为 60m 太近，
  改 `Batching.SheepCullDistanceM` 一处即可，本 ADR 的结论不变。
