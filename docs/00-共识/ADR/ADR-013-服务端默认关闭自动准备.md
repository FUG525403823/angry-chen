# ADR-013：服务端默认关闭自动准备（大厅必须可达）

- 状态：已裁决（实现随本 ADR 一起落地）
- 日期：2026-09-28
- 影响面：`server/src/server/runtime.hpp`（默认值）、`server/src/server/serve_cli.*`（新选项）、
  `server/src/main.cpp`（usage）、`server/tools/gate.cpp`（装载场景显式开启）、
  `server/tests/serve_cli_test.cpp`、`server/tests/runtime_test.cpp`、`server/README.md` §18
- 相关：S10 §5.4（房间相位与"全员准备"）、S14/S15（门禁与浸泡场景）、C10–C12（客户端大厅）、
  C15 §5 第 2/3 步（`ready=false` → 按 Ready 开局）、ADR-012（拒绝准入必须回执）

## 背景与证据

`RuntimeConfig::isAutoReady` 的默认值是 `true`（`runtime.hpp:46`，注释写着"机器人不走大厅：连上即 ready
并开局"），而**没有任何代码路径可以把它关掉**：`--serve` 的选项解析（`serve_cli.cpp`）里没有对应开关，
`ensureMatchRunning()`（`runtime.cpp:560-586`）对**每一个**已连接会话调用
`roomSetReady(..., true, ...)`，随后 `tryStartMatch`。

更根子上的问题：**客户端命令里的 Ready 位（`config::kButtonReady = 0x80`）服务端从来没有读过**。
`config/player.hpp:48` 定义了这个常量，但全仓库只有 `runtime.cpp:574` 这一处按**无条件 true** 调
`roomSetReady`，`roomApplyCommand` 的命令字段里 `buttons` 只被用于冲刺/跳跃/开火/装弹/交互/狂暴/切枪
（`sim/movement.cpp:29`、`combat/resolve.cpp:349-361`）——"准备"这一档在服务端是空的。也就是说：
C10–C12 的客户端大厅把 Ready 位送出去了，服务端既不认、也不回，整条"按准备 → 开局"的产品路径不存在。

后果（联调实测，原始日志 `build/joint/run.log`）：

1. **客户端大厅在真连时不可达**。C15 §5 第 2 步要求"刚进大厅的玩家行 `ready=false`"，但服务端在玩家发出
   任何命令之前就把它标成 ready——客户端用例 `joint.acceptance` 第 2 步实测 `actual=True` 直接红
   （同一断言在只改客户端、不改服务端时必然红，属**服务端侧遗留**）。
2. **第 3 步的"按 Ready 开局"被架空**：开局由服务端的自动准备触发，客户端的 Ready 位不再有意义。
3. **第二个玩家进不来**：首个连上的会话被自动就绪后立即开局，房间进入 `kPlaying`，其余连接一律
   `kMatchInProgress`——ADR-012 之后会收到 `Disconnect(8)`，在此之前是静默黑洞。
4. **装载工具反过来绑架了产品默认**：`ac_bot` 的按钮只发 `Fire|Reload`（`server/tools/bot.cpp:174`），
   从不发 Ready 位，所以门禁/浸泡必须依赖自动准备——但这是"装载场景"的需求，不该是产品默认。

## 裁决

1. `RuntimeConfig::isAutoReady` **默认改为 `false`**。产品默认走 S10 §5.4 的真实大厅：会话只有收到带
   Ready 位的命令才变 ready，房主（第一个进房者）在全房就绪时开局。
2. 新增显式开关 `ac_server --serve --auto-ready`（布尔选项，不带取值；重复出现判失败，与 `--serve` 同款
   校验）。装载/门禁/压测场景**必须显式打开**，不再依赖"默认就是压测模式"。
3. 依赖自动开局的既有场景显式开启，行为不变：`ac_gate` 的进程内 `RuntimeConfig` 与 G1 相自开的
   `ac_server` 子进程都显式配置 `--auto-ready`/`isAutoReady=true`；`ac_tests` 里走"装载路径"的用例
   （`runtime_test.cpp` 的 `testConfig()`）显式开启。（裁决 6 让机器人自己也按准备，两条路都能开局；
   门禁保留显式开关是为了让"这是装载场景"在命令行里可见。）
4. **不新增计数器、不新增日志事件**：S13 §5 的指标名清单与 `core/log.hpp` 的 `EventName` 清单是契约，
   这次改动只动默认值与选项解析。
5. **服务端必须读客户端的 Ready 位**：在 `Runtime::handleCommand` 里（`room_->phase == kLobby` 且会话已在房内时）
   按 `command.buttons & config::kButtonReady` 调 `roomSetReady`；武器预览沿用大厅口径——只有带
   `kButtonSwitchWeapon` 位时才把 `switchTo` 当武器选择，否则传越界值让 `roomSetReady` 不碰武器。
   `roomSetReady` 幂等，只在真变化时广播 MatchState，所以 20Hz 重发不会放大流量。
6. `ac_bot` 常置 Ready 位（`tools/bot.cpp`）：机器人扮演"已按准备的玩家"，这样装载/门禁/联调都能跑在
   **产品默认的服务端**上，不必依赖 `--auto-ready`。0x09 的 Fire|Reload 抖动保持不变。
7. **命令去重方向修正**（同一条链路上抓到的第二个真 bug）：`Runtime::handleCommand` 里 §5.5 的窗口去重
   此前写成 `if (!noteCommandSequence(...)) → 丢`，而该函数的契约（`security_test.cpp` 的
   `security_dedup_window_eviction`/`_handles_seq_wraparound`：命中窗口返回 `true`）是**命中即重复**。
   方向反了 ⇒ **每条命令的首次发送都被当重复丢掉**，只有可靠层重传（同 seq 第二次）才被应用；移动/开火/
   准备位全部迟一个 RTT 生效，`ac_dropped_frames_total` 还把它记成"重复"。修正为
   `if (ac::security::noteCommandSequence(...)) → 丢`。
8. 客户端侧不改代码：`joint.acceptance` 第 2/3 步在默认配置下即可通过（`ready=false` → 举 Ready 位 → 开局）。

## 后果

- 新开的 `ac_server --serve` 在没有玩家按准备时**不会开局**（大厅常驻）；这是产品期望，也是"客户端大厅
  流程"能被联调覆盖的前提。
- 人肉/脚本压测必须带 `--auto-ready`，否则机器人会一直坐在大厅里（不会再有"看起来跑起来了、其实没开局"
  的静默失败）。运维手册与 README §18 的命令示例同步写明。
- `--auto-ready` 与客户端 Ready 位**不冲突**：开关打开时会话被无条件置 ready，客户端的 Ready 位只是重复
  确认（幂等）。
- 本 ADR 不改变任何线上线格式：Hello/HelloAck/MatchState/Disconnect 的载荷与取值域一字未动。
- 裁决 7 修好之后，**门禁/浸泡里机器人的移动才真正生效**（此前只有重传那一份被应用）：G1–G8 的性能数字
  是"原地不动的人群"测出来的，本批已重跑门禁复验（数字见 `server/README.md` §15 与验收证据）。
- 用例覆盖：`runtime_lobby_ready_bit_starts_match`（默认配置下 大厅 → ready=false → 只有房主准备好不开局
  → 全房就绪开局，并断言"首次发送就生效、dropped 不涨"）、`runtime_room_full_answers_disconnect_reason_eight`
  （满员回执）、`serve_cli_auto_ready_flag`（默认 false / `--auto-ready` / 重复与带值都拒绝）。

## 待人类复核

1. 若策划希望"**满员即自动开局**"（不等房主按准备），正确的实现是"人数到 `kMaxPlayersPerRoom` 且全房就绪"
   的另一种触发条件，而不是把 `isAutoReady` 打开——请给一条明确的准入/开局规则，我们再补 ADR。
2. ~~装载侧是否也要 `ac_bot` 改成"真发 Ready 位"~~ —— **已按裁决 6 落地**（机器人常置 Ready 位，因为它扮演的
   就是"已按准备的玩家"）。若你认为装载机器人应当**完全不按准备**（逼产品侧大厅流程先就位），说一声我把它改回
   纯 `Fire|Reload` 并只在门禁里用 `--auto-ready`。
