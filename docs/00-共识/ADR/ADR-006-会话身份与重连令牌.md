# ADR-006 会话身份与重连令牌

- 状态：已接受（O08）
- 生效范围：@ac/shared 的 net/codec.ts、@ac/server 的 session.ts / rooms.ts / room.ts、@ac/client 的 net/connection.ts

## 背景

宽限期重连此前按**昵称**匹配已断线会话（`packages/server/src/rooms.ts` 的 `findGracedSession(room, name)`），
命中后把新连接绑到旧 `pid`（保留位置、血量、名额、武器）。昵称只做长度/字符校验、允许重复，
因此「知道 4 位房间码 + 目标昵称」即可在宽限期内接管他人会话：顶掉对方重连、继承其位置与已得资源。
握手帧（`welcome` 16 字节 / `join`）里没有任何可验证的秘密，身份没有兜底。

## 决策

1. **令牌式身份**：服务器在每次成功 join 时生成 8 字节随机会话令牌（`node:crypto` 的 `randomBytes(8).toString('hex')`），
   随 `welcome` 下发（`[16..23]`，ASCII 十六进制）；客户端存于 `sessionStorage`（每标签页独立），重连时随 `join` 上行（房间码之后 8 字节）。
2. **只按令牌匹配身份**：`findGracedSession(room, token)` 要求 `token.length > 0 && session.token === token`；昵称不再参与身份判定（仍用于显示与聊天）。
   无令牌或令牌不匹配一律按**新玩家**处理；对局进行中则拒绝（沿用既有 `match-in-progress` 路径）。
3. **重连复用不重生成**：`roomReconnect` 把旧会话的令牌复制给新连接，避免「连续刷新第二次掉线」。
4. **协议版本升到 2**（`PROTOCOL_VERSION`）：`welcome` 16 → 24 字节，`join` 追加 8 字节令牌；两端版本不一致即拒绝。
5. **边界**：令牌只用于**重连身份**，不是账号体系；不引入持久化身份（无数据库、无跨房间身份）；令牌不参与反作弊判定；令牌生命周期与房间一致，不做轮换/过期。

## 后果

- 同昵称无法再冒用他人会话；`sessionStorage` 丢失（隐私模式/清站点数据）时退化为新玩家，对局中则收到可读拒绝并提示刷新。
- **协议格式变更必须成对发布**：v1 客户端会被 v2 服务器拒绝（错误码 `protocolMismatch`），v2 客户端连 v1 服务器同理；回滚需客户端与服务器同版本回滚。
- 客户端改用 `sessionStorage` 存令牌（`TOKEN_STORAGE_KEY = 'ac.sessionToken.v1'`），昵称/上次房间码仍在 `localStorage`：同机两标签页同昵称进同一房间不再互相顶替。
- 实现与本 ADR 冲突时以 ADR 为准并回改代码；唯一权威描述就是本文档。
- 未决（移交 O10）：`tools/check-docs.mjs` 的 `REQUIRED_DOCS` 手工清单未含 ADR-005/ADR-006；令牌轮换/过期策略暂不引入。
