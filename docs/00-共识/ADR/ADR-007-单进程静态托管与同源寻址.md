# ADR-007 单进程静态托管与同源寻址

- 状态：**已被 [ADR-008](ADR-008-服务端语言与客户端引擎变更.md) 取代**（v2 客户端是原生进程，不再有浏览器同源问题；静态托管随 v1 客户端退役）
- 生效范围：`@ac/server` 的 `http.ts` / `main.ts` / 新增 `static.ts`、`@ac/client` 的 `main.ts` / 新增 `net/serverUrl.ts`、`.env.example` 与部署文档

## 背景

1. ADR-004 §1 的原文是「**单进程、单端口**：一个 Node 进程同时承载 HTTP（静态资源、健康检查、`/metrics`）与 WebSocket（游戏）」，但实现只落了一半：`packages/server/src/http.ts` 只处理 `/health`、`/metrics`、`/api/*`，其余路径一律 404（`http.ts:139-141`），静态资源被整体推给反向代理（`Dockerfile:18-20`、`docs/运维手册.md` §1）。反代在 ADR-004 里的职责是**终结 TLS**，不是「能看到页面」的前提；两者被混为一谈后，「只起一个 Node 进程」就变成「打开地址看到 404」。
2. 客户端把服务器地址硬编码为 `DEFAULT_SERVER_URL = 'ws://127.0.0.1:8787'`（`packages/client/src/main.ts:57,105`），只有查询串 `?server=` 能覆盖。于是任何**别人**打开的页面都在连**他们自己**的 127.0.0.1；若页面经 https 提供，`ws://` 还会被浏览器按混合内容策略拦掉。
3. `.env` 不会被加载（`docs/运维手册.md` §2），而 `.env.example` 默认写入 `ALLOWED_ORIGINS=http://localhost:5173`：照抄模板部署后，非本机来源会被 `security.origin_rejected` 静默断开（`security.ts` 的 `createOriginGuard`）。
4. 结果：有公网 IP 的机器上跑起服务端，朋友仍然「看不到服务端」。缺的不是服务端，而是**静态托管**与**寻址**这两段。

## 决策

### 1. 静态托管回到 Node 进程（兑现 ADR-004 §1）

- 新增 `packages/server/src/static.ts`：`createStaticServer({ root, immutablePrefix='/assets/', immutableMaxAgeSeconds=31536000, gzipMinBytes=1024 })` 返回 `handle(req, res): boolean`（`true` = 已接管；`false` = 交给既有 404）。
- 契约（冻结）：
  - 只接管 `GET`/`HEAD`，其它方法返回 `false`。
  - 路径安全：`decodeURIComponent` 失败、含反斜杠/NUL/`..` 段、或 `resolve` 后逃出 `root` → `false`；以 `/` 结尾的路径追加 `index.html`；目标是目录而非文件 → `false`。
  - 缓存：`/assets/*` → `public, max-age=31536000, immutable`；`index.html` 及其它 → `no-cache`。**不发 ETag/304，不支持 Range**（Vite 产物名带内容 hash，够用）。
  - 压缩：`accept-encoding` 含 gzip、类型可压缩且体积 ≥ `gzipMinBytes` 时流式 gzip，并设 `vary: accept-encoding`；gzip 响应不设 `content-length`。
  - SPA 兜底：文件不存在、`accept` 含 `text/html`、且路径无扩展名（或 `/`）→ 返回 `index.html`；否则 `false`（保持 404 JSON 语义）。
  - 读流出错不崩进程（工程约定 §7）。
- 路由优先级（`http.ts`）固定为：`/api/*` → `/health` → `/metrics` → 静态 → 404。`createHttpHandler` 的第三参数可选，既有调用与测试不变。
- `CLIENT_DIST` 覆盖 dist 目录（绝对路径或相对 cwd）；未设置时按模块位置解析 `<repo>/packages/client/dist`（与 cwd 无关）；值为 `off`/`none`/空串，或目录不存在 → 关闭静态托管。

### 2. 客户端同源寻址（一条地址即全部）

- 新增 `packages/client/src/net/serverUrl.ts`，优先级（冻结）：
  1. `?server=` 可用（`ws`/`wss`/`http`/`https`，http→ws、https→wss）→ 用它；
  2. `import.meta.env.DEV`（Vite dev）→ `ws://127.0.0.1:8787`（`pnpm dev` 的双进程开发形态不变）；
  3. 页面有 host → `ws://<host>/ws` 或 `wss://<host>/ws`；
  4. 其它（`file://`）→ `DEFAULT_SERVER_URL`。
- 路径取 `/ws`：服务端不按路径过滤 upgrade（`ws-adapter.ts` 把 `WebSocketServer` 挂在同一个 `http.Server` 上），而 `deploy/Caddyfile` 的 `handle /ws` 也正好匹配——裸跑与反代两种形态共用同一条规则。
- `?server=` 保留为覆盖手段；大厅不新增服务器地址输入框。

### 3. CLI 入口加载 `.env`（Node 原生，零依赖）

- `main()`（`packages/server/src/main.ts`）在 `startServer` 之前调用 `process.loadEnvFile(process.env.AC_ENV_FILE ?? resolve(process.cwd(), '.env'))`，缺失/不可读时静默跳过；`AC_ENV_FILE` 可指定路径。
- `startServer(env, logger)` 保持只读传入的 env：单测、`tools/**`、程序化调用不受影响。
- 12-factor 优先级不变：**已存在的真实环境变量不会被 `.env` 覆盖**（Node `--env-file`/`loadEnvFile` 的既有语义，已实测）。

### 4. 运维可见性

- `listening` 日志的 `detail` 增加 `clientDist: string | null` 与 `joinUrls: string[]`（`node:os` 的非内网 IPv4 + 端口），让「把哪个地址发给朋友」不再靠猜。
- 显式设置的 `CLIENT_DIST` 指向不存在的目录时记 `clientDist.missing` warn。

### 5. 反代与 TLS 降级为可选

- `deploy/Caddyfile`、`deploy/nginx.conf`、systemd/PM2 样例**保留**，仍标注静态审查；它们从「唯一能玩的路径」变成「需要域名/HTTPS/压缩卸载时才用的路径」。
- 本期**不做** TLS：公网 IP 上就是明文 `http://` + `ws://`（朋友局，非公开服务）。

### 6. 模板默认 `HOST=0.0.0.0`，代码默认不动

- 代码默认（`DEFAULT_HOST`）保持 `127.0.0.1`；**`.env.example` 模板默认写 `HOST=0.0.0.0`**（联机就绪），并在同一行附近写明代价与改回方式。
- 理由：复制模板是一个**显式**的选择点（用户看得见这一行），而改代码默认是**隐式**改变暴露面，且会波及不读 `.env` 的调用方（容器、测试、`tools/**`）。
- 公网直连必须自行限定来源（云安全组 / 防火墙），或改用 §5 的可选反代样例。

## 备选方案与被否决理由

| 方案 | 否决理由 |
|---|---|
| 继续只提供 `?server=` 手动拼接 | 每次分享都要手写服务器地址；https 页面下 `ws://` 仍被浏览器拦；不解决「看不到服务端」 |
| 静态资源交给独立进程（`vite preview` / 第二个静态服务器） | 违背 ADR-004 §1 的单进程形态，多一个进程与端口要解释，且与「一个地址就能玩」直接冲突 |
| 客户端连根路径而不是 `/ws` | 根路径在反代样例里被 SPA 兜底吃掉，裸跑与反代无法共用同一条规则 |
| 引入 `cross-env` / `dotenv` 等依赖 | 依赖准入（工程约定 §4）要求确有不可自研的必要；Node 24 原生 `loadEnvFile` 已覆盖需求 |
| 让代码默认（`DEFAULT_HOST`）监听 `0.0.0.0` | 会静默改变暴露面，且波及容器/测试/`tools/**` 等不读 `.env` 的调用方；改为只让 `.env.example` 模板默认 `0.0.0.0`（显式、可撤销），代码默认保持 `127.0.0.1` |

## 后果

- 正面：一台有公网 IP（或局域网）的机器上 `pnpm build:client && pnpm --filter @ac/server run start` 后，`http://<IP>:8787` 既是页面也是游戏服务器；朋友无需任何参数即可进房。压缩与缓存头由 Node 进程承担，无需反代。
- 负面：Node 进程多了静态文件 I/O 职责（单机 4 人局量级可忽略）；不发 ETag/304、不支持 Range 会让重复请求重新传输——`/assets/*` 用 immutable 缓存抵消。
- 已知边界：`vite preview`（4173）是生产构建但不由游戏服务器托管，会推导出同源 `ws://localhost:4173/ws` 而连不上；用 `pnpm serve` 或显式 `?server=`。仓库开发主路径（`pnpm dev`，5173 + 8787）不受影响。
- 实现与本 ADR 冲突时以 ADR 为准并回改代码；唯一权威描述就是本文档。
- 重新评估触发条件：需要 HTTPS/域名（回到反代样例）、需要多实例静态托管（换 CDN/对象存储）、或静态请求量级超过单进程预算。
