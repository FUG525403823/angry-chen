# 工程约定（约束文档）

本文件对 v2 的两条计划链（`docs/plans-v2/server/S01–S15`、`docs/plans-v2/client/C01–C15`）具有强制力。计划文档与代码冲突时，以本文件为准；确需偏离时，先改本文件（走 ADR），再改代码。

> 范围说明：§1 是当前仓库形态，§11/§12 是 v2 现行的语言与双链条款。其余章节里的 TypeScript/Node 细则来自 v1（该实现已移出仓库，冻结副本在 `D:\projects\tmp\angry-chen-bak`），保留作为**命名、错误处理与文档纪律**的参考，不再约束 v2 代码。

## 1. 仓库形态

```
angry-chen/
├─ server/              C++ 权威服务器（第一条链 S01–S15）
├─ client/              Unity 6 LTS + URP 客户端（第二条链 C01–C15）
├─ tools/               纯 Node 门禁脚本（无第三方依赖）：check-docs.mjs、check-assets.mjs
└─ docs/                共识（00-共识/）、需求（02）、选型（03）、双链计划（plans-v2/）
```

- **v2 主线**：`server/`（C++20，无第三方运行时库）与 `client/`（Unity 6 LTS + URP）**完全分离**，只通过 [ADR-009](ADR/ADR-009-UDP传输与协议重构.md) 冻结的 UDP 协议通信，不共享源码；两端的施工由两条线性计划链驱动（见 [plans-v2 索引](../plans-v2/README.md)）。
- **v1 去向**：v1 的 TypeScript 全栈实现（`packages/**`）、Node/pnpm 工具链、Docker 与反代配置、以及只描述 v1 的文档都已移出本仓库；冻结副本在 `D:\projects\tmp\angry-chen-bak`（含 `node_modules`）。计划文档里出现的 `packages/**` 一律指该副本。
（以下为 v1 的 TypeScript 约定，仅作历史参考：ESM 与 `.ts` 扩展名导入、包间单向依赖 `client/server → shared`、`shared` 保持纯净。v2 的现行条款见 §11。）
- 客户端消费 `@ac/shared` 的**源码**（`exports: { ".": "./src/index.ts" }`），不经过构建产物，因此改 shared 会触发客户端 HMR。

## 2. 语言与类型

- TypeScript 锁定 `5.9.3`。**不升级到 7.x**，因为 `typescript-eslint@8.70` 的 peer 范围是 `>=4.8.4 <6.1.0`（依据见 ADR-001）。
- `tsconfig.base.json` 必须开启：
  - `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`
  - `verbatimModuleSyntax`（类型导入必须写 `import type`）
  - `erasableSyntaxOnly`（禁 `enum`/`namespace`/参数属性，保证代码永远可被类型剥离）
  - `isolatedModules`、`noImplicitOverride`、`noFallthroughCasesInSwitch`
  - `noEmit`（本仓库不产出服务端构建产物），`skipLibCheck`
- **禁止 `any`**、禁止 `@ts-ignore`（确需时用 `@ts-expect-error` 并写明原因）。
- 不使用装饰器、不使用 `const enum`、不使用类作为模块边界的主要形式（函数 + 纯数据结构优先）。
- 面向数据的配置一律放在 `shared/src/config/*.ts` 并导出为 **冻结对象**（`as const` + `Object.freeze`），不散落在业务代码里。

## 3. 纯净性与确定性（`@ac/shared`）

1. `shared` 不得 import：`three`、任何 DOM 全局、任何 `node:*`。
2. `shared` 不得调用 `Math.random`、`Date.now`、`performance.now`。时间与随机数**必须**由调用方传入（`dtMs`、`tick`、RNG 实例）。
3. 随机数只用 `shared/src/rng.ts` 的 mulberry32，并按规定分三条流：`ai`、`spawn`、`fx`。fx 流不得影响 sim 流。
4. 模拟只做整数毫秒步进：`dtMs` 取值恒为 `50`。不得使用变长 dt。
5. 遍历顺序必须确定：只遍历数组与 `Map` 的插入序，禁止依赖对象键序的"刚好如此"。
6. 浮点一律 `number`（float64），禁止 `Math.fround` 等会引入平台差异的收窄，除非该处已冻结量化规则。
7. 快照编码的量化规则（厘米、角度步长、血量百分比）属于**冻结契约**，修改须走 ADR。

（v1 判定方法，历史参考：`shared` 的纯净性由 eslint 自定义规则区块 + P02 的静态检查用例双重保证；v2 中该角色由 `server/` 的独立编译单元与 ADR-010 的运算子集约束承担。）

## 4. 依赖准入

- 新增任何运行时依赖必须先写 ADR（`docs/00-共识/ADR/`），说明：解决什么问题、为何自研不可行、体积与许可、退出成本。
- 已批准依赖白名单（运行时）：`three`（仅 client）、`ws`（仅 server）。开发依赖：`typescript` `vite` `vitest` `@vitest/coverage-v8` `tsx` `eslint` `typescript-eslint` `prettier` `@types/*` `puppeteer-core`（可选，E2E）。
- **不引入**：React/Vue/Svelte、状态管理库、物理引擎、ECS 框架、UI 组件库、CSS 框架、校验库。
- 不使用需要原生编译的包（本机无构建工具链，且会拖累 CI）。

## 5. 质量门

v2 的可执行门禁是两条**无第三方依赖**的 Node 脚本，必须都退出码 0：

1. `node tools/check-docs.mjs` —— 必需文档齐备、双链编号连续、九段式齐全、§2/§9 移交物守恒、`order` 顺序表的前向依赖、docs 内相对链接可达
2. `node tools/check-assets.mjs` —— 零外部素材（扩展名黑名单 + 二进制嗅探）、依赖白名单（`client/Packages/manifest.json` 只允许 URP 与官方模块，`server/CMakeLists.txt` 不得引入第三方依赖）

链内另有各自的门（写进对应计划的 §6/§7）：S01 的 `cmake --build` + `ctest`、C01 的 Unity 批处理 EditMode 测试。

规定：**任何计划文档的 DoD 都包含"`node tools/check-docs.mjs` 与 `node tools/check-assets.mjs` 全绿"**。v1 的九步 `pnpm check` 已随 Node 工具链移出仓库（备份仓库内仍可运行）。

## 6. 命名与目录

| 对象 | 规则 | 例 |
|---|---|---|
| 文件 | 小写连字符，按域分目录 | `shared/src/ai/flocking.ts` |
| 类型/接口 | 大驼峰，无 `I` 前缀 | `type Snapshot = ...` |
| 函数/变量 | 小驼峰 | `stepWorld` |
| 常量 | 大写下划线（导出）/ 小驼峰（局部） | `SERVER_TICK_MS` |
| 布尔 | `is`/`has`/`can` 前缀 | `isDowned` |
| 事件名 | 过去式（既成事实） | `sheepKilled`、`playerDowned` |
| 协议字段 | 与 `net/protocol.ts` 中的常量同名 | `Op.InputCmd` |
| 测试文件 | 与被测文件同目录，`*.test.ts` | `rng.test.ts` |

## 7. 错误处理与日志

- 服务器：任何来自客户端的输入都视为不可信。解析失败 → 丢弃该消息并计入 `malformedMessages`；连续超阈值 → 断开会话。**不得**因客户端输入抛异常而使进程崩溃。
- 模拟内核：不做 I/O、不抛业务异常。非法输入一律以返回值表达（`{ ok: false, reason }`），由调用方决定日志。
- 客户端：网络异常 → 顶部横幅 + 自动重连；渲染异常 → 错误边界，保留 UI 可交互。
- 日志：服务器用结构化 JSON 行（`{ts, level, room, tick, evt, ...}`），不打印每 tick 的常态日志。客户端日志走 `?debug=1` 开关。

## 8. 提交与变更

- 提交信息用 Conventional Commits：`feat|fix|chore|docs|test|refactor|perf(scope): 描述`。
- 一次提交只做一件事；跨包改动（`shared` 接口变更 + 双侧适配）必须同一个提交内完成，保证任何提交点上 `node tools/check-docs.mjs` 都是绿的。
- 每个计划文档对应一个里程碑标签 `M0`…`M9`，完成时打 `git tag M<n>`。
- 变更冻结契约（协议字段、量化规则、数值表 schema、公开函数签名）时：先改对应 ADR，再改代码，最后同步受影响文档。

## 9. 计划文档模板

P01–P10 必须逐节遵守 `docs/00-共识/计划文档模板.md`。该模板定义了九段式章节名与"移交物 ID"标记格式，`tools/check-docs.mjs` 会机器校验：章节齐全、编号连续、移交物与下一份的入口条件字面一致。

## 10. 文档纪律

- 文档是**施工依据**：读者不需要再看代码就能照做。凡是含糊处，视为文档缺陷，必须补。
- 文档只描述**当前与未来**，不写"曾经尝试过"。历史决策进 ADR。
- 不写"待定/TBD"进入冻结契约；确实未决的，写进 `docs/02-需求分析.md` 的开放问题表。
- 每份计划文档的"移交物 ID"与下一份的"入口条件"必须字面一致，由 `tools/check-docs.mjs` 机器校验。

## 11. v2 语言与依赖约定

- **服务端（`server/`）**：C++20；唯一运行时依赖是标准库与系统库（POSIX/WinSock）。UDP 可靠性层、JSON 日志、测试断言框架全部自研。新增任何第三方库（含 header-only）必须先写 ADR。
- **客户端（`client/`）**：C#（Unity 提供版本）；依赖白名单只有 Unity 官方包（URP），输入用内置 Input，UI 文本用系统字体；不开 `unsafe`。
- **跨语言一致性**：模拟与预测只用 [ADR-010](ADR/ADR-010-跨语言确定性与对拍.md) 允许的运算子集（`+ - * / sqrt` 与整数运算），禁用超越函数、fast-math、`-march=native`。
- **命名**：C++ 用 `snake_case` 文件、`PascalCase` 类型、`camelCase` 函数/变量、`kPascalCase` 常量；C# 用 `PascalCase` 类型/属性/方法、`_camelCase` 私有字段。协议字段名与 [ADR-009](ADR/ADR-009-UDP传输与协议重构.md) 的字段表同名。
- **零外部素材**对两端同时生效：仓库不得出现图片/音频/模型/字体文件，`node tools/check-assets.mjs` 是唯一裁判。

## 12. v2 双链纪律

- v2 施工由 `docs/plans-v2/server/S01–S15` 与 `docs/plans-v2/client/C01–C15` 两条链驱动，链内**严格线性**（移交物守恒），跨链依赖只允许"引用顺序表中排在它之前的计划"。
- 顺序表与链数量写在 `docs/plans-v2/README.md` 的 `<!-- chain -->` 与 `<!-- order -->` 注释里，`tools/check-docs.mjs` 机器校验；改链条必须先改那份索引。
- 每份计划**一次会话可完成**：任务清单 ≤ 9 项、预估 1–2 人日；超出即拆成两份并在索引表登记。
- 计划文档只允许链接**当前已存在**的路径；未来创建的代码路径写成行内代码，否则 `check-docs` 判死链。
- v1 的 P01–P10 与 O01–O10 已随 v1 代码一起移出仓库（冻结副本见备份仓库），本仓库只维护 v2 双链；v2 的决策进 ADR-008/009/010 及其后继。
