# 计划文档模板（十份线性计划的强制格式）

P01–P10 必须逐节遵守下面的九段式结构。`tools/check-docs.mjs` 会机器校验本模板要求的**章节标题**与**移交物 ID**。

## 1. 九段式结构

````markdown
# P<NN> <标题>
> 里程碑：M<n> ｜ 预估：<x> 人日 ｜ 上游移交物：HANDOFF-H<NN-1>

## 1. 目标
一段话说明本步骤结束后"能做什么"，而不是"写了什么文件"。

## 2. 入口条件
**入口条件**：HANDOFF-H<NN-1>
逐条列出必须已成立的事实，每条附一条可执行的验证命令。
（P01 的入口条件是 HANDOFF-H00，即仓库起点。）

## 3. 交付物
表格或清单，标注【新建】/【修改】，并写明每个文件的职责。

## 4. 任务清单
有序、可勾选、以动词开头，每项写明产出文件。
禁止出现"优化代码""完善逻辑"这类不可验收项。

## 5. 冻结契约
本步骤固化、后续不得擅改的接口 / 协议字段 / 数值 / 命令 / 数据表 schema。
必须给出 TypeScript 类型或字段表。代码标识符保留英文。

## 6. 验证
可直接执行的命令 + 期望输出；以及需要人工确认的清单（若有）。
每条验证必须写明"失败意味着什么"。

## 7. DoD（验收标准）
可逐条判定的完成标准，必须包含 `pnpm check` 全绿。

## 8. 风险与回滚
表格：风险 → 触发信号 → 对策；以及回滚目标（回滚到哪个可用状态）。

## 9. 移交物
**移交物 ID**：HANDOFF-H<NN>
给出给下一步的稳定接口清单与已验证能力清单。
````

## 2. 线性链的机器可校验规则

1. **编号连续**：`docs/plans/` 下必须恰好存在 `P01`…`P10` 十个文件，不得缺号、重号、插号。
2. **章节齐全**：每份必须含上表九个 `## N. <标题>` 段落，标题字面一致。
3. **移交物守恒**：`P<NN>` 的 §9 中的移交物 ID 必须**字面等于** `P<NN+1>` 的 §2 入口条件中出现的 ID。
4. **无前向依赖**：正文不得引用编号大于自身的计划文档的**实现细节**；引用其"冻结契约"章节是允许的。
5. **链接可达**：文档内所有相对 markdown 链接必须指向真实存在的文件或目录。

## 4. 写作纪律

- 读者是"下一个执行者"（人或 AI）。假设读者只有本套文档，没有口头上下文。
- 每个任务项必须能回答："做完了，我用什么命令证明？"
- 数值、字段、常量一律写死在本套文档里，不写"参考实现"。
- 不可验收的形容词（"流畅""好看""合理"）必须替换为可测量指标（帧时间 P95、快照字节数、误差厘米数）。
- 每份文档完成后，回头补齐上一份 §9 的"已验证能力清单"中实际被本步骤消费的条目。
