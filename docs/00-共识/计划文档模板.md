# 计划文档模板（v2 两条线性计划链的强制格式）

v2 的 30 份计划（`docs/plans-v2/server/S01–S15` 与 `docs/plans-v2/client/C01–C15`）必须逐节遵守下面的九段式结构。`tools/check-docs.mjs` 会机器校验本模板要求的**章节标题**与**移交物 ID**。

> 范围说明：本文件里的示例与登记表沿用 v1 的 P01–P10 记号，仅作**历史对照**（v1 实现与文档已移出仓库，冻结副本在 `D:\projects\tmp\angry-chen-bak`）。v2 的对应记号：服务器链用 `S<nn>` / `MS<nn>` / `HANDOFF-S<nn>`，客户端链用 `C<nn>` / `MC<nn>` / `HANDOFF-C<nn>`；章节结构、移交物守恒与前向依赖规则完全一致。

## 1. 九段式结构

````markdown
# S<NN> <标题>
> 里程碑：MS<nn> ｜ 预估：<x> 人日 ｜ 上游移交物：HANDOFF-S<nn-1>

## 1. 目标
一段话说明本步骤结束后"能做什么"，而不是"写了什么文件"。

## 2. 入口条件
**入口条件**：HANDOFF-S<nn-1>
逐条列出必须已成立的事实，每条附一条可执行的验证命令。
（客户端链把 `S` 换成 `C`、`MS` 换成 `MC`；`S01` 的入口条件是 HANDOFF-S00，即仓库起点。v1 的 `P<NN>`/`HANDOFF-H<nn>` 形式见上面的范围说明。）

## 3. 交付物
表格或清单，标注【新建】/【修改】，并写明每个文件的职责。

## 4. 任务清单
有序、可勾选、以动词开头，每项写明产出文件。
禁止出现"优化代码""完善逻辑"这类不可验收项。

## 5. 冻结契约
本步骤固化、后续不得擅改的接口 / 协议字段 / 数值 / 命令 / 数据表 schema。
必须给出 TypeScript 类型或字段表。代码标识符保留英文。

## 6. 验证
可直接执行的命令 + 期望输出；以及需要人工确认的清单（若有）。
每条验证必须写明"失败意味着什么"。

## 7. DoD（验收标准）
可逐条判定的完成标准，必须包含 `node tools/check-docs.mjs` 与 `node tools/check-assets.mjs` 全绿。

## 8. 风险与回滚
表格：风险 → 触发信号 → 对策；以及回滚目标（回滚到哪个可用状态）。

## 9. 移交物
**移交物 ID**：HANDOFF-S<nn>
给出给下一步的稳定接口清单与已验证能力清单。
````

## 2. 线性链的机器可校验规则

1. **编号连续**：`docs/plans-v2/server/` 下必须恰好存在 `S01`…`S15` 十五个文件、`docs/plans-v2/client/` 下必须恰好存在 `C01`…`C15` 十五个文件，不得缺号、重号、插号。
2. **章节齐全**：每份必须含上表九个 `## N. <标题>` 段落，标题字面一致。
3. **移交物守恒**：同链第 N 份的 §9 中的移交物 ID 必须**字面等于**第 N+1 份的 §2 入口条件中出现的 ID（服务器链 `HANDOFF-S<nn>`、客户端链 `HANDOFF-C<nn>`）。
4. **无前向依赖**：正文不得引用编号大于自身的计划文档的**实现细节**；引用其"冻结契约"章节是允许的。
5. **链接可达**：文档内所有相对 markdown 链接必须指向真实存在的文件或目录。

## 4. 写作纪律

- 读者是"下一个执行者"（人或 AI）。假设读者只有本套文档，没有口头上下文。
- 每个任务项必须能回答："做完了，我用什么命令证明？"
- 数值、字段、常量一律写死在本套文档里，不写"参考实现"。
- 不可验收的形容词（"流畅""好看""合理"）必须替换为可测量指标（帧时间 P95、快照字节数、误差厘米数）。
- 每份文档完成后，回头补齐上一份 §9 的"已验证能力清单"中实际被本步骤消费的条目。

## 5. v2 双链格式（S 链 / C 链）

v2 的两条链（`docs/plans-v2/server/S01–S15`、`docs/plans-v2/client/C01–C15`）沿用 §1 的九段式与 §2 的机器校验规则，另加：

1. **头行**：`> 里程碑：MS<nn> ｜ 预估：<x> 人日 ｜ 上游移交物：HANDOFF-S<nn-1>`（客户端把 `S` 换成 `C`）。
2. **移交物 ID**：链前缀 + 两位序号，S 链 `HANDOFF-S00…S15`，C 链 `HANDOFF-C00…C15`；`S00`/`C00` = v2 起点（本套文档 + `server/`、`client/` 目录就位）。
3. **链内守恒**：第 NN 份的 §9 必须字面等于第 NN+1 份的 §2 首行。
4. **跨链依赖**：索引 `docs/plans-v2/README.md` 的 `<!-- order -->` 给出推荐执行顺序；计划 §2 中提到的任何 `S<nn>`/`C<nn>` 必须排在它自己之前。
5. **一次会话**：任务清单 ≤ 9 项，预估 1–2 人日；超出即拆分并在索引表登记新编号。
6. **链接纪律**：只链接当前已存在的路径；未来路径写成行内代码。
