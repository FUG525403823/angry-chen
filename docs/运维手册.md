# 运维手册（P10 / M9）

本手册覆盖：**发布、回滚、扩容、故障排查、日志与指标速查**，以及 P10 的后续路线图。
适用形态是 ADR-004 冻结的**单机单进程 + 反向代理 + 日志文件 + `/metrics`**。

## 0. 本机环境事实与验证状态图例

| 事实                                   | 证据                                                       |
| -------------------------------------- | ---------------------------------------------------------- |
| 本机 **没有 docker**                   | `docker --version` → `command not found`（ADR-004 背景 1） |
| 本机没有 caddy / nginx / systemd / PM2 | Windows 开发机；`deploy/**` 只能静态审查                   |
| Node v24.14.1、pnpm 11.22.0            | `node --version`、`pnpm --version`                         |
| 服务端零构建产物，用 `tsx` 直跑源码    | ADR-004 §1；`packages/server/src/main.ts`                  |

每条交付物按 P10 §5.5 标注：**已验证**（有可复现命令与输出）、**静态审查**（无环境验证）、
**未验证**。`Dockerfile` / `docker-compose.yml` / `deploy/**` 一律是**静态审查**。

## 1. 系统形态速查

| 项             | 值                                                         | 位置                                                                       |
| -------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| 服务端进程     | 单进程，HTTP 与 WebSocket 同端口                           | `packages/server/src/main.ts`                                              |
| 默认监听       | `127.0.0.1:8787`                                           | `DEFAULT_HOST` / `DEFAULT_PORT`（`main.ts`）                               |
| 健康检查       | `GET /health`                                              | `packages/server/src/http.ts`                                              |
| 指标           | `GET /metrics`（Prometheus 文本）                          | `packages/server/src/metrics.ts`                                           |

| 对战记录       | `DATA_DIR/matches.ndjson`                                  | `packages/server/src/match/store.ts`                                       |
| 单场诊断报告   | `DATA_DIR/reports/<matchId>.json`                          | `packages/server/src/report.ts`                                            |
| 日志           | stdout 的结构化 JSON 行                                    | `packages/server/src/log.ts`                                               |
| 反代样例       | `deploy/Caddyfile`、`deploy/nginx.conf`                    | **静态审查**                                                               |

## 2. 环境变量与 `.env` 加载

变量全集来自 ADR-004；下表是**当前代码真实读取**的位置。

| 变量                   | 默认                            | 读取位置                                  | 说明                                                                                                             |
| ---------------------- | ------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `PORT`                 | `8787`                          | `packages/server/src/main.ts`             | 单端口承载 HTTP 与 WebSocket                                                                                     |
| `HOST`                 | `127.0.0.1`                     | `packages/server/src/main.ts`             | 容器内必须 `0.0.0.0`，宿主只发布回环地址                                                                         |
| `MAX_ROOMS`            | `LIMITS.maxRooms`（64）         | `packages/server/src/main.ts`             | 房间数上限                                                                                                       |
| `MAX_PLAYERS_PER_ROOM` | `LIMITS.maxPlayersPerRoom`（4） | `packages/server/src/main.ts`             | 单房人数上限                                                                                                     |
| `DATA_DIR`             | `./data`                        | `main.ts` → `match/store.ts`、`report.ts` | 生产环境务必用绝对路径                                                                                           |
| `LOG_LEVEL`            | `info`                          | `packages/server/src/log.ts`              | `debug` / `info` / `warn` / `error`                                                                              |
| `ALLOWED_ORIGINS`      | 未设置＝不校验                  | `packages/server/src/security.ts`         | 逗号分隔；`*` 表示关闭校验（仅限本机）                                                                           |
| `TICK_MS`              | —                               | **当前无人读取**                          | ADR-004 保留了该变量，但模拟步长冻结为 `SERVER_TICK_MS = 50`（`packages/shared/src/index.ts`），改它不会改变步长 |

**服务端不会自动加载 `.env`**（仓库没有 dotenv 依赖，`packages/server/src/main.ts` 只读 `process.env`）。
三种让 `.env` 生效的方式：

```bash
# 方式 A（本机 shell，已验证）：加载后再起服务
set -a && . ./.env && set +a && pnpm dev:server

# 方式 B（tsx 直跑，已验证 --env-file 生效）：路径按需替换
pnpm --filter @ac/server exec tsx --env-file=.env src/main.ts

# 方式 C（守护进程）：systemd 的 EnvironmentFile= / PM2 的 env 块，见 §3.2、§3.3
```

复制模板：`cp .env.example .env`；`.env` 已被 `.gitignore` 忽略，仓库不提交任何密钥。

## 3. 部署

### 3.1 裸机直跑（已验证）

```bash
pnpm install --frozen-lockfile
pnpm build:client                      # 产出 packages/client/dist
set -a && . ./.env && set +a && pnpm --filter @ac/server run start
curl -s http://127.0.0.1:8787/health   # {"status":"ok","protocolVersion":1,...}
```

```
{"status":"ok","protocolVersion":1,"rooms":0,"connections":0,"players":0,"ticks":0}
```

### 3.2 systemd（静态审查）

样例：`deploy/angry-chen.service`。要点：专用用户 `angrychen`、`WorkingDirectory=/srv/angry-chen`、
`EnvironmentFile=/etc/angry-chen.env`、`DATA_DIR=/var/lib/angry-chen`、`Restart=on-failure`、
`KillMode=mixed`（让 `main.ts` 的优雅停机收到 SIGTERM）。

```bash
sudo useradd --system --home /srv/angry-chen --shell /usr/sbin/nologin angrychen
sudo install -d -o angrychen -g angrychen -m 0750 /var/lib/angry-chen /var/log/angry-chen
sudo install -o root -g angrychen -m 0640 /dev/null /etc/angry-chen.env   # 内容参照 .env.example
sudo cp deploy/angry-chen.service /etc/systemd/system/angry-chen.service
sudo systemctl daemon-reload && sudo systemctl enable --now angry-chen
journalctl -u angry-chen -n 50 -f
```

### 3.3 PM2（静态审查）

样例：`deploy/ecosystem.config.cjs`（PM2 只支持 CJS 配置，故用 `.cjs` 扩展名）。
PM2 **没有** `EnvironmentFile`：本样例把所有变量写进 `env` 块；也可以用方式 A 先加载 `.env` 再启动。

```bash
pm2 start deploy/ecosystem.config.cjs && pm2 save
pm2 logs angry-chen-server --lines 50
```

### 3.4 Docker / docker compose（静态审查，未构建、未运行）

样例：`Dockerfile`（多阶段：build 阶段装依赖并构建客户端，runtime 阶段只装 `@ac/server`
生产依赖并用 tsx 跑源码）、`docker-compose.yml`（`game` 服务 + `proxy` 服务提供静态资源与 WSS）。

```bash
cp .env.example .env
pnpm build:client                       # proxy 挂载 ./packages/client/dist
docker compose build                    # 静态审查：本机无 docker，未执行
docker compose up -d
docker compose ps
curl -s http://127.0.0.1:8787/health    # game 容器直连探针
```

### 3.5 反向代理（静态审查）

- Caddy：`deploy/Caddyfile`。`reverse_proxy` 自动透传 Upgrade，无需额外配置。
- Nginx：`deploy/nginx.conf`。必须包含 `map $http_upgrade $connection_upgrade` 与
  `proxy_set_header Upgrade` / `proxy_set_header Connection`，否则 WSS 握手失败。
- 客户端默认连 `ws://127.0.0.1:8787`（`packages/client/src/main.ts` 的 `DEFAULT_SERVER_URL`），
  公网必须显式指定：`https://<域名>/?server=wss://<域名>/ws`。
- 静态缓存：`/assets/*` 一年 immutable（文件名带内容 hash）；`index.html` 不缓存。

### 4.1 压测工具用法与阈值（P10 §5.2）

```bash
# bots：4 个无头客户端跑 5 分钟，输出 JSON 报告（阈值判定写在报告里）

  --json docs/evidence/soak-5min.json
```

## 5. 回滚

回滚目标：`HANDOFF-H09`（P10 不改变玩法与协议，回滚只影响运维与压测资产）。

```bash
git fetch --tags
```

## 6. 扩容（本期上限与后续路径）

**本期上限（冻结）**：单机 + 反向代理 + 日志文件 + `/metrics`。
一台机器、一个 Node 进程、一个端口；房间是进程内对象，无跨进程协调（ADR-004 §1）。

| 触发信号                                    | 说明                                | 扩容路径（**文档化，未实现**）                                                      |
| ------------------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------- |
| 单核 CPU 长期 > 30%（soak 报告 / 系统监控） | 4 人 60 羊已接近单核预算            | 换多核机器并开多个 Node 进程，按房间码前缀分片，反代按房间码一致性哈希路由          |
| `ac_rooms` 逼近 `MAX_ROOMS`                 | 进程内房间数上限                    | 提高 `MAX_ROOMS` 前先测内存；再不够则上一步的分片                                   |
| 需要跨机房间列表 / 大厅                     | 当前无跨进程状态                    | 引入 Redis 存房间注册表，`RoomRegistry`（`packages/server/src/rooms.ts`）抽远程实现 |
| 需要账号与云排行                            | 当前只有本地 NDJSON（`MatchStore`） | 实现 `SqliteMatchStore` / `HttpMatchStore` 适配同一接口（ADR-004 §2 的缝）          |
| 需要多房间水平扩展                          | 房间状态必须外置                    | WebTransport 换传输（见 §10）+ 状态外置；属架构级改动，需新 ADR                     |

不在本期：Kubernetes、服务网格、监控栈（Prometheus/Grafana 部署）、多区域。

## 7. 故障排查表

| #   | 症状                                                       | 可能原因                                                                    | 定位（命令或文件）                                                                                                                          | 处理                                                                             |
| --- | ---------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 1   | 起不来，日志 `EADDRINUSE`                                  | 8787 被占用（另一个实例或别的软件）                                         | `netstat -ano \| grep 8787`；`packages/server/src/main.ts` 的 `DEFAULT_PORT`                                                                | `PORT=9000 pnpm dev:server`；客户端用 `?server=ws://127.0.0.1:9000`              |
| 2   | `/health` 返回 `{"error":"not-found"}`                     | 反代把探针请求交给了静态站点                                                | `deploy/nginx.conf` 的 `location = /health`、`deploy/Caddyfile` 的 `handle /health`                                                         | 把具体 location 放在静态兜底（Nginx 的 `location /`、Caddy 最后的 `handle`）之前 |
| 3   | 浏览器控制台 `WebSocket connection failed`、界面反复重连   | 客户端连的是默认 `ws://127.0.0.1:8787`，公网应为 wss                        | `packages/client/src/main.ts` 的 `DEFAULT_SERVER_URL`、`?server=` 参数                                                                      | 打开 `https://<域名>/?server=wss://<域名>/ws`                                    |

| 5   | 日志出现 `security.origin_rejected`，浏览器连不上          | `ALLOWED_ORIGINS` 没包含实际来源                                            | `packages/server/src/security.ts` 的 `parseAllowedOrigins` / `isOriginAllowed`                                                              | 在 `.env` 里补 `ALLOWED_ORIGINS=https://<域名>`（来源不带路径）                  |
| 6   | 玩家频繁被踢，日志 `session.rate_limited`                  | 客户端每秒命令超 60 条                                                      | `packages/shared/src/net/protocol.ts` 的 `LIMITS.maxMessagesPerSecond`；`ac_rate_limited_frames_total`                                      | 排查客户端重复发送（`packages/client/src/net/connection.ts`），不要盲目放宽阈值  |
| 7   | 大帧导致断线（Error 码 4 / 1009）                          | 单帧超过 8192 字节                                                          | `packages/shared/src/net/protocol.ts` 的 `LIMITS.maxFrameBytes`、`packages/server/src/transport/ws-adapter.ts`、`ac_oversized_frames_total` | 确认客户端没有拼接/泄漏大包；阈值属冻结契约，改动需走 ADR                        |

## 8. 日志速查

结构化 JSON 行，字段固定：`ts`（毫秒）、`level`、`evt`、`room`、`tick`、`pid`、`detail`。
`evt` 名与 `LOG_EVENTS`（`packages/server/src/log.ts`）一一对应。

```bash
pnpm dev:server                        # 本机：直接看 stdout
journalctl -u angry-chen -f            # systemd
pm2 logs angry-chen-server --lines 50  # PM2
docker compose logs -f game            # 容器
```

| `evt`                                                                                                 | 何时出现         | 关注点                              |
| ----------------------------------------------------------------------------------------------------- | ---------------- | ----------------------------------- |
| `room.create` / `room.reclaim`                                                                        | 建房 / 空闲回收  | 回收是否生效，配合 `ac_rooms`       |
| `session.join` / `session.leave` / `grace.reconnect`                                                  | 进出房与重连     | 重连成功率                          |
| `session.rate_limited` / `session.join_throttled`                                                     | 限流触发         | 客户端 bug 或攻击                   |
| `malformedFrame` / `frameHandlerError`                                                                | 非法帧/处理异常  | 与 `ac_malformed_frames_total` 对照 |
| `wave.start` / `wave.clear` / `match.start` / `match.end`                                             | 对局流程         | 波次是否卡住                        |
| `illegalTransition`                                                                                   | 非法状态迁移被拒 | 客户端越权请求                      |
| `anticheat.speed`                                                                                     | 姿态校验失败     | 作弊或客户端漂移                    |
| `grace.start` / `grace.reconnect` / `grace.timeout`                                                   | 宽限期           | 掉线恢复能力（AC-06）               |
| `security.origin_rejected`                                                                            | 来源白名单拒绝   | 反代 / 域名配置错误                 |
| `store.error` / `report.write_failed`                                                                 | 落盘失败         | 数据目录权限与磁盘                  |
| `error.uncaught`                                                                                      | 未捕获异常       | **任何一条都是发布阻塞项**          |
| `server.listening` / `server.shutdown_requested` / `server.shutdown_complete` / `server.start_failed` | 进程生命周期     | 起停是否干净                        |

## 9. 指标速查（`GET /metrics`）

Prometheus 文本；前缀 `ac_`。常用排障子集：

```bash
curl -s localhost:8787/metrics | grep -E \
  'ac_(tick_schedule_error_ms_p95|sim_drift_ms|tick_work_ms_p95|snapshot_bytes_avg|rooms|connections|players|grace_active|malformed_frames_total|rate_limited_frames_total|corrupt_lines_total)'
```

| 指标                                                                                         | 含义                       | 阈值 / 期望                 |
| -------------------------------------------------------------------------------------------- | -------------------------- | --------------------------- |
| `ac_tick_schedule_error_ms_p95`                                                              | 调度误差 P95（实际 tick 时刻 − 理想时刻） | ≤ 8ms（O02 起为判据；粒度 >8ms 用替代判据） |
| `ac_sim_drift_ms` / `ac_sim_drift_ms_last`                                                   | 模拟时间与真实时间偏差（近期最大 / 最近一次） | 绝对值 ≤ 50ms 且不随运行时间累积 |
| `ac_tick_work_ms_p95` / `ac_tick_work_ms_p99` / `ac_tick_work_ms_max`                        | 单次 `runTick` 工作量耗时  | 与 `roomTickBudgetMs`（8ms）对齐 |
| `ac_room_budget_exceeded_total`                                                              | 房间因工作量预算让出事件循环的次数 | 偶发正常；持续增长说明单房间 tick 变重 |
| `ac_tick_interval_error_ms_p95` / `ac_tick_jitter_ms_p95`（别名，旧口径）                     | 相邻 tick 间隔误差 P95     | 只作对照，不参与判定        |
| `ac_tick_skips_total`                                                                        | 追赶逻辑跳过的 tick        | 长期 >0 说明 CPU 不够       |
| `ac_snapshot_bytes_avg` / `ac_snapshot_records_avg`                                          | 单快照字节 / 实体记录均值  | ≤ 1200B                     |
| `ac_malformed_frames_total` / `ac_oversized_frames_total` / `ac_rate_limited_frames_total`   | 非法帧 / 超限帧 / 限流帧   | 异常升高＝客户端 bug 或攻击 |
| `ac_rooms` / `ac_connections` / `ac_players`                                                 | 在线规模                   | 与预期一致                  |
| `ac_grace_active`                                                                            | 宽限期内的会话数           | 长期 >0 说明有玩家反复掉线  |
| `ac_client_lag_ticks_avg`                                                                    | 客户端确认 tick 的平均滞后 | 与 RTT 相关                 |
| `ac_hard_correct_total` / `ac_rewind_clamped_total`                                          | 硬纠正 / 回滚夹取次数      | 硬纠正 ≤ 5/分钟/人          |
| `ac_speed_violations_total`                                                                  | 姿态校验拒绝数             | 持续增长＝作弊或预测漂移    |
| `ac_sheep_alive` / `ac_wave_current` / `ac_spawns_total`                                     | 战斗进度                   | 波次是否推进                |
| `ac_shots_fired_total` / `ac_hits_total` / `ac_damage_total`                                 | 射击与伤害                 | 与结算页核对（AC-03）       |
| `ac_joins_total` / `ac_leaves_total` / `ac_rooms_created_total` / `ac_rooms_reclaimed_total` | 进出与房间回收             | 回收数应追上创建数          |
| `ac_corrupt_lines_total`                                                                     | NDJSON 损坏行              | 应长期为 0                  |
| `ac_uptime_seconds`                                                                          | 进程运行时长               | 用于确认重启是否生效        |

## 10. 路线图（P10 §4）

以下方向**不在 MVP 范围内**，按收益排序记录，实施前需各自新增 ADR：

1. **WebTransport / WebRTC 换传输**：解决 TCP 队头阻塞与移动网络抖动；改动集中在
   `packages/server/src/transport/**` 与 `packages/client/src/net/**`，协议编解码可复用。
2. **账号与云排行**：把 `MatchStore`（`packages/server/src/match/store.ts`）换成服务端实现，
   引入登录与排行榜查询；需要新的安全与隐私评估。
3. **掉落与补给（FR-15）**：局内补给点、弹药与医疗包，扩展 `packages/shared/src/config/*` 数值表。
4. **观战与回放**：复用 `packages/server/src/report.ts` 的诊断数据 + 快照日志做时间轴回放。
5. **第二张场地与模式**：`packages/shared/src/config/arena.ts` 参数化，新增 PVE 模式变体。
6. **AI 增强与反作弊深化**：羊群 AI 行为树升级、服务器侧统计式异常检测（基于 §9 的指标基线）。
