# 技术选型 v2

> 本文是 v2 双链计划（`docs/plans-v2/server/S01–S15`、`docs/plans-v2/client/C01–C15`）的**技术前提**。
> 旧栈前提见 `01-技术选型`（已被 [ADR-008](00-共识/ADR/ADR-008-服务端语言与客户端引擎变更.md) 取代，仅作 P01–P10 的历史依据）。
> 每条"实测"都附可执行命令；未实测的判断一律标注"判断"。

## 1. 选型约束（决定性的五条）

| 约束 | 事实依据 | 对选型的影响 |
|---|---|---|
| 要突破性能上限 | ADR-001 自设的复查触发条件（>8 人同局或需要 UDP 语义）已触发 | 服务端换原生语言；客户端离开浏览器 |
| 要突破表现力上限 | v1 客户端受 WebGL2 与 GC 抖动约束（v1 证据 `client-frame-alloc.md` 在备份仓库 `D:\projects\tmp\angry-chen-bak` 的 `docs/evidence/`） | 客户端换真实引擎 + 原生 GPU |
| 玩射击必须有 UDP | v1 用 TCP/WebSocket 只能"模拟"不可靠通道（ADR-002 §TCP 队头阻塞） | 自研 UDP 可靠性层（ADR-009） |
| 零外部素材 | ADR-003 / NFR-07；`node tools/check-assets.mjs` 拦所有图片/音频/模型/字体的扩展名并对受控文件做 NUL 嗅探 | 程序化网格/材质/shader/音频；UI 用系统字体 |
| 计划必须线性可施工 | 工程约定 §10；每份计划一次会话可完成 | 两端各自 15 份线性计划，跨链依赖写进"推荐执行顺序" |

## 2. 选型结论一览

| 层次 | 选择 | 版本 | 一句话理由 |
|---|---|---|---|
| 服务端语言 | C++ | **C++20** | 零 GC、可控内存布局、可上原生剖析器 |
| 服务端构建 | CMake + Ninja（或 MSVC） | CMake ≥3.28 | 跨平台、可接 Linux CI；mingw g++ 15.2 为当前可用兜底（实测存在） |
| 服务端依赖 | **无第三方运行时库** | — | UDP/可靠性/JSON/测试断言全自研；新增需 ADR |
| 客户端引擎 | **团结引擎（Tuanjie）** | **2022.3 线（本机 2022.3.62t16）** | 国内网络条件下 Unity 国际版不可得；同源 2022.3 LTS 内核 + 原生 GPU、实例化、可控帧时间；补丁号与安装路径由 C01 固化并允许实测回写 |
| 客户端渲染 | URP（官方包） | 编辑器随附（离线内置，本机 14.1.x） | 桌面与移动通吃，量级足够；不额外引包 |
| 客户端语言 | C# | 引擎提供版本（2022.3 线 → C# 9 / .NET Standard 2.1） | 不开 `unsafe`；模拟代码遵守 ADR-010 子集 |
| 客户端输入 | 引擎内置 Input | — | 不引 Input System 包，减少依赖面 |
| 客户端 UI 文本 | 系统字体 `Font.CreateDynamicFontFromOSFont` | — | 不导入 TMP Essentials（素材禁令） |
| 网络 | 自研 UDP + 三通道 | 协议版本 `1` | ADR-009 冻结：快照不可靠 / 事件可靠幂等 / 命令可靠有序 |
| 模拟节奏 | 20Hz（`dtMs = 50`） | — | 继承 v1 冻结契约 |
| 确定性 | 双精度 + 受限运算子集 + 对拍向量 | — | ADR-010 |
| 持久化 | v1 NDJSON 语义 + `MatchStore` 缝 | — | S13；数据量小，先文件后 sqlite |
| 可观测 | 结构化 JSON 行日志 + `/metrics` + 单局报告 | — | 继承 v1 形态，S13 重建 |
| 部署 | Linux 单进程 + 反代（`deploy/Caddyfile`、`deploy/nginx.conf` 由 S15【新建】） | — | v2 起点无 `deploy/` 目录；v1 的 Node systemd/PM2 资产留在备份仓库作历史 |
| 旧 TS 实现 | **冻结对照（只读）**（备份仓库的 `packages/` + `tools/`） | 同 HEAD | 提供对拍向量与基准对照（S07/S14）；需要打补丁时在派生副本 `D:\projects\tmp\angry-chen-fixture` 上做 |

## 3. 分层论证

### 3.1 为什么服务端必须是原生语言

v1 每 tick 要做：命令解码 → 模拟 → 快照投影 → 差分编码 → 背压发送。Node 侧这条链的抖动来源是 GC 与事件循环（v1 证据 `soak-5min-o03.md`，在备份仓库的 `docs/evidence/`）。C++ 侧可以把 tick 循环写成"无分配、无额外系统调用"的稳态：容器与缓冲预分配（S05/S12），热路径零 `new`，帧时间下界由内核调度决定而不是 GC。

### 3.2 为什么客户端必须离开浏览器

1. 浏览器拿不到裸 UDP（ADR-009 的动因）。
2. 表现力：实例化羊群、程序化 shader、粒子与后处理在 WebGL2 下受限；团结引擎侧可直接用 URP + GPU 实例化。
3. 工程可验证性：团结引擎有本地构建脚本与 Profiler；v1 的帧时间只能靠 CDP 采样（备份仓库的 `tools/e2e-cdp.mjs`）。

### 3.3 为什么保留旧 TS 实现（而不是删掉）

1. `tools/bots.mjs`、`probe.mjs`、`soak.mjs`、`bench-sim.mjs` 依赖 `packages/server`，删掉即失去基准对照。
2. **对拍向量**由 v1 `packages/shared` 导出（ADR-010），它是跨语言确定性的唯一可信来源。
3. v1 的数值平衡（武器散布、羊群参数）是三轮试玩调出来的，v2 直接继承而不是重新调。

### 3.4 为什么自研 UDP 层而不是 Unity Transport

双端协议必须"同名"：C++ 侧无法实现 Unity Transport 的私有 baselib，因此要么两端都不用，要么放弃 C++ 服务器。自研层的范围被 ADR-009 卡死（1200B 单包上限、三通道、RTO 200ms 起、重传上限 5 次），S04 与 C03 各写一份实现并用同一批字节 fixture 对拍。

### 3.5 为什么「零外部素材」在团结引擎下仍然成立

引擎的默认玩法是「导入素材包」，而本仓库禁止二进制资源。因此 v2 客户端：

- 网格：`Mesh` API 代码生成（羊、枪、场地）。
- 材质/光照：代码创建 `Material`/`Shader`（`.shader` 是纯文本，允许入库）。
- 音频：`AudioClip.Create` 程序化合成（继承备份仓库 `packages/client/src/audio/synth.ts` 的合成配方）。
- 文本：系统字体，不导入 TMP 素材。

失败信号：`node tools/check-assets.mjs` 报"发现第三方素材文件"——意味着有人往仓库里丢了二进制。

## 5. 与 v1 的关系（不变量）

- **不变量**：量化表（ADR-009 承继 ADR-002）、tick 50ms、房间码规则、`MatchPhase` 状态机、宽限期 30s、回滚上限 200ms、术语（CONTEXT）。
- **被替换**：运行时（Node → C++ / 团结引擎）、传输（WebSocket/TCP → 自研 UDP）、工程形态（pnpm workspace → 双工程 + 冻结对照）。
