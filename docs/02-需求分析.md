# 需求分析

> 本文是 v2 两条计划链（`S01–S15` 与 `C01–C15`）的**需求前提**，也是验收的最终依据。文中每条需求都有编号，并在第 11 节给出"需求 → 计划文档"追溯矩阵。

## 1. 产品定位

**一句话**：一款 Windows 桌面端的 1–4 人协作波次生存射击游戏——玩家扮演**愤怒的陈sir**，在被疯草致疯的**羊群**围攻中守住牧场，羊群每一只的额头都带着「问界」标志。

| 项 | 内容 |
|---|---|
| 类型 | 第三人称之外的**第一人称**（FPS）PVE，波次生存 |
| 平台 | Windows 10/11 x64 独立客户端（团结引擎播放器），键鼠 |
| 人数 | 1–4 人协作，服务器权威，房间制 |
| 单局时长 | 15–25 分钟（10 波，可继续无尽） |
| 情绪基调 | 荒诞、爽快、略带黑色幽默（陈sir 越打越怒） |
| 交付形态 | 本地可构建：一条命令产出 C++ 服务器与 Windows x64 客户端；无账号、无付费、无云依赖 |

## 2. 目标用户与场景

| 用户 | 场景 | 诉求 |
|---|---|---|
| 主要用户：2–4 名朋友 | 局域网/公网开黑，语音里互相吐槽 | 掉线能回、一局能打完、结算有乐子 |
| 次要用户：单人玩家 | 一个人守牧场 | 单人难度可通（人数缩放必须生效） |
| 开发者/QE | 回归测试、压测、调参 | 无头可跑、数值表可改、确定性可复现 |

## 3. 核心玩法循环

```
大厅（昵称/房间码/选枪/准备）
   ↓
加载（场地与首批生成点预热）
   ↓
┌─────────────── 对局中 ───────────────┐
│  波次开始 → 清剿羊群 → 击杀累积怒气    │
│      ↑                      ↓        │
│  波间备战（20s，可全员跳过）  ← 本波清空 │
└──────────────────────────────────────┘
   ↓（第 10 波 / 全员倒地 / 主动放弃）
结算（击杀、爆头、命中率、存活时长、排名）
   ↓
回大厅（本地排行榜更新）
```

**爽点设计（需求层面的三条约束）**：

1. **越残越亮**：问界羊/羊王血量下降时额标自发光增强，玩家一眼看出"还剩一口气"。
2. **越杀越怒**：击杀累积怒气，满值可主动激活狂暴，火力与位移同时提升，屏幕语言全程反馈。
3. **越晚越多**：波次预算随波次与人数上升，羊形组队从"咩咩兵"逐步过渡到"冲撞羊 + 问界羊"混编，每 5 波出羊王。

## 6. 关键验收场景（Given-When-Then）

以下场景是端到端验收的**最小集合**，S10/S13 与 C12/C15 必须逐条给出可执行证据。

| ID | 场景 |
|---|---|
| AC-01 | **Given** 服务器已启动、2 个 Windows 客户端已启动，**When** A 创建房间并把房间码告诉 B，B 输入房间码，**Then** 双方在大厅互相看到昵称与准备状态，且房间人数显示 2/4 |
| AC-02 | **Given** 2 人已准备，**When** 房主开始对局，**Then** 双方进入 `playing`，第 1 波在 3 秒内生成，且双方看到的羊的数量与种类一致（允许 ≤1 tick 的时序差） |
| AC-03 | **Given** 一只咩咩兵在准星内且距离 20m，**When** 玩家开火命中，**Then** 服务器权威扣血、客户端显示伤害数字，且**服务器日志中的伤害值与客户端显示一致**（无客户端权威伤害） |
| AC-04 | **Given** 玩家 A 被打至 0 血，**When** 玩家 B 在 3 秒内按住交互键（默认 `E`）且不中断，**Then** A 复起并保留 50% 生命；若 B 中途松手或被打断，则进度在 5 秒后归零 |
| AC-05 | **Given** 玩家连续击杀 10 只咩咩兵，**When** 怒气条充满并按下激活键，**Then** 进入 8 秒狂暴，射速与移速按冻结数值提升，且**同一状态在服务器与所有客户端一致** |
| AC-06 | **Given** 玩家 A 在第 3 波中断网，**When** 20 秒后重新连接，**Then** A 在 30 秒宽限内回到原位置、血量与武器不变，且波次进度未丢失 |
| AC-07 | **Given** 波次 10 清空，**When** 进入结算，**Then** 显示每人的击杀/爆头/命中率/存活时长，并写入 `<data-dir>/matches.ndjson`（S13 的追加式战绩），重启服务后排行榜仍能读到该局 |
| AC-08 | **Given** 150ms 人为延迟，**When** 玩家对着正在冲锋的羊开火，**Then** 命中判定使用回滚补偿（回滚 ≤200ms），且服务器拒绝任何"回滚超限"的命中 |
| AC-09 | **Given** 一只问界羊血量从 100% 降到 10%，**When** 观察其额头，**Then** 额标自发光强度按 `0.2 + 0.8 * (1 - hp/maxHp)` 单调增强（可截图对比） |
| AC-10 | **Given** 恶意客户端发送超长分片组（超过 8 片 / 超过 9408B 逻辑消息）/ 未知 `type` / 每秒 500 条命令，**When** 服务器收到，**Then** 进程不崩溃、不卡顿，非法帧被丢弃并计数，超阈值连接被断开 |

## 7. 数值基线（MVP 冻结值）

> 数值的唯一来源是 v1 冻结副本的 `packages/shared/src/config/*`；v2 双端按本表各自落成 `server/src/config/*.hpp` 与 `client/Assets/Scripts/Config/*.cs`，值必须逐项相同（ADR-010）。

### 7.1 玩家与场地

| 项 | 值 |
|---|---|
| 移动速度 / 疾跑速度 | 4.5 m/s / 6.3 m/s |
| 跳跃初速 / 重力 | 4.8 m/s / 14 m/s² |
| 生命 / 护甲 | 100 / 50（护甲先扣，吸收 60% 伤害） |
| 玩家半径 / 身高 / 眼高 | 0.4 m / 1.7 m / 1.6 m |
| 场地 | 80m × 80m，四周 3m 高围栏，中央谷仓（8m × 8m × 5m）作掩体 |
| 玩家出生点 | 4 个，位于谷仓南侧 |
| 敌人生成点 | 12 个，沿围栏内侧均匀分布 |

### 7.2 武器

| 武器 | 伤害（身体/头） | 射速 | 弹匣 | 换弹 | 散布（度） | 射程衰减 |
|---|---|---|---|---|---|---|
| 手枪 `pistol` | 25 / 50 | 300 RPM（半自动） | 12 | 1.4 s | 0.8 | 无（不随距离衰减） |
| 突击步枪 `rifle` | 20 / 40 | 600 RPM | 30 | 2.0 s | 0.6（连发累积 +0.1/发，上限 0.25） | 无（不随距离衰减） |
| 霰弹枪 `shotgun` | 12 × 8 弹丸 / 18 × 8 | 70 RPM | 6 | 2.6 s | 4.0 | 无（不随距离衰减） |

- **连射散布累积收紧到 0.25°**：原值 +0.6°/发、上限 3.0°，在 45m 处是 ±2.4m 的圆锥 —— 按住左键连射时
  命中率只剩 ~20%（纯模拟回归测试实测——v1 冻结副本里的 `packages/shared/src/combat/longRange.test.ts` 手枪 2/10、步枪 2/12），玩家感知就是
  "打远处的羊怎么还打不到"。收紧后 45m 连射命中率 ≥ 60%（步枪基础散布同时从 1.4° 收到 0.6°）。
- **距离不衰减**（三把武器 `falloffPerM = 0`）：竞技场 80m × 80m、敌人沿围栏内侧生成，常见交战距离
  20–45m。三轮试玩先减半斜率（-4%/-3%/-7.5% + 50% 伤害下限）后玩家仍反馈"有效射程还是太近"，
  于是追加关闭距离衰减：**场内任何距离命中都是满伤害**。射线最大距离 160m（场地对角线 ≈113m）；
  衰减公式与下限常数仍保留在 v1 配置（备份仓库 `packages/shared/src/config/weapons.ts` / `config/combat.ts`），要重新调参只改斜率即可。

|---|---|---|---|---|---|---|

### 7.4 波次与难度缩放

- 波次预算：`budget(wave) = round(6 + 3.2 * wave + 0.18 * wave^2)`。
- 人数缩放：`budget *= (1 + 0.35 * (playerCount - 1))`，羊的移动速度额外 `* (1 + 0.02 * (playerCount - 1))`。
- 波间：20 秒；全员按准备可跳过，最少等待 5 秒。
- Boss 波：`wave % 5 == 0`。
- 第 10 波结束后进入 `ended`；可选"继续无尽"（P2）。

| 爆头加成 | ×2 |
| 满值 | 100 |
| 狂暴持续 | 8 s |

## 8. 范围边界

**MVP 内（v2 双链 `S01–S15` 与 `C01–C15` 必须交付）**：FR-01…FR-14 中除 P2 外的全部；一张场地；三把武器；四种羊形；十波 + 结算 + 本地排行榜；程序化视听；单进程部署与运维手册。

**明确不做（写进路线图的理由）**：

| 不做的事 | 理由 |
|---|---|
| PVP、排位、赛事 | 与项目定位（协作 PVE）冲突，且需要完全不同的平衡与反作弊投入 |
| 账号系统、云存档、云端排行榜 | MVP 的持久化需求只有"本地战绩"；引入账号会连带出安全、隐私、运维三条线 |
| 多张地图与自定义工坊 | 一张场地已足以验证全部玩法与网络；内容扩张属于发布后运营 |
| 掉落系统、经济与商店、武器改装 | 会牵动数值平衡与 UI 工作量，收益低于先把核心循环做扎实 |
| 观战、回放、录像导出 | 需要额外的状态与权限模型；`Snapshot` 结构已为将来回放留了可能 |
| 移动端与手柄 | 第一人称射击在触屏上没有可接受的输入方案 |
| 语音聊天 | 用户自会用第三方语音；自研语音是巨大的额外系统 |
| 反作弊（内存篡改、自动瞄准检测） | 服务器权威 + 输入校验（NFR-05）已覆盖 MVP 威胁模型；深度反作弊不进 MVP |
| Docker 构建验证 | 本机无 docker，无法验证；只交付静态审查过的可选产物 |
