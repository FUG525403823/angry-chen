# P02 核心模拟内核

> 里程碑：M1 ｜ 预估：1.5 人日 ｜ 上游移交物：HANDOFF-H01

## 1. 目标

本步骤结束后，**不用打开浏览器**就能跑完一局模拟：给定种子与命令序列，`stepWorld` 把世界以固定 50ms 步进推进，`snapshotWorld` 把世界投影成可序列化的快照；同种子同命令跑两次，快照逐位一致。这一步是后续所有网络与渲染逻辑的共同底座——服务器权威、客户端预测、无头压测机器人此后都调用同一份代码。

## 5. 冻结契约

### 5.1 固定 tick 顺序（后续步骤只能往既有槽位里加内容，不能改顺序）

```
1. 应用输入命令（sanitize → 写入实体意图）
2. AI / 意图求解（P07 填充）
3. 移动积分（速度 → 位置）
4. 碰撞与边界（玩家 vs 静态几何、实体间分离）
5. 战斗与投射物（P06 填充）
6. 事件产生（把本 tick 的既成事实写入 world.events）
7. 快照投影（由调用方在 stepWorld 之后显式调用 snapshotWorld）
```

### 5.2 `Entity`（字段名冻结）

```ts
export interface Entity {
  readonly id: EntityId;        // uint16，0 保留为无效
  active: boolean;
  kind: EntityKind;             // 'player' | 'sheep' | 'projectile' | 'pickup'
  pos: Vec3;                    // 米，Y-up
  vel: Vec3;                    // m/s
  yaw: number;                  // 弧度
  pitch: number;                // 弧度，仅玩家
  hp: number;                   // 绝对值（快照编码时才转百分比）
  maxHp: number;
  armor: number;                // 仅玩家
  state: number;                // 语义由 kind 决定（见 P07/P06 的状态枚举表）
  team: 0 | 1;                  // 0 = 玩家阵营，1 = 羊阵营
  ownerId: EntityId;            // 投射物/召唤物归属，0 表示无
  aliveMs: number;              // 存在时长，毫秒
}
```

### 5.3 `Command`（客户端上行意图；字段冻结，P03 起编码）

```ts
export interface Command {
  seq: number;        // uint16，单调递增，回绕
  tick: number;       // 客户端认为的目标 tick（服务器仅用于诊断）
  moveX: number;      // -1..1 前后；不再出现第二套左右轴命名
  moveY: number;      // -1..1 左右
  yaw: number;        // 弧度
  pitch: number;      // 弧度
  buttons: number;    // 位域：1=开火 2=疾跑 4=跳跃 8=换弹 16=交互 32=激活狂暴 64=切换武器
  switchTo: 0 | 1 | 2; // 0=手枪 1=步枪 2=霰弹枪，仅当 64 位为 1 时有效
}
```


**命令与玩家槽位映射（冻结）**：`stepWorld(world, commands, dtMs)` 的 `commands[i]` 对应第 i 个玩家实体（按 id 升序）。命令数组短于玩家数时，缺少命令的玩家本 tick 速度置 0；P03 的每连接队列必须按此顺序组装。
### 5.4 `Snapshot`（跨进程与网络传输的**唯一**投影；字段冻结）

```ts
export interface SnapshotEntity {
  id: EntityId;
  kind: EntityKind;      // 1 字节
  flags: number;         // 位域：`SNAPSHOT_FLAG.downed=1 / rageMode=2 / reloading=4 / charging=8 / fading=16`
  x: number; y: number; z: number;   // 米，float（编码时才量化）
  yaw: number; pitch: number;        // 弧度
  hpRatio: number;       // 0..1
  state: number;
}
export interface Snapshot {
  tick: number;
  serverTimeMs: number;
  readonly entities: SnapshotEntity[];   // 按 id 升序，保证确定性
}
```

**缓冲所有权（冻结）**：复用池归属调用方长期持有的 `Snapshot` 实例本身——同一个 `out` 跨 tick 复用同一批 `SnapshotEntity` 对象，不同 `out` 互不干扰。因此稳态零分配的前提是复用同一个 `out`；每 tick 新建 `out` 会重新分配整池（P03 的每连接快照缓冲必须长期持有）。

### 5.5 常量与容量

`SERVER_TICK_MS = 50`、`MAX_ENTITIES = 1024`、`SNAPSHOT_MAX_ENTITIES = 256`（超出则只发最近的 256 个，并在 `Snapshot` 上记录 `truncated: true`）。

### 5.6 数据表示决策

实体采用 **AoS（普通对象 + 对象池）**，不用 SoA 类型化数组：在"4 人 + 60 羊 @20Hz"的规模下 AoS 的缓存与 GC 代价可忽略，而可读性与可测性显著更好。若将来实体数超过 512 且帧时间超标，再迁移到 SoA（迁移只影响 `world.ts` 与 `snapshot.ts`，因为 `sim` 只通过访问器读写）。

### 5.7 `SimEvent`（事件通道；字段冻结）

```ts
export interface SimEvent {
  type: string;          // 事件类型标识，取值由 P06/P07 追加
  tick: number;
  subjectId: EntityId;   // 0 表示无主体
  targetId: EntityId;    // 0 表示无目标
  x: number; y: number; z: number;
  value: number;         // 数值载荷（伤害、怒气、拾取数量）
}
```

`world.events` 每个 tick 由 `stepWorld` 先清空，只写入本 tick 的既成事实；P03 按 tick 编码下发，客户端仅用于表现层（音效/特效/飘字），不参与命中判定。该数组由世界持有并复用，写入方不得保留其引用。

## 7. DoD（验收标准）

1. `pnpm check` 全绿。
2. §6 第 1 条的 `determinism` 用例存在且通过：同种子 + 同命令序列跑两次，快照逐字节一致。
3. `snapshotWorld` 在稳态下不分配新对象（复用外部缓冲），由 §6 第 5 条确认。
4. 实体池可通过 `MAX_ENTITIES` 上限压力测试：请求第 1025 个实体返回 `{ ok: false, reason: 'entity-pool-exhausted' }` 且世界不损坏。
5. `shared` 覆盖率达到 80%。
6. 所有常量、数值表集中在 `shared/src/config/`，业务代码内无散落魔法数字（由 lint 的 `no-magic-numbers` 白名单外的检查或代码审查确认）。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 浮点不确定性（不同 JS 引擎/优化路径） | `determinism` 用例在客户端与服务器上结果不同 | 内核只用 `number` 与整数毫秒；禁用 `Math.fround`；不依赖 `Math.hypot` 等实现差异函数，改用手写 `sqrt(a*a+b*b)` |
| 在 1024 个实体槽位上做 O(n²) 遍历 | `--trace-deopt` 显示 `resolveEntitySeparation` 在 3000 tick 内去优化 197 次（OSR 退出），稳态仍新增约 30 B/tick | 对策（已验证）：世界维护 id 升序的稠密活动表 `activeIds`，各阶段只遍历活动实体，复杂度降为 O(活动数²)，去优化降至 5 次/3000 tick |
| 用 `heapUsed` 直接判定“每 tick 新增对象”会误报 | 同一份代码在 -26 与 +70 B/tick 之间跳动；GC 事件数与实际分配量不成比例 | 改用 A/B 对照 + 测量后强制 GC 读保留量：`tools/check-alloc.mjs`，并以对照组证明探针灵敏度 |
| 逐帧分配导致 GC 抖动 | §6 第 5 条不达标 | 快照缓冲改为调用方持有；向量运算提供 `into` 变体 |
| 配置表结构在后期演变 | P06/P07 需要新字段 | 配置表加字段允许，但删除/改名必须走 ADR 并同步协议 |
| 碰撞算法复杂度蔓延 | 每 tick 耗时随实体数超线性增长 | 本步只用静态几何（AABB）+ 实体间 O(n²)（n ≤ 80 可接受）；P07 若引入羊群分离力，仍保持 O(n²) 但在 100 只以内 |

**回滚目标**：`HANDOFF-H01`（骨架）。删除 `packages/shared/src/{math,rng,world,sim,snapshot,command,config}` 即可回到 P01 结束态；协议与客户端尚未依赖它。

## 9. 移交物

**移交物 ID**：HANDOFF-H02

稳定接口与能力清单：

1. `createWorld(seed, cfg)` / `stepWorld(world, commands, dtMs)` / `snapshotWorld(world, out?)` 三个公开函数。
