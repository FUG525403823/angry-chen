> 里程碑：M5 ｜ 预估：2 人日 ｜ 上游移交物：HANDOFF-H05

## 1. 目标

本步骤结束后，**在浏览器里可以真正打死羊**：三把武器各有手感（半自动手枪、连发步枪、霰弹枪），有后坐、散布、弹匣与换弹；命中分部位并受距离衰减；玩家会掉血、会倒地、可被队友按住 F 救起；击杀累积怒气，满值可主动激活 8 秒狂暴。所有伤害数字都是**服务器权威**的——客户端只负责乐观表现。

## 5. 冻结契约

### 5.1 权威性铁律

1. 伤害与死亡只由服务器产生；客户端**不得**上报命中。
2. 客户端的伤害数字必须来自 `playerHit` 事件（事件 1），不得由本地射线自算。
3. 弹药与换弹由服务器扣减与计时；客户端 UI 可乐观显示，但每次收到 `MatchState`/事件后必须以权威值校正。
4. 射速超发（一 tick 内超出武器允许的发射次数）直接丢弃多余的开火，不累计到下一刻。

### 5.2 `WeaponState`（追加到 `Entity`，字段冻结）

```ts
export interface WeaponState {
  slots: readonly [WeaponSlot, WeaponSlot, WeaponSlot]; // 0=pistol 1=rifle 2=shotgun
  activeSlot: 0 | 1 | 2;
  magInSlot: [number, number, number];   // 当前弹匣
  reserveAmmo: number;                   // 共享备弹，初值 120
  reloadEndsAtMs: number;                // 0 表示未在换弹
  nextFireAllowedAtMs: number;           // 射速节流时间戳（世界内时间，非 Date.now）
  spreadDeg: number;                     // 当前散布（连发累积、停火衰减）
}
```

### 5.3 武器数值表（= 需求 §7.2，此处为实现的唯一真源）

```ts
  rifle:   { damage: 20, pellets: 1, rpm: 600, auto: true,  mag: 30, reloadMs: 2000, spreadDeg: 1.4,  falloffStartM: 40, falloffPerM: 0.06, headshotMultiplier: 2.0 },
  shotgun: { damage: 12, pellets: 8, rpm: 70,  auto: false, mag: 6,  reloadMs: 2600, spreadDeg: 4.0,  falloffStartM: 12, falloffPerM: 0.15, headshotMultiplier: 2.0 },

```

### 5.4 伤害公式（冻结）

```
damage = base
       × headshotMultiplier            (命中头部子段时)
       × max(0.2, 1 - falloffPerM × max(0, distanceM - falloffStartM))
       × (rageMode ? 1.3 : 1.0)
armorDamage = damage × 0.6 × (armor > 0 ? 1 : 0)     // 护甲先扣，吸收 60%
hpDamage    = damage - armorDamage
```

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 射速节流与 tick 折算误差导致"打不出子弹" | 手动测试中步枪 1 秒明显少于 10 发 | 节流用 `nextFireAllowedAtMs` 累积式（而非按 tick 计数上限），并在单测里断言 1 秒 ≥ 9 发 |
| 回滚命中与羊的移动速度冲突 | 冲锋羊被"打空"抱怨 | 回滚上限 200ms 已冻结；若观感仍差，先查羊的插值延迟是否与回滚时长匹配 |
| 客户端乐观表现掩盖服务器拒绝 | 玩家看到命中却没有伤害 | 命中标记**只**由事件驱动；本地曳光与服务器命中标记视觉区分（本地用短曳光，服务器命中才出十字标记） |
| 数值平衡失衡 | 单人第 3 波即无法通过 | 数值集中在 `config/combat.ts`；用 P10 的无头机器人跑胜率基线再调 |
| 弹药经济导致后期无弹可用 | 波间总是缺弹 | 备弹初值 120 与波间补满策略（P08 的备战阶段）作为调参入口 |
