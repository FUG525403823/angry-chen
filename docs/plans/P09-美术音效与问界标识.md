# P09 美术、音效与"问界"标识

> 里程碑：M8 ｜ 预估：3 人日 ｜ 上游移交物：HANDOFF-H08

## 1. 目标

本步骤结束后，游戏**看起来与听起来像一个成品**：灰盒变成低多边形风格化牧场；每只羊额头都有程序化绘制的「问界」标识，问界羊与羊王的额标随血量下降而更亮（"越残越亮"）；第一人称有手臂与武器动作；开火有枪口火焰、曳光、弹孔、毛屑；音效全部由 WebAudio 合成（枪声、羊叫、命中、冲锋警报、UI）；HUD 与大厅统一视觉主题，并提供色盲安全与减少动态两项可访问性开关。仓库仍然零外部素材。

## 5. 冻结契约

### 5.1 额标规范（冻结，回应 FR-09 与 NFR-10）

| 项 | 值 |
|---|---|
| 载体 | 128×128 `CanvasTexture`，透明背景 |
| 构成 | 菱形外框（描边 6px）+ 居中问号笔画 + 底衬圆环，全部由代码绘制 |
| 贴放 | 羊头部前侧独立面片，尺寸 0.22m × 0.22m（羊王 0.36m × 0.36m） |
| 颜色 | 主色 `#e8e8f0`；自发光色 `#7ad1ff`（羊王改 `#ff8a4c`） |
| 自发光强度 | `emblemIntensity(hpRatio) = 0.2 + 0.8 * (1 - hpRatio)` |
| 平滑 | 强度变化带 0.3 秒时间常数，避免血量骤变时闪烁 |
| 合规 | 不含任何真实商标图形、字体或品牌名称；不使用外部图片 |

### 5.2 HUD 与状态呈现规则（冻结）

| UI 元素 | 数据来源 | 呈现规则 |
|---|---|---|
| 准星扩散 | `WeaponState.spreadDeg`（P06） | 映射 0.5°–5° → 4px–24px |
| 血条/护甲 | 本地玩家 `hpRatio` + 护甲 | 受伤后 0.8 秒残影（第二层红条缓慢追上） |
| 弹药 | `WeaponState.magInSlot[activeSlot]` + `reserveAmmo` | 低于 30% 变黄，空弹匣变红并脉动 |
| 换弹进度 | `reloadEndsAtMs` | 准星下方环形进度 |
| 怒气条 | `rage` | 未满：蓝白；满值：橙色脉动 + 提示键位；狂暴中：倒计时边缘高亮 |
| 波次条 | `MatchState.wave` | 10 段，Boss 波段落标记 |
| 击杀提示 | 事件 2 `sheepKilled` | 右上滚动，爆头加图标，3 秒淡出 |
| 伤害数字 | 事件 1 `playerHit` | 命中点漂浮，爆头更大更亮；**不本地自算** |
| 倒地/救援 | 事件 5/6/7 | 全屏灰化 + 底部救援进度环（仅救援者可见进度） |
| 冲锋预警 | 羊 `state == windup` | 地面红环扩散 + 音效（由 `fx` 流触发，不影响模拟） |

### 5.3 性能预算（冻结，回应 NFR-01）

| 项 | 上限 |
|---|---|
| draw call | ≤ 120（稳态、40 实体） |
| 三角面 | ≤ 180k |
| 粒子并发 | ≤ 256 |
| 同时发声 | ≤ 24 |
| 材质实例 | ≤ 24（共享为主） |
| 帧时间 P95 | ≤ 20ms（1080p、像素比 ≤1.5） |

### 5.4 音频与可访问性（冻结）

| 项 | 值 |
|---|---|
| `AudioContext` 创建时机 | 首次用户交互（点击"进入"按钮）之后 |
| 音量总线 | `masterGain` → `sfxGain`（0.8）/ `uiGain`（0.5） |
| 3D 定位 | `PannerNode`，`refDistance 3`、`maxDistance 40`、`rolloffFactor 1.4` |
| 色盲安全 | 蓝橙对比调色板；不依赖红绿区分敌我与危险度（羊的危险度同时用轮廓粗细与额标亮度表达） |
| 减少动态 | 关闭屏幕抖动、暗角脉动、粒子高频抖动；保留所有影响判定的视觉信息 |
| 字幕 | 关键音效（冲锋预警、波次开始、倒地、胜负）在屏幕上给出文字提示 |

## 5.5 实现澄清与披露（P09 执行期）

1. 零外部素材策略保持：所有贴图由 canvas 程序化绘制（`emblem.ts` / `arenaArt.ts` / `particles.ts`），所有音效由 WebAudio 合成（`audio/synth.ts` + `sfx.ts`），未新增任何 npm 依赖（`git diff M7 -- package.json pnpm-lock.yaml packages/client/package.json` 为空）。
2. 额标自发光管线 = `CanvasTexture`（`getEmblemTexture()` 单例）+ 逐实例自发光属性（`instanceEmissiveTint` / `instanceEmissiveIntensity`，`InstancedBufferAttribute`）+ `materials.emblem.onBeforeCompile` 注入 `applyEmblemShaderPatch`。补丁在片元做 `totalEmissiveRadiance *= vEmissiveTint * vEmissiveIntensity`，因此材质的 `emissiveIntensity` 必须 > 0，否则零乘后额标全黑；评审恰好抓到这一点，现已修复为 `emissiveIntensity: 1` 并加回归测试（`materials.test.ts` 断言 > 0）。
3. `render/**` 不得 import `@ac/shared`（eslint `no-restricted-imports` 强制），因此 `render/entityViews.ts` 的 `SNAPSHOT_FLAG_DOWNED` 是共享标志位的本地镜像；`test/entityViewsFlags.test.ts` 断言镜像值等于 `SNAPSHOT_FLAG.downed` 且不等于 `rageMode`（防漂移成 2）。
4. 客户端测试命令是 `pnpm exec vitest run --project client`：`@ac/client` 没有 `test` 脚本（只有 dev/build/preview），所以 `pnpm --filter @ac/client test` 是静默 no-op，不产生任何用例结果。
5. 模块级缓存的 `CanvasTexture` 从不释放：`getEmblemTexture()` 与 `getSoftDotTexture()` 各自单例缓存；`materials.dispose()` 只 `material.dispose()`，`particles.dispose()` 只释放 geometry/mesh，都不释放这两张纹理（`resetEmblemTexture()` 仅测试调用）。
6. 以下评审发现为**有意暂不修复**，本次执行明确披露（不计入本步骤 DoD）：

   1. 每帧仍有分配：`render/entityViews.ts` 的 `SheepInstance` / `ChargeWarning` 对象字面量、`render/effects.ts` 每帧 `new Set()`、`audio/mixer.ts` 的 `{ ...DEFAULT_LISTENER }` / `{ ...pose }` 展开、`main.ts` 帧体内的 `views.sync((id, state) => …)` 箭头闭包。
   2. 手写数学在渲染模块间重复：`mergeParts` / `boxPart` / `withShade`（`entityViews.ts` / `sheepModel.ts` / `arenaArt.ts` 各一份）、`hashFloat`（`particles.ts`）、`clamp01` 与指数平滑（`emblem.ts`）。
   3. 魔数未集中：`MATERIAL_BUDGET` 在 `render/materials.ts` 与 `ui/debugPanel.ts` 各定义一次；256 粒子上限在 `render/particles.ts`（`PARTICLE_CAPACITY`）与 `ui/debugPanel.ts`（`PARTICLE_BUDGET`）各一份。
   4. `net/sheepVisual.ts` 只能从 `entity.state` 反推羊形，因为快照里没有 `sheepKind` 字段。
   5. 护甲条是死 UI：护甲不在线上协议里，`main.ts` 恒传 `armorRatio: undefined`，HUD 只走 `display: none` 分支。
   6. 倒地灰化只作用于覆盖层的 `backdrop-filter`（`styles.css` 的 `.hud-downed`：`saturate(0.25) grayscale(0.4)`），并没有真的给 3D 场景去色。
   7. `settings/store.ts` 把 `sfxVolume` 加进了冻结的 `ac.settings.v1` 结构，但没有配套修订 P04 文档（P04 §5.5 的字段表仍只有 sensitivity/fov/masterVolume/colorblindSafe/reduceMotion 五项）。
   8. 色盲安全模式只切换调色板（`styles.css` 的 `.colorblind-safe` 改写 `--hud-accent/--hud-danger/--hud-warn/--hud-rage/--hud-rage-full/--fx-blood`）与额标亮度，没有为危险度提供"轮廓粗细"这第二视觉通道（§5.4 承诺的该项未落地）。
