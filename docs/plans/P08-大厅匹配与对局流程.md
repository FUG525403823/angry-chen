## 5. 冻结契约

### 5.1 `MatchPhase` 与合法迁移（唯一真源）

```
0 lobby · 1 loading · 2 playing · 3 intermission · 4 ended

lobby        → loading
loading      → playing
playing      → intermission | ended
intermission → playing | ended
ended        → lobby
```

任何其它迁移必须返回 `{ ok: false, reason: 'illegal-transition' }`，并在服务器日志中以 `level: warn` 记录（含当前阶段与请求阶段）。

### 5.2 断线宽限期规则（冻结，回应 R-08）

| 项 | 值/行为 |
|---|---|
| 宽限时长 | 30000ms（从连接关闭时刻起算） |
| 宽限期内实体 | 保留在原位、速度清零、受 `flags` 标记为"待机"，**不参与羊的目标选择**，也不受伤害 |
| 宽限期内名额 | 仍占用房间名额（新玩家不能顶替） |
| 重连识别 | 房间码 + 昵称（区分大小写）完全一致 → 复用原 `pid` 与实体、血量、武器、怒气 |
| 重连后状态 | 生命恢复到至少 50%（防止"回来即死"），其余状态原样 |
| 超时 | 移除实体、释放名额、广播 `MatchState`；其统计仍计入本局结算（标注"中途离开"） |
| 全员断线 | 房间保留 60 秒后回收 |

### 5.3 复活与复苏规则（冻结）

| 场景 | 行为 |
|---|---|
| 倒地 | 生命归零 → `downed`，不可移动、不可开火、可被救援（P06 已实现） |
| 救援 | 队友 2m 内按住交互 3 秒 → 以 50% 生命复起；被打断则进度 5 秒后归零 |
| 波次清空 | 所有倒地者以 50% 生命复苏（无需救援） |
| 波间/新波开始 | 全体玩家生命补满 100%、护甲补满 50、备弹补满、怒气归零 |
| 主动重生 | 不允许；倒地后只能等救援或波次清空（`Respawn` opcode 仅在大厅/加载阶段有效） |

### 5.4 `MatchStore` 接口与记录 schema（冻结）

```ts
export interface MatchResultRecord {
  matchId: string;         // 房间码 + 起始时间戳（服务器本地时钟）
  startedAtMs: number;
  durationMs: number;
  waveReached: number;
  winnerTeam: 0 | 1;       // 0 = 玩家阵营胜，1 = 羊阵营胜
  playerCount: number;
  players: Array<{
    name: string;
    kills: number;
    headshots: number;
    shotsFired: number;
    hits: number;          // 派生：accuracy = hits / max(1, shotsFired)
    revives: number;
    downs: number;
    aliveMs: number;
    leftMidMatch: boolean;
  }>;
}

export interface MatchStore {
  appendMatchResult(record: MatchResultRecord): Promise<void>;
  listTopScores(limit: number): Promise<MatchResultRecord[]>;   // 按 players[].kills 最大值降序
  getRecentMatches(limit: number): Promise<MatchResultRecord[]>; // 按 startedAtMs 降序
}
```

落盘位置：`DATA_DIR/matches.ndjson`（默认 `./data`），每行一个 JSON 对象，UTF-8 + `\n`。读取时单行解析失败则跳过并计入 `corruptLines`。

### 5.7 实现澄清与披露（P08 执行期）

1. `MatchPhase` 编号重排：`packages/shared/src/net/protocol.ts` 原有 4 值 `MATCH_PHASE`（`lobby=0`、`intermission=1`、`playing=2`、`ended=3`）。P08 将其**重编号**为 5 值（`lobby=0`、`loading=1`、`playing=2`、`intermission=3`、`ended=4`），唯一真源移到 `packages/shared/src/match/phase.ts`，`protocol.ts` 改为再导出。重编号使 `0x84 MatchState.phase` 字节语义改变（旧 1/2/3 = intermission/playing/ended，新 1/2/3 = loading/playing/intermission），与 M6 旧客户端**不线兼容**；`playing=2` 恰好不变，`loading` 为新增值。
2. 30s 断线宽限期表示：**不占用 `flags` 位**。`Entity` 新增布尔字段 `idle`（`packages/shared/src/world.ts`），会话用 `Session.disconnectedAtMs` 记录断开时刻，时长常量 `GRACE_PERIOD_MS = 30000`。实体置 `idle = true` 后从羊/导演目标集合排除（`packages/shared/src/sim.ts`、`packages/server/src/room.ts`），并映射到快照旗标 `SNAPSHOT_FLAG.idle = 32`。
3. 结算写入：`packages/server/src/match/controller.ts` 的 `endMatch` → `deps.store.appendMatchResult`，落 `<dir>/matches.ndjson`；`DATA_DIR` 默认 `./data`（`DEFAULT_DATA_DIR`，`main.ts` 用 `env.DATA_DIR ?? DEFAULT_DATA_DIR`）。
4. 损坏行计数：`JsonMatchStore.load()` 逐行 `trim` 后跳过空行；`JSON.parse` 失败或未通过 `isMatchResultRecord` 结构校验的行计入 `corruptLines`，并写入 `metrics.corruptLines`（指标 `ac_corrupt_lines_total`）。
5. 新增指标名：`ac_grace_active`（gauge，宽限期内会话数）、`ac_matches_finished_total`（counter）、`ac_corrupt_lines_total`（counter）。
6. 聊天连线布局修复：测试中发现 `encodeChatMessage` 把 payload 写在偏移 3，随后 `putU8(out, 3, length)` 又把该 payload 首字节覆盖成长度。现改为 payload 从偏移 4 起、长度在偏移 3，总长 `4 + length`；`decodeChatMessage` 对应按偏移 3 读长度、偏移 4 读 payload。
7. 未实现 / 未验证（诚实披露）：
   - `packages/client` 的 P08 交付物全部未落地：`src/ui/lobby.ts`、`src/ui/intermission.ts`、`src/ui/results.ts`、`src/ui/chat.ts` 不存在；`src/net/connection.ts` 未改动，没有 `ac.nickname.v1` / `ac.lastRoomCode.v1` 持久化，也无"回座后按房间码自动 `Join`"（现有重连仅复用 URL `?room=` 参数）。
   - §6 第 4–7 行的手动浏览器验收（AC-01/AC-02/AC-06/AC-07）**全部未执行**。
   - `ALL_DISCONNECTED_RECLAIM_MS = 60000` 已导出但无任何引用；"全员断线 60s 回收"实际走 `LIMITS.emptyRoomReclaimMs = 60000` + `roomIsIdle`。

## 5.8 双轴评审结论与未修清单（P08 执行期）

评审在固定点 M6 上对本次改动做了标准轴与规格轴审查，结论与处置如下。

已核对通过：§5.1 的 5×5 迁移矩阵（7 条合法 / 18 条非法）、§5.2 的 30 秒宽限期（10 秒重连保留 pid 与实体、31 秒回收并释放名额、待机实体被羊 AI 与伤害链路忽略）、§5.3 的复苏与补满、§5.4 的 MatchStore 与 NDJSON 追加/跳损坏行、§5.6 的两个只读接口、房主转移、错误码 3/6/7/9。

未修（按严重度，留作下一步首要项）：
1. 高：MatchState.hostId 没有进线格式——encodeMatchState/decodeMatchState 都没有序列化它，客户端解出来恒为 0，房主永远看不到「开始」按钮，AC-01 在浏览器里走不通。修法是给 MatchState 头加一个 hostId u16 并把 P03 §5.3 的冻结布局同步修订；本次为避免在上下文不足时改坏冻结线格式而没有动它。
2. 中：ac_corrupt_lines_total 在生产路径恒为 0——main.ts 构造 JsonMatchStore 时没有注入 metrics。
3. 中：全员断线的房间实际约 90 秒才回收（30 秒宽限 + 60 秒空房回收），与 §5.2 的「60 秒」不一致；ALL_DISCONNECTED_RECLAIM_MS 目前导出但未被使用，也没有对应用例。
4. 低：非法迁移的 warn 日志路径存在但没有用例覆盖；同阶段自迁移会被 controller 的短路跳过因而不会记日志。
5. 低（代码评审，标准轴）：Room.phase / MatchState.phase 仍声明为 number 并靠 as MatchPhase 转换；MatchState 的 hostId 与 loadingMs、matchState.* 状态分散在 room 与 controller 两处；房间广播的「跳过断线连接」循环重复了 4 处；match store 写入失败用了字符串拼接而不是 formatLogLine 的单行 JSON；MATCH_PHASE_NAMES 是与 MATCH_PHASE 平行维护的列表；store.ts 用 String.fromCharCode(10) 当换行；rooms.ts 的空房回收重复实现了 removeMember 的清理；createMatchStatePlayer / resetPlayerMatchStats / ALL_DISCONNECTED_RECLAIM_MS 暂无生产调用方；removeMember 的 leftMidMatch 形参未被读取；P02 §5.4 与 P03 §5.3/§5.8 的文档尚未同步新增的 idle 标记、阶段编号与 0x87 聊天帧。
6. 已修：聊天帧 encodeChatMessage 的越界写（先把正文写在偏移 3，又把长度写回偏移 3，导致首字节被覆盖、中文乱码），已改为正文写在偏移 4。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 宽限期语义模糊导致"幽灵玩家" | 房间长期显示 4/4 但只有 3 人在打 | 宽限期严格 30 秒 + `/metrics` 暴露 `ac_grace_active`；超时务必移除 |
| 重连复用 pid 与快照基线冲突 | 重连后画面出现他人实体"瞬移" | 重连时服务器下发全量快照（`baselineTick = 0`） |
| NDJSON 并发写坏行 | 偶发解析失败计数增长 | 单进程单写入者（架构保证）；写入用 `fs.appendFile`，不做读改写 |
| 结算统计与服务器计数不一致 | 玩家发现击杀数与击杀提示数量不同 | 统计只在服务器累加；客户端不自行计数（复用 P06 的事件） |
| 房主离开导致卡在大厅 | 无人能开始 | 房主转移规则（id 最小存活玩家）+ 日志告警 |
| 加载阶段时间过长/过短 | 首波出现时有人还在加载 | `loading` 固定 1.5 秒并广播剩余时间；加载期间玩家不可被攻击 |
