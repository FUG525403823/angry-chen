> 里程碑：M7 ｜ 预估：2 人日 ｜ 上游移交物：HANDOFF-H07

## 1. 目标

本步骤结束后，**一条完整的路走得通**：开浏览器 → 输昵称 → 创建房间拿到 4 位房间码 → 朋友输房间码进来 → 各自选枪并准备 → 房主开始 → 打十波（中途断线 30 秒内可回来接着打）→ 结算页显示每人击杀/爆头/命中率/存活时长 → 排行榜写入本地并在重启服务后仍可读。全程只有服务器能推进对局阶段。

## 4. 任务清单

- [ ] 写 `phase.ts`：`MatchPhase` 值——`lobby = 0`、`loading = 1`、`playing = 2`、`intermission = 3`、`ended = 4`；迁移表：`lobby → loading`、`loading → playing`、`playing → intermission`、`intermission → playing`、`playing → ended`、`intermission → ended`、`ended → lobby`（房主重开）。其余一律非法。`playing → intermission` 由"波次清空且未到最后一波"触发。
- [ ] 写 `stats.ts`：累加器与派生值（命中率 = 命中数 / 射出发数，射出发数由 P06 的 `ac_shots_fired_total` 同类事件提供；存活时长 = 本局时长 - 累计倒地时长）。
- [ ] 写 `controller.ts`：
  - [ ] `lobby`：全员准备且人数 ≥ 1 时，房主可 `StartMatch` → `loading`（1.5 秒加载倒数）→ `playing`，广播 `waveStart(1)`。
  - [ ] `playing`：波次清空 → 若 `wave == 10` 则 → `ended`（`matchEnded` 事件）；否则 → `intermission`（20 秒倒计时，全员准备可跳过，最少 5 秒）。
  - [ ] `intermission → playing`：波次 +1，广播 `waveStart`，重选武器生效（弹药补满）。
  - [ ] 结束判定：全员倒地且无人能救援（或全部断线）→ `ended`，`winnerTeam = 1`（羊阵营）；第 10 波清空 → `winnerTeam = 0`。
  - [ ] 结束时写入 `MatchStore` 并广播结算摘要。
- [ ] 写 `store.ts`：`MatchStore` 接口 + NDJSON 记录 schema（§5.4）；启动时读入并构建内存排行索引（按最高分、总击杀、局数）；写文件用"追加一行 + `\n`"，避免重写全文件。
- [ ] `room.ts` 增加：昵称净化（复用 P03 限额规则，非法则回错误码 6）；房主离开时把房主交给 id 最小的存活玩家；`Leave` 与超时都走同一条移除路径；聊天只做长度与字符校验后广播（≤ 64 字节）。
- [ ] `session.ts` 增加宽限期：玩家断线 → 标记 `disconnectedAtMs`、实体标记 `flags |= 待机`（原地不动、宽限期内不成为羊的攻击目标、不受伤 30 秒）；30 秒内用相同房间码 + 昵称重连 → 复用 `pid` 与实体；超时 → 移除实体并把名额释放；广播 `MatchState` 变化。
- [ ] `main.ts` 增加两个只读 HTTP 接口（仅返回 JSON，不写盘）：`/api/leaderboard?limit=20`、`/api/matches/recent?limit=10`。
- [ ] 客户端 `lobby.ts`：昵称输入（存 `ac.nickname.v1`）、房间码输入（4 位、大写、自动过滤易混淆字符）、创建/加入按钮、玩家列表（含准备标记与所选武器）、房主可见"开始"按钮；错误码文案映射到具体提示（房间不存在/已满/进行中）。
- [ ] 客户端 `intermission.ts`：倒计时环、本波统计、武器重选（复用备战界面）、"准备跳过"按钮（显示已准备人数）。
- [ ] 客户端 `results.ts`：表格逐人显示（击杀/爆头/命中率/救援/倒地/存活时长）、胜负横幅、返回大厅按钮、排行榜前 10。
- [ ] 客户端 `connection.ts`：重连成功后自动发送带房间码的 `Join` 实现回座；若收到错误码 7（进行中且超宽限）则回到大厅并提示。
- [ ] 测试：
  - [ ] 迁移表：所有非法迁移被 `canTransition` 拒绝（枚举全组合 5×5 断言）。
  - [ ] 房间生命周期集成测试（内存适配器）：2 个假客户端进房 → 准备 → 开始 → 第 1 波清空 → 波间 → 第 2 波 → 一方离开 → 房间继续 → 结算 → NDJSON 落盘。

## 5. 冻结契约

### 5.1 `MatchPhase` 与合法迁移（唯一真源）

```
0 lobby · 1 loading · 2 playing · 3 intermission · 4 ended

lobby        → loading
loading      → playing
playing      → intermission | ended
intermission → playing | ended
ended        → lobby
```

任何其它迁移必须返回 `{ ok: false, reason: 'illegal-transition' }`，并在服务器日志中以 `level: warn` 记录（含当前阶段与请求阶段）。

### 5.2 断线宽限期规则（冻结，回应 R-08）

| 项 | 值/行为 |
|---|---|
| 宽限时长 | 30000ms（从连接关闭时刻起算） |
| 宽限期内实体 | 保留在原位、速度清零、受 `flags` 标记为"待机"，**不参与羊的目标选择**，也不受伤害 |
| 宽限期内名额 | 仍占用房间名额（新玩家不能顶替） |
| 重连识别 | 房间码 + 昵称（区分大小写）完全一致 → 复用原 `pid` 与实体、血量、武器、怒气 |
| 重连后状态 | 生命恢复到至少 50%（防止"回来即死"），其余状态原样 |
| 超时 | 移除实体、释放名额、广播 `MatchState`；其统计仍计入本局结算（标注"中途离开"） |
| 全员断线 | 房间保留 60 秒后回收 |

### 5.3 复活与复苏规则（冻结）

| 场景 | 行为 |
|---|---|
| 倒地 | 生命归零 → `downed`，不可移动、不可开火、可被救援（P06 已实现） |
| 救援 | 队友 2m 内按住交互 3 秒 → 以 50% 生命复起；被打断则进度 5 秒后归零 |
| 波次清空 | 所有倒地者以 50% 生命复苏（无需救援） |
| 波间/新波开始 | 全体玩家生命补满 100%、护甲补满 50、备弹补满、怒气归零 |
| 主动重生 | 不允许；倒地后只能等救援或波次清空（`Respawn` opcode 仅在大厅/加载阶段有效） |

### 5.4 `MatchStore` 接口与记录 schema（冻结）

```ts
export interface MatchResultRecord {
  matchId: string;         // 房间码 + 起始时间戳（服务器本地时钟）
  startedAtMs: number;
  durationMs: number;
  waveReached: number;
  winnerTeam: 0 | 1;       // 0 = 玩家阵营胜，1 = 羊阵营胜
  playerCount: number;
  players: Array<{
    name: string;
    kills: number;
    headshots: number;
    shotsFired: number;
    hits: number;          // 派生：accuracy = hits / max(1, shotsFired)
    revives: number;
    downs: number;
    aliveMs: number;
    leftMidMatch: boolean;
  }>;
}

export interface MatchStore {
  appendMatchResult(record: MatchResultRecord): Promise<void>;
  listTopScores(limit: number): Promise<MatchResultRecord[]>;   // 按 players[].kills 最大值降序
  getRecentMatches(limit: number): Promise<MatchResultRecord[]>; // 按 startedAtMs 降序
}
```

落盘位置：`DATA_DIR/matches.ndjson`（默认 `./data`），每行一个 JSON 对象，UTF-8 + `\n`。读取时单行解析失败则跳过并计入 `corruptLines`。

## 7. DoD（验收标准）

1. `pnpm check` 全绿。
2. AC-01、AC-02、AC-06、AC-07 四条验收场景全部通过并留下证据（截图或命令输出）。
3. 非法迁移被拒绝：5×5 全组合单测通过，且服务器日志出现 `illegal-transition` 警告。
4. 宽限期规则与 §5.2 完全一致（10 秒重连保留、31 秒移除、全员断线 60 秒回收）。
5. 结算数据落盘且重启后可读；损坏行不影响其余记录。
6. 非房主无法开始对局（错误码 9）；房间满时加入返回错误码 3；对局进行中加入返回错误码 7。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 宽限期语义模糊导致"幽灵玩家" | 房间长期显示 4/4 但只有 3 人在打 | 宽限期严格 30 秒 + `/metrics` 暴露 `ac_grace_active`；超时务必移除 |
| 重连复用 pid 与快照基线冲突 | 重连后画面出现他人实体"瞬移" | 重连时服务器下发全量快照（`baselineTick = 0`） |
| NDJSON 并发写坏行 | 偶发解析失败计数增长 | 单进程单写入者（架构保证）；写入用 `fs.appendFile`，不做读改写 |
| 结算统计与服务器计数不一致 | 玩家发现击杀数与击杀提示数量不同 | 统计只在服务器累加；客户端不自行计数（复用 P06 的事件） |
| 房主离开导致卡在大厅 | 无人能开始 | 房主转移规则（id 最小存活玩家）+ 日志告警 |
| 加载阶段时间过长/过短 | 首波出现时有人还在加载 | `loading` 固定 1.5 秒并广播剩余时间；加载期间玩家不可被攻击 |

**回滚目标**：`HANDOFF-H07`。移除 `shared/src/match/**`、`server/src/match/**`、`client/src/ui/{lobby,intermission,results,chat}.ts`，退回"进房即开始、无大厅无结算"的最小可玩态（服务器仍可用脚本驱动）。
