# P01 项目基线搭建

> 里程碑：M0 ｜ 预估：0.5–1 人日 ｜ 上游移交物：HANDOFF-H00

## 1. 目标

本步骤结束后，仓库是一个**能跑、能查、能测的空壳工程**：`pnpm install` 一次装齐、`pnpm check` 全绿、`pnpm dev` 同时拉起服务端与客户端，浏览器页面能显示它读到的协议版本号，服务端 WebSocket 健康检查返回 JSON。此后每份计划文档都在这个骨架上增量施工，不再调整目录与脚本约定。

## 5. 冻结契约

### 5.1 包名与脚本

```ts
// package.json 的 exports（三个包一致的形态）
{ "exports": { ".": "./src/index.ts" }, "type": "module" }
```

| 脚本 | 命令 | 说明 |
|---|---|---|
| `pnpm dev` | 并行 `dev:server` + `dev:client` | 日常开发入口 |
| `pnpm dev:server` | `pnpm --filter @ac/server dev` → `tsx watch src/main.ts` | 服务端 |
| `pnpm dev:client` | `pnpm --filter @ac/client dev` → `vite` | 客户端 |
| `pnpm check` | `typecheck && lint && test && check:docs` | **唯一质量门** |
| `pnpm typecheck` | `tsc -b --noEmit`（或逐包 `tsc --noEmit`） | 类型 |
| `pnpm lint` | `eslint . && prettier --check .` | 风格与纯净性 |
| `pnpm test` | `vitest run` | 测试 |
| `pnpm check:docs` | `node tools/check-docs.mjs` | 文档链 |
| `pnpm build:client` | `pnpm --filter @ac/client build` | 产物构建（P10 用体积预算） |

### 5.2 编译项冻结清单

`tsconfig.base.json` 必须包含且不得删除：`strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`verbatimModuleSyntax`、`erasableSyntaxOnly`、`isolatedModules`、`noImplicitOverride`、`noFallthroughCasesInSwitch`、`skipLibCheck`、`noEmit`、`module: "esnext"`、`moduleResolution: "bundler"`、`target: "es2023"`。

> 注意：`server` 由 tsx 运行，因此 `moduleResolution: "bundler"` 之外还需允许 `.ts` 相对导入（`allowImportingTsExtensions: true`，与 `noEmit` 配套）。`client` 由 Vite 构建，同样满足。

### 5.3 环境变量名（此处只定名，不定值）

`PORT`、`HOST`、`MAX_ROOMS`、`MAX_PLAYERS_PER_ROOM`、`TICK_MS`、`DATA_DIR`、`LOG_LEVEL`、`ALLOWED_ORIGINS`。

### 5.4 常量冻结

```ts
export const PROTOCOL_VERSION = 1 as const;
export const SERVER_TICK_MS = 50 as const;
```

## 6. 验证

| # | 命令 | 期望输出 | 失败意味着 |
|---|---|---|---|
| 1 | `pnpm install` | 无错误；生成 `pnpm-lock.yaml` | 版本冲突——回到 §5 版本表核对精确版本 |
| 2 | `pnpm check` | 四个子步骤全部通过，退出码 0 | 骨架不成立，后续文档无法在此之上施工 |
| 3 | `pnpm dev:server` 后 `curl -s localhost:8787/health` | `{"ok":true,"protocolVersion":1,"tickMs":50,...}` | tsx 或 ws 配置错误 |
| 4 | `pnpm dev:client` 后浏览器打开提示的地址 | 页面显示 `protocolVersion 1 / tickMs 50` | `@ac/shared` 源码消费链路断了（检查 `exports` 与 `optimizeDeps.exclude`） |
| 5 | `node -e "const {WebSocket}=require('ws');const w=new WebSocket('ws://localhost:8787');w.on('message',m=>{console.log(String(m));process.exit(0)})"` | 一行 JSON 欢迎帧 | 服务端握手逻辑错误 |
| 6 | 在 `shared/src` 里临时写 `Math.random()` 后 `pnpm lint` | 报错 | 纯净性规则没生效，必须修 `eslint.config.js` |
| 7 | `git ls-files` 输出经 `grep -Ei` 过滤 `png/jpg/jpeg/gif/mp3/wav/ogg/glb/gltf/fbx` | 无输出 | 违反零外部素材（NFR-07） |

人工确认：浏览器控制台无报错；页面刷新后 HMR 仍工作。

## 7. DoD（验收标准）

1. `pnpm install` 在干净克隆上成功，且无 `^`/`~` 版本号出现在 `package.json`（全部精确版本）。
2. `pnpm check` 全绿（typecheck + lint + test + 文档链校验四项）。
3. `pnpm dev` 一条命令同时起服务端与客户端，且 §6 的第 3、4、5 条同时成立。
4. `shared` 的纯净性 lint 规则可被 §6 第 6 条证伪步骤触发。
5. 仓库无任何外部素材二进制（§6 第 7 条）。
6. `README.md` 的快速开始四条命令可复制即用。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| Vite 预打包 workspace 的 `.ts` 依赖报错 | 开发服务器启动即报 dependency optimize 失败 | 已写死 `optimizeDeps.exclude: ['@ac/shared']`；仍失败则加 `resolve.preserveSymlinks: true` |
| tsx 与 `erasableSyntaxOnly` 之外的语法冲突 | 启动抛 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` | 确认无 `enum`/参数属性；编译期已有规则拦截 |
| eslint 10 与 typescript-eslint 8 的 flat config 组合不生效 | lint 不报已知违规 | 用 `tseslint.config()` helper 组装；必要时降级到 eslint 9（需改 ADR-001） |
| `tsc -b` 与 `noEmit` 冲突 | typecheck 报配置错误 | 改为逐包 `tsc --noEmit -p packages/<x>`，脚本层面包装 |
| 依赖安装体积/时长异常 | `pnpm install` 超过数分钟 | 检查是否有包触发了原生编译（本仓库禁止此类包） |
| pnpm 11 不再读取 package.json 的 `pnpm` 字段 | `pnpm install` 退出码 1 并报 `ERR_PNPM_IGNORED_BUILDS` | 构建设置写在 `pnpm-workspace.yaml` 的 `allowBuilds`（`pnpm approve-builds --all` 会自动写入正确形态）；已执行 |
| 默认端口 8080 与本机 Cursor 的内置服务冲突 | 服务端启动抛 `EADDRINUSE`，`/health` 被 Cursor 以 403 应答 | 默认端口改为 8787；`PORT` 仍可由环境变量覆盖，冲突时用 `PORT=9000 pnpm dev:server` |
| Vite 默认绑定 `localhost`（本机解析为 `::1`）| 访问 `http://127.0.0.1:5173` 被拒（连接失败）| 使用 Vite 输出的 `http://localhost:5173`；确需 IPv4 直连时在 `vite.config.ts` 设 `server.host` |

**回滚目标**：回到 `HANDOFF-H00`（空仓库 + 文档），删除 `packages/`、`node_modules/`、锁文件与根配置文件即可，文档不受影响。
