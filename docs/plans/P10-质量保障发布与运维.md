> 里程碑：M9 ｜ 预估：3 人日 ｜ 上游移交物：HANDOFF-H09

## 1. 目标

本步骤结束后，这个项目**可以交付给别人并长期跑下去**：一条 `pnpm check` 覆盖类型、风格、测试与文档链；`tools/bots.mjs` 能拉起 4 个无头客户端跑 30 分钟 soak 并给出带宽/内存/公平性报告；客户端有构建体积预算并可通过反代以 `wss://` 对外服务；服务器有结构化日志、`/metrics`、单场诊断报告、安全清单与故障排查手册；仓库没有未验证的交付物（Dockerfile 明确标注"仅静态审查"）。

## 5. 冻结契约

### 5.1 质量门（最终形态，冻结）

```
pnpm check = pnpm typecheck && pnpm lint && pnpm test && pnpm check:docs
```

| 附加门槛 | 阈值 |
|---|---|
| `shared` 行覆盖率 | ≥ 80%（`@vitest/coverage-v8`，低于阈值失败） |
| 客户端构建体积 | gzip 后 ≤ 1.5MB（超出失败） |
| 测试总数 | ≥ 120 个用例（含单测与集成测试） |
| 文档链 | `node tools/check-docs.mjs` 退出码 0 |
| 仓库素材扫描 | 无第三方图片/音频/模型文件 |

### 5.2 压测与 soak 阈值（冻结，回应 NFR-01/02/03）

| 指标 | 阈值 | 数据来源 |
|---|---|---|
| 单快照字节（均值） | ≤ 1200 | bots 报告 |
| 每客户端带宽 | ≤ 40 KB/s | bots 报告 |
| 快照速率 | 19–21/s | bots 报告 |
| 服务端 tick 抖动 P95 | ≤ 8ms | `/metrics` |
| 4 人 60 羊时单核 CPU | ≤ 30% | soak 报告 |
| 服务端 RSS 增长 | < 1MB/分钟 | soak 报告 |
| 30 分钟无未捕获异常/无房间泄漏 | 成立 | soak 报告 |
| 80ms RTT + 20ms 抖动 + 1% 丢包下可玩 | 硬纠正 ≤ 5/分钟/人 | bots 报告 |
| 200ms RTT 下可玩 | 回合内无"隔墙命中"记录 | bots 报告 + 断言 |

### 5.3 单场诊断报告 schema（冻结）

```ts
export interface MatchDiagnostics {
  matchId: string;
  durationMs: number;
  ticks: { total: number; skipped: number; jitterMsP50: number; jitterMsP95: number };
  net: { snapshotBytesAvg: number; snapshotBytesMax: number; messagesInTotal: number; malformedInTotal: number; rateLimitedTotal: number };
  fair: { hardCorrectTotal: number; rewindClampedTotal: number; speedViolationsTotal: number; shotsFiredTotal: number; hitsTotal: number };
  grace: { starts: number; reconnects: number; timeouts: number };
  peak: { entities: number; players: number };
}
```

## 5.5 实现澄清与披露（P10 执行期）

1. 质量门实际形态：pnpm check = typecheck && lint && test && check:docs && check:assets && check:count && check:coverage。test 用 vitest 的 json reporter 落盘 coverage/test-results.json，供 check:count 读取（缺失时自行跑一次 vitest）。
2. 覆盖率门槛是真门槛：@vitest/coverage-v8 已在本机安装，vitest.config.ts 配置 shared 行覆盖 ≥80%，实测 84.92%（语句 81.12 / 分支 66.25 / 函数 88.01）。把阈值临时改到 100 会 exit 1，已反向验证。
3. 体积门槛：客户端 JS gzip 合计 176.84 kB（index 41.35 + three 135.49），门槛 1.5 MB，占 11.8%；three 单独分包；把阈值改到 1000 B 会让构建失败，已反向验证。
4. 交付物验证状态（§5.5 规则）：已验证——质量门链条、素材扫描、用例数、覆盖率、体积、bots 与 soak 实测、房间生命周期与宽限期日志；静态审查——Dockerfile、docker-compose.yml、deploy/{Caddyfile,nginx.conf,angry-chen.service,ecosystem.config.cjs}（本机无 docker/nginx/systemd）、SIGTERM 优雅退出（Git Bash 直接杀进程，无法触发 handler）；未执行——浏览器人工验收（AC-01/02/06/07/09）、30 分钟全量 soak、200ms RTT 的隔墙命中断言。
5. 房间码熵修正：房间码字符表实际为 31 个字符（31^4 = 923521），不是 §5.4 写的 32 字符；对应测试按 ≥31 字符与 ≥900k 组合断言，本节以此为准。
6. 压测两项未达标且未放宽阈值：tick 抖动 P95 12.85ms（阈值 ≤8ms）、硬纠正 523.34/分钟/人（阈值 ≤5）。后者语义需澄清：该计数来自压测端为模拟 80ms RTT / 20ms 抖动 / 1% 丢包而做的输入重放（`applyPoseValidation` 对不合法权威位移计数回退），不能直接等同于真实客户端的预测缺陷，需要后续单独排查后才能定论，本节不把它记为通过。复跑进一步说明它不可直接读作客户端缺陷：同命令在本机独立复跑为 5222 → 261.1/分钟/人，而提交里的 `docs/evidence/bots-4p-5min.json`（room AHBW）记录为 0，同一命令三次结果 0 / 5222 / 10467 分散极大。
7. bots 与 soak 的产物：docs/evidence/bots-4p-5min.json、docs/evidence/soak-5min.{json,md}，均由本机真实运行生成（命令见 §6.1）。
8. tools/e2e-edge.mjs 为可选：本机没有 puppeteer-core（无外网无法安装），脚本打印明确的 Skipped 原因并 exit 0，不进入 pnpm check 必过项。
9. 历史事件披露：另一个会话的提交 6688a55 曾把本轮新增的运维脚本、packages/server/src/{report,security}.ts 与 Dockerfile 当作"越界"删除，工作区也多次被回退；本次按人类"完成所有未完成部分"的指令从 /tmp 备份与 HEAD 恢复全部交付物，并在同一分支上追加提交（未做 reset/amend/rebase/force-push）。
10. 已知代码债：structured log 的 pid 字段语义是 session/player id（0=无）；check-test-count.mjs 在需要现场跑 vitest 时用了 shell:true 触发 Node 弃用告警；RoomClient 的指标为进程级 gauge，多房间时后写覆盖。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 阈值过严导致发布被卡住 | 体积或覆盖率反复失败 | 阈值可调，但调整必须记录在 ADR；先优化再放宽 |
| soak 暴露内存泄漏 | RSS 斜率超标 | 用 `--inspect` 对比三次快照定位；重点查房间回收、事件数组、粒子池 |
| 无真实部署环境验证 | 反代配置未实测 | 本机可用 Caddy/Nginx 走 `localhost` + 自签证书实测一次；仍无法验证的部分标注"静态审查" |
| E2E 依赖外部浏览器 | `puppeteer-core` 找不到 Edge | 已设计为可选并优雅跳过；不进入 `pnpm check` 必过项 |
| 手册与实现漂移 | 排障表里的路径已改名 | 排障表每条引用具体文件路径，改名时同 PR 更新 |
| 过度运维（K8s、监控栈） | 引入不必要的基础设施 | 明确"单机 + 反代 + 日志文件 + /metrics"为上限；扩容路径写进手册而非实现 |

**回滚目标**：`HANDOFF-H09`。P10 不改变玩法与协议，回滚只影响运维与压测资产：移除 `tools/{bots,soak,report,e2e-edge}.mjs`、`deploy/**`、Dockerfile、`docs/{运维手册,验收报告}.md`，游戏仍可运行。
