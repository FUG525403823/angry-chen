# P10 质量保障、发布与运维

> 里程碑：M9 ｜ 预估：3 人日 ｜ 上游移交物：HANDOFF-H09

## 1. 目标

本步骤结束后，这个项目**可以交付给别人并长期跑下去**：一条 `pnpm check` 覆盖类型、风格、测试与文档链；`tools/bots.mjs` 能拉起 4 个无头客户端跑 30 分钟 soak 并给出带宽/内存/公平性报告；客户端有构建体积预算并可通过反代以 `wss://` 对外服务；服务器有结构化日志、`/metrics`、单场诊断报告、安全清单与故障排查手册；仓库没有未验证的交付物（Dockerfile 明确标注"仅静态审查"）。

## 4. 任务清单

- [ ] 写 `tools/bots.mjs`：复用 `@ac/shared` 的 codec 与 `sim` 做决策（注意：机器人**不是**客户端，它构造 `Command` 并校验服务器结果）；支持参数 `--players 4 --minutes 30 --latency 80 --jitter 20 --loss 0.01`。
- [ ] 写 `tools/soak.mjs`：每 10 秒采样一次 `process.memoryUsage()` 与 `/metrics`；断言 RSS 增长斜率 < 1MB/分钟、房间数回落、无未捕获异常；产出 Markdown 报告。
- [ ] 写 `packages/server/src/report.ts`：对局结束时落盘诊断报告（§5.3 字段），供 P08 的结算页之外单独排查用。
- [ ] 写 `log.ts` 并替换所有 `console.*`：字段固定为 `ts/level/evt/room/tick/pid/detail`；`evt` 使用固定短名（`room.create`、`session.join`、`wave.start`、`wave.clear`、`anticheat.speed`、`grace.start`、`grace.timeout`、`match.end`、`error.uncaught`）。
- [ ] 写 `security.ts` 与安全复查：逐条对照 §5.4 清单，缺一补一；把"服务端权威（客户端无伤害能力）"作为固定检查项写进验收报告。
- [ ] `vite.config.ts`：`build.target = 'es2022'`、`sourcemap: false`、`rollupOptions.output.manualChunks` 把 `three` 单独分包；加一个体积断言（客户端 JS gzip 后 ≤ 1.5MB）。
- [ ] 写部署样例与运维手册：Caddy/Nginx 的 WSS 反代与静态缓存；systemd/PM2 的自启与重启策略；数据目录权限；端口与健康检查接入。
- [ ] 写 `tools/e2e-edge.mjs`：探测 Edge 路径，若不存在则打印"Skipped: 未找到 Chromium 系浏览器"并以 0 退出（不能让可选的 E2E 阻塞 `pnpm check`）。
- [ ] 写 `docs/验收报告.md`：AC-01…AC-10 逐条给出证据类型（自动脚本输出 / 截图 / 人工观察）与结论；自动项由 `tools/report.mjs` 填充。
- [ ] 建立"发布清单"：`pnpm check` → `pnpm build:client` → 体积校验 → bots 5 分钟抽检 → 打 `git tag v<x.y.z>` → 按运维手册发布 → 冒烟（`/health`、一局单人第 1 波）。
- [ ] 路线图章节（写入运维手册）：WebTransport/WebRTC 换传输、账号与云排行、掉落与补给（FR-15）、观战与回放、第二张场地与模式、AI 增强与反作弊深化。

## 5. 冻结契约

### 5.1 质量门（最终形态，冻结）

```
pnpm check = pnpm typecheck && pnpm lint && pnpm test && pnpm check:docs
```

| 附加门槛 | 阈值 |
|---|---|
| `shared` 行覆盖率 | ≥ 80%（`@vitest/coverage-v8`，低于阈值失败） |
| 客户端构建体积 | gzip 后 ≤ 1.5MB（超出失败） |
| 测试总数 | ≥ 120 个用例（含单测与集成测试） |
| 文档链 | `node tools/check-docs.mjs` 退出码 0 |
| 仓库素材扫描 | 无第三方图片/音频/模型文件 |

### 5.2 压测与 soak 阈值（冻结，回应 NFR-01/02/03）

| 指标 | 阈值 | 数据来源 |
|---|---|---|
| 单快照字节（均值） | ≤ 1200 | bots 报告 |
| 每客户端带宽 | ≤ 40 KB/s | bots 报告 |
| 快照速率 | 19–21/s | bots 报告 |
| 服务端 tick 抖动 P95 | ≤ 8ms | `/metrics` |
| 4 人 60 羊时单核 CPU | ≤ 30% | soak 报告 |
| 服务端 RSS 增长 | < 1MB/分钟 | soak 报告 |
| 30 分钟无未捕获异常/无房间泄漏 | 成立 | soak 报告 |
| 80ms RTT + 20ms 抖动 + 1% 丢包下可玩 | 硬纠正 ≤ 5/分钟/人 | bots 报告 |
| 200ms RTT 下可玩 | 回合内无"隔墙命中"记录 | bots 报告 + 断言 |

### 5.3 单场诊断报告 schema（冻结）

```ts
export interface MatchDiagnostics {
  matchId: string;
  durationMs: number;
  ticks: { total: number; skipped: number; jitterMsP50: number; jitterMsP95: number };
  net: { snapshotBytesAvg: number; snapshotBytesMax: number; messagesInTotal: number; malformedInTotal: number; rateLimitedTotal: number };
  fair: { hardCorrectTotal: number; rewindClampedTotal: number; speedViolationsTotal: number; shotsFiredTotal: number; hitsTotal: number };
  grace: { starts: number; reconnects: number; timeouts: number };
  peak: { entities: number; players: number };
}
```

### 5.4 安全清单（冻结，每项必须有代码或测试对应）

| # | 项 | 落地位置 |
|---|---|---|
| 1 | 服务端权威：客户端无伤害/无击杀能力 | P06 权威性测试 |
| 2 | 单帧上限 8192 字节，超限断开 | P03 `ws-adapter` |
| 3 | 频率限制 60 msg/s，3 次超限断开 | P03 `session` |
| 4 | opcode 白名单，未知一律丢弃 | P03 `session` |
| 5 | 拨入字段范围校验（角度取模、轴夹取） | P02 `sanitizeCommand` |
| 6 | 姿态校验（速度/加速度/位置合法性） | P05 `anticheat` |
| 7 | 昵称与聊天净化（长度 + 控制字符 + HTML 元字符） | P08 `room` |
| 8 | 房间码熵：32 字符表 4 位（≈ 10^6 组合）+ 失败重试节流 | P03 `rooms` |
| 9 | 来源校验 `ALLOWED_ORIGINS`（浏览器来源白名单） | P10 `security.ts` |
| 10 | 无密钥入库、`.env` 被忽略、日志不打印昵称以外个人信息 | P10 `.gitignore`/`log.ts` |
| 11 | 异常隔离：未捕获异常记日志并保持进程可用；`unhandledRejection` 有兜底 | P10 `main.ts` |
| 12 | 依赖最小化：运行时依赖仅 `three` + `ws` + `tsx`（ADR 已批准） | 仓库审查 |

### 5.5 交付物可信度标注规则（冻结）

任何交付物必须标注验证状态：**已验证**（有可复现命令与输出）、**静态审查**（无环境验证）、**未验证**。`Dockerfile`/`docker-compose.yml` 必须标注为"静态审查（构建环境缺失：本机无 docker）"。

## 6. 验证

| # | 命令 | 期望输出 | 失败意味着 |
|---|---|---|---|
| 1 | `pnpm check` | 全绿，含覆盖率与体积门槛 | 交付质量不达标 |
| 2 | `node tools/bots.mjs --players 4 --minutes 5` | 报告满足 §5.2 全部阈值 | 性能或网络不达标，不可发布 |
| 3 | `node tools/soak.mjs --minutes 30` | RSS 增长 < 1MB/分钟、无异常、房间无泄漏 | 存在内存泄漏，长期运行不可靠 |
| 4 | `pnpm build:client` | 构建成功且 gzip ≤ 1.5MB | 体积预算失败 |
| 5 | `node tools/e2e-edge.mjs` | 通过，或明确打印 `Skipped`（无浏览器） | E2E 阻塞了可选项（不应发生） |
| 6 | 启动生产模式 + 反代样例，`curl -s https://<host>/health` | `{"ok":true,...}` | 部署链不通 |
| 7 | 交付物清单逐项核对验证状态标注 | 无未标注项 | 交付诚信问题 |
| 8 | 按"发布清单"完整走一遍并发一版 | 从 tag 到冒烟通过 | 发布流程不可复现 |

## 7. DoD（验收标准）

1. `pnpm check` 全绿，且 §5.1 的四项附加门槛全部生效（覆盖率、体积、用例数、文档链、素材扫描）。
2. `tools/bots.mjs` 与 `tools/soak.mjs` 存在且能在本机完整跑完；报告满足 §5.2 全部阈值。
3. `docs/验收报告.md` 中 AC-01…AC-10 每条都有结论与证据引用；无"待验证"条目。
4. `docs/运维手册.md` 含：发布、回滚、扩容、故障排查表（≥ 10 条常见故障）、日志与指标速查。
5. 安全清单 12 项逐条有代码位置或测试覆盖，无空缺。
6. 所有交付物都标注了验证状态；Docker 相关文件明确标注"静态审查"。
7. `README.md` 的"从零到跑通"不超过 10 行命令，且在干净克隆上可复现。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 阈值过严导致发布被卡住 | 体积或覆盖率反复失败 | 阈值可调，但调整必须记录在 ADR；先优化再放宽 |
| soak 暴露内存泄漏 | RSS 斜率超标 | 用 `--inspect` 对比三次快照定位；重点查房间回收、事件数组、粒子池 |
| 无真实部署环境验证 | 反代配置未实测 | 本机可用 Caddy/Nginx 走 `localhost` + 自签证书实测一次；仍无法验证的部分标注"静态审查" |
| E2E 依赖外部浏览器 | `puppeteer-core` 找不到 Edge | 已设计为可选并优雅跳过；不进入 `pnpm check` 必过项 |
| 手册与实现漂移 | 排障表里的路径已改名 | 排障表每条引用具体文件路径，改名时同 PR 更新 |
| 过度运维（K8s、监控栈） | 引入不必要的基础设施 | 明确"单机 + 反代 + 日志文件 + /metrics"为上限；扩容路径写进手册而非实现 |

**回滚目标**：`HANDOFF-H09`。P10 不改变玩法与协议，回滚只影响运维与压测资产：移除 `tools/{bots,soak,report,e2e-edge}.mjs`、`deploy/**`、Dockerfile、`docs/{运维手册,验收报告}.md`，游戏仍可运行。
