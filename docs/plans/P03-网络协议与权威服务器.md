## 1. 目标

本步骤结束后，**一个不含渲染的脚本客户端**可以：连上服务器、用房间码进房间、以 30Hz 上报命令，并稳定收到 20Hz 的差分快照与事件。服务器是唯一权威：世界只在 `stepWorld` 里前进，客户端发来的只是命令。所有网络行为都可以在不打开浏览器、不占用真实端口的情况下被自动化测试。

## 5. 冻结契约

### 5.1 帧格式

```
[opcode: uint8][payload...]      小端序，全部整数；字符串为 UTF-8，长度前缀 uint8
量化：位置 int16 = 厘米；角度 uint16 = 弧度 / 2π * 65536；血量 uint8 = round(hp/maxHp*255)
```

### 5.2 客户端 → 服务器

| opcode | 名称 | 载荷 |
|---|---|---|
| `0x01` | `Join` | `[protocolVersion uint8][nameLen uint8][name utf8][roomCode 4B ascii]`；房间码 `0000` 表示新建房间 |
| `0x02` | `InputCmd` | `[seq uint16][tick uint32][moveX int8][moveY int8][yaw uint16][pitch uint16][buttons uint8][switchTo uint8]` |
| `0x03` | `Ready` | `[ready uint8][weapon uint8]`（仅 `lobby`/`intermission` 阶段有效） |
| `0x04` | `Chat` | `[len uint8][utf8]`（≤ 64 字节，净化控制字符） |
| `0x05` | `Interact` | `[act uint8]`（1 = 开始救援队友，0 = 取消） |
| `0x06` | `Ping` | `[clientTimeMs uint32][lastRecvTick uint32]` |
| `0x07` | `Respawn` | 空（仅在服务器允许时生效） |
| `0x08` | `Leave` | 空 |
| `0x09` | `StartMatch` | 空（房主专用；非房主发送返回错误码 9） |

`buttons` 位域：`1` 开火、`2` 疾跑、`4` 跳跃、`8` 换弹、`16` 交互、`32` 激活狂暴、`64` 切换武器（配合 `switchTo`）。

### 5.3 服务器 → 客户端

| opcode | 名称 | 载荷 |
|---|---|---|
| `0x81` | `Welcome` | `[pid uint16][roomCode 4B][protocolVersion uint8][tick uint32][serverTimeMs uint32]` |
| `0x82` | `Snapshot` | `[tick uint32][serverTimeMs uint32][lastAckedSeq uint16][baselineTick uint32][count uint8][record×count][removedCount uint8][removedId uint16 × removedCount]` |
| `0x83` | `Event` | `[tick uint32][count uint8][(type uint8)(payload)…]` |
| `0x84` | `MatchState` | `[phase uint8][wave uint8][intermissionMs uint16][playerCount uint8][(pid uint16)(nameLen uint8)(name utf8)(ready uint8)(weapon uint8)(hpRatio uint8)(kills uint16)]×playerCount` |
| `0x85` | `Pong` | `[clientTimeMs uint32][serverTimeMs uint32][snapshotRateX10 uint8]` |
| `0x86` | `Error` | `[code uint8][msgLen uint8][msg utf8]` |

**快照实体记录（15 字节，字段顺序冻结）**：

```
[id uint16][kindFlags uint8][x int16][y int16][z int16][yaw uint16][pitch uint16][hpRatio uint8][state uint8]
kindFlags：bits0-1 kind(0=player,1=sheep,2=projectile,3=pickup)  bits2-7 flags(倒地/狂暴/换弹/蓄力/淡出)
```

### 5.4 错误码

`1` 协议版本不匹配、`2` 房间不存在、`3` 房间已满、`4` 被限流、`5` 帧格式非法、`6` 昵称非法、`7` 对局进行中拒绝加入（非宽限期）、`8` 服务器关停、`9` 权限不足（非房主）。

### 5.5 事件类型表

| type | 名称 | 载荷 |
|---|---|---|
| `1` | `playerHit` | `[attackerId uint16][victimId uint16][damage uint16][flags uint8(1=爆头 2=致倒 4=击杀)]` |
| `2` | `sheepKilled` | `[victimId uint16][killerId uint16][sheepKind uint8]` |
| `3` | `waveStart` | `[wave uint8][budget uint16]` |
| `4` | `waveClear` | `[wave uint8][clearMs uint32]` |
| `5` | `playerDowned` | `[pid uint16]` |
| `6` | `reviveProgress` | `[targetId uint16][reviverId uint16][progressPermille uint16]` |
| `7` | `reviveDone` | `[targetId uint16][reviverId uint16]` |
| `8` | `rageActivated` | `[pid uint16][durationMs uint16]` |
| `9` | `matchEnded` | `[winnerTeam uint8][wave uint8][durationMs uint32]` |

### 5.6 限额（越界即视为非法帧或触发断开）

| 项 | 值 |
|---|---|
| 单帧最大字节 | 8192 |
| 客户端消息频率 | 60 msg/s（1 秒滑窗），超限先丢弃、3 次超限断开 |
| 昵称 | 1–12 字节，仅字母/数字/中文/下划线，控制字符与 `< > & " '` 一律剥除 |
| 每会话保留命令 | 最近 3 条，按 `seq` 丢弃更旧的 |
| 单房间人数 | 4（`MAX_PLAYERS_PER_ROOM`） |
| 快照实体上限 | 256（超出时按距离最近优先，并置 `truncated` 标志） |
| tick 追帧上限 | 单次调度最多补 5 个 tick，超出则跳时间（记录 `tickSkip` 指标） |

### 5.7 带宽预算推导（写入本文档，P10 用它做验收）

稳态 40 个实体 × 15 字节 = 600 字节 + 头部 12 字节 ≈ 612 字节/快照；20Hz → **≈ 12.2 KB/s/客户端**，远低于 NFR-02 的 40 KB/s。留出余量给事件与 MatchState。

### 5.8 实现期澄清（与 §5 同等冻结）

- **Ping 时钟**：`clientTimeMs` 是 uint32，客户端必须发送回绕安全的时钟（如 `Date.now() % 2**32`），RTT 由客户端用 Pong 回显值做回绕减法得出。服务器不算 RTT，只统计 Ping/Pong 次数与"客户端确认延迟" `lagTicks = world.tick - lastRecvTick`。
- **`baselineTick = 0` 只表示全量快照**：服务器仅在 `world.tick ≥ 1` 之后发送快照，真实基线 tick 永远不会是 0，哨兵值与合法 tick 不冲突。每 2 秒（`world.tick % 40 === 0`）强制一次全量作为兜底。
- **u8 计数上限**：`count` 与 `removedCount` 都是 u8，而 §5.6 允许每帧 256 个实体，故实际每帧最多 255 条记录 / 255 条删除；放不下的实体**不写入服务器基线**、下一帧补发（删除同理），客户端镜像在下一帧收敛。
- **轴量化**：`moveX`/`moveY` 是 int8，±127 表示 ±1（`QUANT.moveAxisScale`）。
- **限流窗口包含所有上行帧**（含 Join）：每秒前 60 帧被处理，之后每超限一帧记一次 strike，第 3 次超限回 Error(4) 并断开。
- **空帧**按非法帧丢弃（回 Error(5)、不断开）；超过 8192 字节的帧由传输层计数并断开该连接（`ac_oversized_frames_total`）。
- **Chat 无下行帧**：§5.3 没有服务器→客户端 Chat 帧，P03 只净化/计数/日志，投递留待 P08（见 §8 R-06）。
- **房间从空开始**：`createRoom` 释放 `createWorld` 预生成的 4 个玩家实体（降序释放，使首次 Join 拿到 pid 1）；玩家实体在 Join 时按 `ARENA.playerSpawnPoints[slot]` 生成、Leave 时销毁，"会话 ↔ 实体"一一对应。
- **startMatch**：仅房主可发起；`lobby → intermission(5000ms) → playing(wave=1)` 是 P03 的最小状态机，波次内容由 P07/P08 接管。
- **每会话命令缓冲**：保留最近 3 条（`LIMITS.maxCommandsPerSession`），按 seq 升序插入、重复 seq 忽略、比已保留 3 条都旧的丢弃；tick 时应用**最新**那条（客户端预测负责重放未确认命令，ADR-002）。
- **限流是 1 秒滑窗**：每会话保留最近 60 个帧时间戳，超出即丢弃该帧并计 strike；连续 3 次超限回 Error(4) 并断开；窗口滑空后 strike 归零。
- **客户端丢弃旧快照**：`decodeSnapshot` 在 `tick < mirror.tick` 时直接返回（镜像不变），不论全量还是差分。
- **事件帧上限**：`count` 是 u8，编码端最多写 255 条事件，并在超出 `LIMITS.maxFrameBytes` 之前停止。
- **`HOST` 默认 127.0.0.1**：默认只允许本机连接；局域网联机需在 `.env` 显式设 `HOST=0.0.0.0`。
- **256 与 255 的差值**：`SNAPSHOT_MAX_ENTITIES` 是 256，而 §5.3 的 `count` 是 u8（≤255）且线上没有 truncated 标志位；满 256 实体的全量快照会跨两帧下发（以本节为准，P10 抽查时按此判定）。
- **interact / respawn 只登记意图**：P03 校验并计数（`session.interactAct`、`ac_interact_requests_total`、`ac_respawn_requests_total`），真正的交互与复活规则由 P06/P08 消费。
- **tick 抖动定义**：只采样"一次更新中执行的第一个 tick"的相邻间隔偏差，追帧补跑产生的连续 tick 不计入（它们计入 `tickSkips`），否则抖动指标会被补帧污染。

4. 差分快照正确：客户端按 `baselineTick` 重建后的世界投影与服务器全量快照逐字段一致（集成测试断言）。
5. 恶意输入测试集全通过：超长帧、未知 opcode、截断载荷、错序 seq、500 msg/s 洪泛，服务器进程均存活。
6. `/metrics` 可用且包含 §6 第 6 条的指标。
7. 房间逻辑测试**不依赖真实端口**（全部走内存适配器），可在无网络环境下运行。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| TCP 队头阻塞影响手感 | probe 在注入 3% 丢包时快照间隔抖动 > 200ms | 已在协议层做到"快照可丢、旧快照直接丢"；加大插值缓冲由 P05 负责 |
| 差分快照的基线失配导致渲染缺实体 | 集成测试中出现实体"消失一帧" | 服务器每 2 秒发送一次全量快照（`baselineTick = 0`）作为兜底，代码与测试都要覆盖 |
| tick 累加器追帧雪崩 | `tickSkip` 指标持续增长 | 单帧最多补 5 tick，超出跳时间；并在 `/metrics` 暴露 |
| 房间码碰撞 | 创建房间返回已被占用的码 | 生成时循环取未占用码，最多重试 32 次后返回错误码 3 |
| 内存泄漏（房间未回收） | 长时间运行后 RSS 持续增长 | 空房 60 秒回收；P10 的 30 分钟 soak 测试守住 |

| R-05 客户端时钟回绕导致 RTT 失真 | probe 报出 10^12 量级 RTT | `clientTimeMs` 规定为 uint32 相对时钟，客户端做回绕减法（§5.8）；probe 已按此实现 |
| R-06 Chat 没有下行帧，客户端看不到别人的话 | P08 联调时"发出去没反应" | §5.3 未定义服务器→客户端 Chat 帧；P03 记为已知偏差，P08 决定复用事件通道或新增 opcode（并补 ADR-002 修订） |
| R-07 Windows 定时器粒度抬高抖动指标 | `ac_tick_jitter_ms_p95 > 8ms` 但 `ac_tick_skips_total` 为 0 | 抖动只采样每批第一个 tick、补帧不计入；指标按平台解读，速率由累加器保证 |
| R-08 单帧 255 条记录上限导致镜像短暂缺实体 | 实体数刚过 255 时客户端少 1 个 | 溢出不写入基线、下一帧补发；`snapshot-codec.test.ts` 覆盖"260 实体 → 255 + 5 两帧收敛" |

| R-09 `SimEvent` 的 flags/value/subjectId 被多种事件复用 | P06/P07 消费事件时语义要靠编码端记忆 | 线格式已按 §5.5 命名；P06 引入事件载荷类型时一并拆字段 |
| R-10 每会话每 tick 一次 `subarray` 视图分配 | 长时间 soak 后 GC 抖动 | 单次分配远小于帧编码开销（ADR-005 只约束实体池）；若 P10 soak 显示有影响，再把 `(buffer, offset, length)` 透传给传输层 |

**回滚目标**：`HANDOFF-H02`（内核）。删除 `packages/shared/src/net/` 与 `packages/server/src/{transport,session,room,rooms,metrics}.ts`，`main.ts` 退回"仅 `/health` + 欢迎帧"。

## 9. 移交物

**移交物 ID**：HANDOFF-H03

稳定接口与能力清单：

1. `protocol.ts` 的全部码表与限额常量（P04/P05/P08 只能引用，不得重新定义）。
2. `codec.ts` 的 `encode*`/`decode*` 函数集，含量化规则与差分快照重建。
3. `Transport` / `Connection` 缝与两个适配器（生产 WebSocket、测试内存，后者支持延迟与丢包注入）。
4. 一个可被脚本完整驱动的权威服务器：20Hz 快照、30Hz 命令、事件通道、`/health`、`/metrics`、优雅关停。
5. 已验证能力：单客户端 5 秒稳定快照（19–21/s，≤1200 字节）；洪泛与畸形帧不崩；差分快照可无损重建；房间逻辑可在无端口、无网络环境下被测试。

### 9.1 供后续步骤复用

- 传输缝：`Transport` / `Connection`（`packages/server/src/transport/types.ts`）；`createMemoryTransport({ latencyMs, dropRate })` 支持延迟/丢包注入，P05 的延迟测试直接复用。
- 服务端装配：`createGameServer(transport, options)` → `{ metrics, rooms, transport, sessionCount, step(nowMs), listen(), close() }`；`createHttpHandler(game, startedAtMs)` 提供 `/health` 与 `/metrics`；`startServer(env)` 在回环/外网口上装配真实 WebSocket。
- 客户端可复用：`packages/shared/src/net/codec.ts` 的全部 encode/decode 与 `createSnapshotMirror()`——P04 用它把 20Hz 差分快照重建成世界投影，无需自己写解码。
- 探针：`node tools/probe.mjs [--clients N] [--duration S] [--flood] [--bad-frame] [--chat] [--room CODE]`；P05 的 `--latency` 场景在此脚本上加参数即可。
