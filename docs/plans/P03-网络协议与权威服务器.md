# P03 网络协议与权威服务器

> 里程碑：M2 ｜ 预估：2 人日 ｜ 上游移交物：HANDOFF-H02

## 1. 目标

本步骤结束后，**一个不含渲染的脚本客户端**可以：连上服务器、用房间码进房间、以 30Hz 上报命令，并稳定收到 20Hz 的差分快照与事件。服务器是唯一权威：世界只在 `stepWorld` 里前进，客户端发来的只是命令。所有网络行为都可以在不打开浏览器、不占用真实端口的情况下被自动化测试。

## 5. 冻结契约

### 5.1 帧格式

```
[opcode: uint8][payload...]      小端序，全部整数；字符串为 UTF-8，长度前缀 uint8
量化：位置 int16 = 厘米；角度 uint16 = 弧度 / 2π * 65536；血量 uint8 = round(hp/maxHp*255)
```

### 5.2 客户端 → 服务器

| opcode | 名称 | 载荷 |
|---|---|---|
| `0x01` | `Join` | `[protocolVersion uint8][nameLen uint8][name utf8][roomCode 4B ascii]`；房间码 `0000` 表示新建房间 |
| `0x02` | `InputCmd` | `[seq uint16][tick uint32][moveX int8][moveY int8][yaw uint16][pitch uint16][buttons uint8][switchTo uint8]` |
| `0x03` | `Ready` | `[ready uint8][weapon uint8]`（仅 `lobby`/`intermission` 阶段有效） |
| `0x04` | `Chat` | `[len uint8][utf8]`（≤ 64 字节，净化控制字符） |
| `0x05` | `Interact` | `[act uint8]`（1 = 开始救援队友，0 = 取消） |
| `0x06` | `Ping` | `[clientTimeMs uint32][lastRecvTick uint32]` |
| `0x07` | `Respawn` | 空（仅在服务器允许时生效） |
| `0x08` | `Leave` | 空 |
| `0x09` | `StartMatch` | 空（房主专用；非房主发送返回错误码 9） |

`buttons` 位域：`1` 开火、`2` 疾跑、`4` 跳跃、`8` 换弹、`16` 交互、`32` 激活狂暴、`64` 切换武器（配合 `switchTo`）。

### 5.3 服务器 → 客户端

| opcode | 名称 | 载荷 |
|---|---|---|
| `0x81` | `Welcome` | `[pid uint16][roomCode 4B][protocolVersion uint8][tick uint32][serverTimeMs uint32]` |
| `0x82` | `Snapshot` | `[tick uint32][serverTimeMs uint32][lastAckedSeq uint16][baselineTick uint32][count uint8][record×count][removedCount uint8][removedId uint16 × removedCount]` |
| `0x83` | `Event` | `[tick uint32][count uint8][(type uint8)(payload)…]` |
| `0x84` | `MatchState` | `[phase uint8][wave uint8][intermissionMs uint16][playerCount uint8][(pid uint16)(nameLen uint8)(name utf8)(ready uint8)(weapon uint8)(hpRatio uint8)(kills uint16)]×playerCount` |
| `0x85` | `Pong` | `[clientTimeMs uint32][serverTimeMs uint32][snapshotRateX10 uint8]` |
| `0x86` | `Error` | `[code uint8][msgLen uint8][msg utf8]` |

**快照实体记录（15 字节，字段顺序冻结）**：

```
[id uint16][kindFlags uint8][x int16][y int16][z int16][yaw uint16][pitch uint16][hpRatio uint8][state uint8]
kindFlags：bits0-1 kind(0=player,1=sheep,2=projectile,3=pickup)  bits2-7 flags(倒地/狂暴/换弹/蓄力/淡出)
```

### 5.4 错误码

`1` 协议版本不匹配、`2` 房间不存在、`3` 房间已满、`4` 被限流、`5` 帧格式非法、`6` 昵称非法、`7` 对局进行中拒绝加入（非宽限期）、`8` 服务器关停、`9` 权限不足（非房主）。

### 5.5 事件类型表

| type | 名称 | 载荷 |
|---|---|---|
| `1` | `playerHit` | `[attackerId uint16][victimId uint16][damage uint16][flags uint8(1=爆头 2=致倒 4=击杀)]` |
| `2` | `sheepKilled` | `[victimId uint16][killerId uint16][sheepKind uint8]` |
| `3` | `waveStart` | `[wave uint8][budget uint16]` |
| `4` | `waveClear` | `[wave uint8][clearMs uint32]` |
| `5` | `playerDowned` | `[pid uint16]` |
| `6` | `reviveProgress` | `[targetId uint16][reviverId uint16][progressPermille uint16]` |
| `7` | `reviveDone` | `[targetId uint16][reviverId uint16]` |
| `8` | `rageActivated` | `[pid uint16][durationMs uint16]` |
| `9` | `matchEnded` | `[winnerTeam uint8][wave uint8][durationMs uint32]` |

### 5.6 限额（越界即视为非法帧或触发断开）

| 项 | 值 |
|---|---|
| 单帧最大字节 | 8192 |
| 客户端消息频率 | 60 msg/s（1 秒滑窗），超限先丢弃、3 次超限断开 |
| 昵称 | 1–12 字节，仅字母/数字/中文/下划线，控制字符与 `< > & " '` 一律剥除 |
| 每会话保留命令 | 最近 3 条，按 `seq` 丢弃更旧的 |
| 单房间人数 | 4（`MAX_PLAYERS_PER_ROOM`） |
| 快照实体上限 | 256（超出时按距离最近优先，并置 `truncated` 标志） |
| tick 追帧上限 | 单次调度最多补 5 个 tick，超出则跳时间（记录 `tickSkip` 指标） |

### 5.7 带宽预算推导（写入本文档，P10 用它做验收）

稳态 40 个实体 × 15 字节 = 600 字节 + 头部 12 字节 ≈ 612 字节/快照；20Hz → **≈ 12.2 KB/s/客户端**，远低于 NFR-02 的 40 KB/s。留出余量给事件与 MatchState。

## 6. 验证

| # | 命令 | 期望输出 | 失败意味着 |
|---|---|---|---|
| 1 | `pnpm --filter @ac/shared test` | codec round-trip 属性测试全通过 | 协议不可靠，客户端重建出的世界会与服务器不同 |
| 2 | `pnpm --filter @ac/server test` | 集成测试全通过 | 房间/会话逻辑有洞 |
| 3 | `pnpm dev:server` 后另开终端 `node tools/probe.mjs` | `snapshots/s ≈ 20`、`avg snapshot bytes ≤ 1200`、`avg RTT` 有值 | 广播或差分编码有问题 |
| 4 | `node tools/probe.mjs --flood`（脚本内置：500 msg/s 持续 3 秒） | 服务器不崩、探测端被以错误码 4 断开 | 限流未生效（NFR-05） |
| 5 | `node tools/probe.mjs --bad-frame`（内置：发送 9KB 帧与未知 opcode 0xFF） | 服务器日志出现 `malformedFrames` 计数，进程存活 | 输入校验有洞 |
| 6 | `curl -s localhost:8080/metrics` | 含 `ac_tick_jitter_ms_p95`、`ac_snapshot_bytes_avg`、`ac_malformed_frames_total` | 可观测性未落地（NFR-09） |
| 7 | 手动：两个 probe 并发进同一房间 | 两者收到相同 tick 号与相同实体集合 | 房间隔离或广播逻辑错误 |

## 7. DoD（验收标准）

1. `pnpm check` 全绿。
2. §5 的 opcode 表、字段顺序、限额、错误码全部在 `protocol.ts` 中落地，且与本文档逐字一致（由 P10 的文档一致性检查抽查）。
3. `tools/probe.mjs` 能完整驱动一局：进房 → 30Hz 上报命令 → 收 20Hz 快照 → 打印带宽统计，且快照速率在 19–21/s。
4. 差分快照正确：客户端按 `baselineTick` 重建后的世界投影与服务器全量快照逐字段一致（集成测试断言）。
5. 恶意输入测试集全通过：超长帧、未知 opcode、截断载荷、错序 seq、500 msg/s 洪泛，服务器进程均存活。
6. `/metrics` 可用且包含 §6 第 6 条的指标。
7. 房间逻辑测试**不依赖真实端口**（全部走内存适配器），可在无网络环境下运行。

## 8. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| TCP 队头阻塞影响手感 | probe 在注入 3% 丢包时快照间隔抖动 > 200ms | 已在协议层做到"快照可丢、旧快照直接丢"；加大插值缓冲由 P05 负责 |
| 差分快照的基线失配导致渲染缺实体 | 集成测试中出现实体"消失一帧" | 服务器每 2 秒发送一次全量快照（`baselineTick = 0`）作为兜底，代码与测试都要覆盖 |
| tick 累加器追帧雪崩 | `tickSkip` 指标持续增长 | 单帧最多补 5 tick，超出跳时间；并在 `/metrics` 暴露 |
| 房间码碰撞 | 创建房间返回已被占用的码 | 生成时循环取未占用码，最多重试 32 次后返回错误码 3 |
| 内存泄漏（房间未回收） | 长时间运行后 RSS 持续增长 | 空房 60 秒回收；P10 的 30 分钟 soak 测试守住 |

**回滚目标**：`HANDOFF-H02`（内核）。删除 `packages/shared/src/net/` 与 `packages/server/src/{transport,session,room,rooms,metrics}.ts`，`main.ts` 退回"仅 `/health` + 欢迎帧"。
