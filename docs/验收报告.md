### 3.2 bots 5 分钟（4 个无头客户端，模拟 RTT 80ms / 抖动 20ms / 丢包 1%）

- PASS：快照字节均值 66B（≤1200）；每客户端带宽 1.39 KB/s（≤40）；快照速率 20.02/s（19–21）。
- PASS：隔墙命中 0、无开火即命中 0、无命中即击杀 0、解码失败 0、非法位置 0、unknownOpcode 0。
- FAIL：tick 抖动 P95 12.85ms（阈值 ≤8ms）。
- FAIL：硬纠正 10467 次 → 523.34/分钟/人（阈值 ≤5）。
- NOT-MEASURED：200ms RTT 下"回合内无隔墙命中"断言未跑。
- 其他：RTT avg 98.3ms / p95 111ms；hits 113、kills 37、开火命令 600；**verdict=fail**；未加 `--strict` 时退出码仍为 0（阈值失败只记录在报告，不阻塞）。

**硬纠正语义与可复现性（诚实披露）**：该计数来自 `/metrics` 的 `ac_hard_correct_total` 差值，
压测端为模拟 80ms RTT / 20ms 抖动 / 1% 丢包会做输入重放，而
`packages/server/src/room.ts` 的 `applyPoseValidation` 在权威位移被判定不合法（速度/垂直/位置）时计数并回退。
本轮文档期在同一工作树独立复跑 `node tools/bots.mjs --players 4 --minutes 5` 得到
**5222 → 261.1/分钟/人**，而提交中的 `docs/evidence/bots-4p-5min.json` 记录为 **0**；
同一命令三次结果 0 / 5222 / 10467 分散极大。这说明该指标主要反映压测端的模拟延迟重放与事件循环调度，
**不能直接读成真实客户端的预测缺陷**，需要后续单独排查才能定论。因此本报告既不把硬纠正记为"通过"，
也不把它当作已确认的客户端 bug。
