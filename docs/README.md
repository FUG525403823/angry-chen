## 4. 线性保证机制

1. **入口/出口成对**：每份文档 §2「入口条件」列出必须已成立的事实（附验证命令），§9「移交物」列出交给下一步的稳定接口与已验证能力。第 N 份的 §9 ID 必须等于第 N+1 份的 §2 ID。
2. **只允许引用已冻结的契约**：正文不得引用编号大于自身的文档的**实现细节**；引用其"冻结契约"章节是允许的。
3. **机器校验**：`node tools/check-docs.mjs` 校验十份文档齐全、编号连续、九段式章节齐全、移交物守恒、相对链接可达、仓库无外部素材文件。它也是 `pnpm check` 的第四步。
4. **需求不悬空**：[02-需求分析.md](02-需求分析.md) 第 11 节的追溯矩阵保证每条 FR/NFR 至少被一份计划文档覆盖。

## 5. 执行方式

```bash
node tools/check-docs.mjs      # 先确认文档链完整
# 然后从 P01 开始：读 §1 目标 → 检查 §2 入口条件 → 按 §4 任务清单施工
# 每完成一份：跑该文档 §6 验证 → 确认 §7 DoD → 打 tag（M0…M9）→ 进入下一份
```
